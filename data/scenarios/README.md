# Сценарии ДДС: один файл — один сценарий

Каталог учебных сценариев диспетчера ДДС. Каждый файл `<код>.json` — один сценарий одной
службы и одного уровня: карточка, эталон, бригады и их доклады до завершения, события и
ветки, варианты частей для ввода без микрофона, ловушки. Формат —
`contracts/scenario-file.schema.json`, эталон игрового процесса — `docs/dds_gameplay.md`.

Занятие преподавателя и тренировка («Мой путь») берут сценарии отсюда. Тренировка отбирает
их по службе и уровню, копий нет. Код при добавлении сценария не меняется.

## Как добавить сценарий

1. **Скопируйте похожий файл** и назовите копию новым кодом: строчные латинские буквы,
   цифры и дефис, например `gas-entrance-104-1.json`. Начните с
   `smoke-apartment-101-1.json`: в нём есть и доклады, и события, и ловушка.
2. **Заполните шапку.**
   - `code` — то же, что имя файла без `.json`.
   - `version` — `1`.
   - Поле `id` удалите: оно есть только у сценариев, перенесённых из `data/practice`.
   - `title`, `service_id` (служба обучаемого из `data/phonebook.json`), `level` (1–4),
     `weight`, `incident_type_code` (классификатор `data/classifier.json`),
     `teacher_comment` — что увидит преподаватель.
3. **Карточка** (`card`) — как её получает диспетчер. Номер `card.number` — восемь цифр,
   не занятые другим сценарием.
4. **Эталон** (`reference`): ход статусов `expected_flow`, адрес, службы, звонок
   `expected_call`, ожидаемый комментарий. Если ход кончается статусом «Прибытие»,
   «Проведение работ», «Работы завершены» или «Отказ от выполнения работ», для каждого
   такого статуса нужен доклад бригады в плане.
5. **Бригады** (`brigades`): ключ, которым на бригаду ссылаются доклады и события, и номер
   учебной бригады службы `ordinal` (0–3).
6. **План докладов** (`plan`) — по порядку, до завершающего статуса. У доклада:
   - `key` — имя доклада (`departure`, `arrival`, `works`, `completion`);
   - `brigade` — ключ бригады;
   - `line` — текст доклада или `{"text": …, "audio": "<путь в data/voices>"}`. Текст —
     дословно фраза банка озвучки своей службы (`scripts/voices/bank/phrases/<служба>.json`,
     правила — раздел «Реплики — из банка» ниже); свой текст не пишется;
   - `requires_state` — после какого статуса диспетчера бригада докладывает;
   - `justifies_state` — какой статус доклад разрешает поставить;
   - `after_s` — через сколько секунд после статуса, не больше 40;
   - `task_change` (необязательно) — доклад с места меняет задачу: «пострадавших больше»,
     «нужна деблокировка», «нужна другая служба». После того как доклад прозвучал, эталон
     оценки карточки другой: `expected_flow`, `expected_call` (срок `within_s` — секунды от
     доклада), `expected_comment` заменяют эталонные, `comment_keywords` дописываются; `label` —
     строка разбора. Правила — `contracts/scenario-events.md`, «Доклад меняет задачу»; пример —
     `traffic-fire-102-2.json`. Реплика такого доклада — фраза своего места или `update`.
7. **События и ветки** (`events`, необязательно) — как в `contracts/scenario-events.md`,
   только вместо UUID ключи: в триггере `"report": "<ключ доклада>"` или
   `"event": "<ключ события>"`, в последствиях `delay` и `replace` — ключ доклада.
   У просьбы о службе (`request_service`) ветки `already` («уже вызвал, едут») и `surprise`
   (служба вызвана заранее, бригаде не сказали) и варианты ответа загрузчик достраивает сам из
   банка, если их нет в файле (`contracts/scenario-events.md`, «Служба вызвана заранее»).
8. **Ловушки** (`traps`) — ключи событий-ловушек, например повтор адреса с ошибкой
   (событие `readback_error`).
9. **Варианты частей** (`input_parts`) — для ввода без микрофона: шаги `who`, `address`,
   `what`, `people`, `decision`, на шаге до трёх коротких вариантов, ровно один с
   `"correct": true`.
10. **Исход** (`outcome`, необязательно) — блок «Что было дальше» в разборе закрытой карточки:
    - `people` — полный ход: что стало с людьми, когда службы отработали вовремя;
    - `late` — чем обернулась поздняя «Принята» («Не принята»);
    - `why` — почему это важно; только с источником, нет источника — поля нет;
    - `status` — что значит ход статусов не по эталону именно в этом сценарии (например,
      «Отказ от выполнения работ» вместо «Работы завершены»); нет поля — общая строка разбора.

    Пишите по фактам карточки и реплик сценария, без выдумок сверх них: по-русски, без
    обращения к читателю («Расчёт нашёл очаг…», «Карточку приняли позже норматива…»). Реплики
    собеседников — фразы банка, а исход — не реплика, фраз банка здесь не требуется. Блок
    попадает в план сценария, поэтому правка исхода — новая версия. Нет блока — разбор берёт
    исход тренировки `data/practice` по номеру карточки (так работают старые сценарии).
11. **Проверьте файл:**
    ```bash
    uv run --package arm112-scripts python scripts/validate_contracts.py
    uv run pytest -q apps/api/tests/test_scenario_files.py apps/api/tests/test_scenario_phrases.py
    ```
    Ошибка называет файл и что не так: «нет плана до завершения: в плане нет доклада для
    статуса «Работы завершены»», «неизвестная служба «999»».
12. **Загрузите на стенд:** `python -m app.seed.training` в контейнере api (его же
    выполняет запуск стенда). Файл с ошибкой не загружается, остальные загружаются;
    причина — в журнале seed: «Сценарий не загружен: …».

## Как изменить сценарий

Выданный сценарий и его план неизменяемы: на них ссылаются журналы занятий. Любое изменение
файла — новая версия:

1. Поднимите `version` на единицу.
2. Если в файле есть `id` (перенесённый сценарий), удалите его и впишите это значение в
   `"replaces": ["…"]`.
3. Загрузите seed. Новая версия получит свой UUID, прежняя будет снята с выдачи (статус
   `retired`), её журналы и разборы останутся.

Без новой версии seed изменённый файл на развёрнутом стенде не применит и предупредит в
журнале: «изменён без новой версии».

## Сгенерированные сценарии

Файлы каталога — ещё и шаблоны генератора (`apps/api/app/seed/generator.py`, GP-14). Когда
обучаемый прошёл все готовые сценарии ступени, тренировка готовит новый: берёт файл своей
службы (для уровней 3–4 — уровня 2), меняет адрес, заявителя, телефон и номер карточки,
добавляет ловушки по уровню и слабому месту и проверяет результат той же схемой. Новый
сценарий — черновик в пакете «Сгенерировано для тренировок» в студии сценариев:
преподаватель утверждает его или отклоняет. Чем больше файлов у службы, тем разнообразнее
сгенерированные сценарии.
## Набор на финал

По сценарию на службу (`docs/dds_gameplay.md`, раздел 8) и бытовой сценарий со звонком
заявителю (рекомендации организаторов 16.10, п. 8). У каждого — полный план бригады, ветки и
варианты частей; проверка — `apps/api/tests/test_final_scenarios.py` (эталонный путь и одна
ветка ошибки через API).

| Файл | Служба | Что проверяет | Ветка ошибки в разборе |
|---|---|---|---|
| `smoke-apartment-101-1.json` | 101 | Повтор адреса с ошибкой, этаж, скорая жильцу, тревога (вводная преподавателя) | Не поправили повтор адреса — критическая ошибка |
| `traffic-blocked-102-2.json` | 102 | ДТП, Каширское шоссе, 26: повтор адреса, участники уехали | «Работы завершены» вместо «Отказ от выполнения работ» |
| `unwell-street-103-2.json` | 103 | Человеку плохо у аптеки: вопрос бригады, отказ от госпитализации | «Отказ от выполнения работ» у скорой (памятка, с. 23) |
| `gas-entrance-104-2.json` | 104 | Запах газа в подъезде: нужна пожарная охрана — звонок в 112 | Не сообщили в 112 — бригада перезванивает, работы затягиваются |
| `not-ours-pipe-104-2.json` | 104 | Не наша карточка: течь в подвале дома без газа | Карточку приняли — ошибка маршрутизации |
| `animal-shaft-gkh-1.json` | ЖКХ | Котёнок в вентиляционной шахте: звонок заявителю по телефону ДДС | Заявителя нет в списке — звонка нет |

**Звонок заявителю.** Номер заявителя — в карточке. Позвонить ему можно, только если заявитель
есть в телефоне ДДС (роль «Заявитель»): на занятии его включает преподаватель (например номер
458), в тренировке по каталогу — сама тренировка (405). В случайную выдачу ступеней бытовой
сценарий не попадает: его выбирают сами. С пострадавшими ДДС не говорит ни в одном сценарии.

**Пауза между докладами** (GP-12). Обучаемый не ждёт доклада дольше 40 с и после ошибки
(`docs/dds_gameplay.md`, раздел 1, п. 5). Задержку ветки (`delay`) сервер сам обрезает до 40 с
от начала ожидания доклада, а срок события, исход которого что-то меняет, — данные: не больше
40 с от начала отсчёта (`after_s + within_s`, у молчания бригады `silent_s + within_s`).
Проверка — `apps/api/tests/test_report_wait_budget.py`, правила — `contracts/scenario-events.md`,
«Пауза между докладами». Прохождение набора на стенде трижды (голосом, по частям, с ошибками) —
`qa/smoke/dds_walk.py`, отчёт — `docs/dds_gameplay_check.md`.

**Отдел контроля** (TC-07). У сценариев 101–104 набора есть `control_call`: карточка дольше
60 с без «Принята» или «Не принята» — звонит отдел контроля реагирования и просит пояснить
(памятка ДДС, с. 26–28). Варианты пояснения без микрофона — `reply_options` (правильного нет,
пояснение не оценивается, но видно в разборе). Правила — `contracts/scenario-events.md`,
«Отдел контроля»; добавили поле — новая версия файла.

**Озвучка.** Реплики бригад набора — фразы банка озвучки (GP-25, раздел ниже); до записей
банка они уходят текстом. Повтор адреса с ошибкой и реплики, которых в банке ещё нет, остались
текстом и записями прежней версии.

## Реплики — из банка озвученных фраз

Решение 16.10 (`docs/decisions.md`, «Сценарии ИИ собираются из готовых фраз»): реплики бригад
не пишутся заново, а берутся из банка `scripts/voices/bank` — правила места в разговоре, фактов
и связности в `contracts/scenario-events.md`, «Реплики — из банка озвученных фраз».

1. **Происшествие банка.** Найдите в книге службы (`phrases/<служба>.json`, поле `incidents`)
   код происшествия сценария и впишите пару «служба, `incident_type_code` → код» в
   `BANK_INCIDENT` проверки `apps/api/tests/test_scenario_phrases.py`. Нет подходящего — годятся
   только фразы с `incidents: ["*"]`.
2. **Фраза на каждый шаг.** Доклад плана — по статусу, который он обосновывает; события и ветки —
   по виду события. Текст копируется дословно, `audio` не пишется до записей банка; с набором
   `data/voices/bank-v1` — `"audio": "bank-v1/<служба>/<id>.ogg"`.
3. **Связность.** Факты фраз (`facts`) не спорят с карточкой (пострадавшие, заблокированные) и
   между собой; одна фраза — один раз на сценарий, в том числе в разных ветках.
4. **Фразы нет.** Свою не придумывайте: оставьте прежний текст, впишите место в `AWAITING`
   проверки (служба, slot, нужный смысл) и в `scripts/ralph/gameplay/handoff.md` — фразу
   допишет и озвучит сессия озвучки.

Проверка — `apps/api/tests/test_scenario_phrases.py`: все файлы, кроме 30 перенесённых из
`data/practice` без правок (у них реплики с записями Piper).
