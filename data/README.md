# Данные для старта команды

`classifier.json` воспроизводимо собран из **046_24** (решение капитана 24.09):
`docs/dataset/Датасет/Классификатор_…_046_24_….csv`, **1283 типа, 3835 правил** шести MVP-служб.
Парсер `evalcore/classifier.py` определяет редакцию по шапке (046_24 или прежняя 046_11,
1281/3854) и проверяет, что колонки относятся к нужным службам. У правила есть стабильный
`condition.trigger` (`default`, `no_access`, `offense`, `victims`, `victims_off_site`,
`gasification`): номер колонки между редакциями сдвинулся, смысл условия — нет.
`scenario_code` в 046_24 пуст — такого столбца нет. Исходник предоставлен кейсодержателем,
внешняя лицензия не утверждается. Сборка — `uv run --package arm112-scripts python scripts/build_classifier.py`.

Сиды, номера 105/106, ФИО, телефоны и golden — синтетические данные команды.
Они не являются импортом материалов заказчика. 24.09 получен и проверен
[набор из 32 билетов / 96 задач, памятка ДДС и классификатор 046_24](../docs/dataset/README.md).
По решению капитана используем 046_24,
эталоны разрабатываем самостоятельно; ответов и исходного аудио от заказчика не ожидаем.
Новый классификатор отличается структурой и правилами, подключение требует адаптации
парсера. Полный справочник улиц Москвы и четыре Piper-голоса
не входят в D1-каркас; получение/лицензирование отслеживается отдельно в STATUS.md.
Golden проходят проверку схем, но ещё не проверку алгоритмов оценщика T-006.
Форматы и ожидания — `contracts/data_formats.md`; пароли задаются только env.

## C-05: источники и синтетические черновики

`source_inventory.json` фиксирует файлы этой рабочей копии и отдельные наблюдения из
`docs/fromTG`, загруженного пользователем в исходную worktree: относительный путь, размер,
SHA-256, известную версию и статус прав. Хеши десяти вложений записаны в
`fromtg_manifest.json`; шесть совпадают побайтно с уже имеющимися документами.
Бинарные файлы `fromTG` в ветку C-05 не скопированы. Обновление локального инвентаря:
`python scripts/inventory_c05_sources.py`; проверка без записи: `--check`. При наличии
вложений `--tg-dir ПУТЬ` пересчитывает и проверяет их хеши.
Оригинальный классификатор v0.46, его CSV и `classifier.json` учтены отдельно.
Пересланное сообщение о найденном участниками датасете не подтверждает наличие файлов здесь.
Datasheet телефона РТУ Т16Р найден в `fromTG`, но не содержит справочника номеров ДДС;
инструкция по заведению карточки относится к оператору 112, не является памяткой ДДС.
Для 96 официальных билетов и решений, памятки ДДС и справочника улиц в инвентаре стоят
явные отсутствия. Права на материалы заказчика пока не установлены.

`generated_packs/pack-01.json`…`pack-03.json` — три воспроизводимых набора по 10 **синтетических
черновиков** для проверки конструктора. Их создаёт `uv run --package arm112-scripts python
scripts/build_c05_packs.py` (`--check` проверяет уже сохранённые файлы). Адрес взят из
единственного учебного шаблона, поэтому пакеты не доказывают покрытие улиц Москвы и не должны
выдаваться за импорт 96 билетов. Файлы содержат `ScenarioPreview` с происхождением и эталоном;
формат является автономным артефактом для ревью, не сидом `data/packs/`.
Черновик с `wrong_address` содержит `validation_errors`: ответ заказчика от 23.09 относит
контроль исходной карточки к оператору 112, а последующее уточнение для ДДС пока не получено.
Такой черновик нельзя утверждать или оценивать как обязанность ДДС без решения по этому стыку.
Краткая карта новых ответов заказчика и открытого уточнения — `tg_followup_20260924.md`.

`ScenarioGenerator(classifier)(constructor)` получает данные от вызывающего кода и не читает
файлы. Основная служба берётся из `main_service_code`; дополнительные службы добавляются
только по тем колонкам классификатора, условие которых выражено во входе: пострадавшие
(23/24/25) и безусловные Мослифт/ЖКХ (54/56). Колонки о правонарушении, доступе и
газификации без соответствующих признаков не считаются выполненными. `suggested_weight` —
простое предложение `clamp(2×level−1 + victims + число осложнений, 1, 10)`; явный вес учителя
сохраняется. Отсутствие справочника улиц означает, что адрес пока проверяется только на
обязательные компоненты, не на существование в Москве.
`provenance.sha256` в preview — хеш канонического JSON переданного классификатора;
`source_inventory.json` хранит хеш исходных байтов каждого файла.

## C-05: сценарии по билетам заказчика

`ticket_scenarios/ticket-NN-K.json` — **10 заданий из 32 билетов** (билеты 1, 2, 3, 4, 5, 30, 31, 32):
пожары (101), драка и нарушение тишины (102), запах газа в квартире и частном доме (104),
наезд на пешехода и ДТП с троллейбусом, отравление (103) и отказ по зоне ответственности
(адрес в Московской области → «Не принята» с причиной). Ситуация и адрес перенесены вручную
со скана страницы PDF; OCR использовался только для поиска.

- `origin=imported`, `status=draft`: эталон — **учебная разметка команды** по памятке ДДС и
  классификатору 046_24; преподаватель утверждает сценарий в студии (FR-3.3). Готовых ответов
  заказчик не предоставляет.
- `ticket_scenarios/manifest.json` — происхождение: билет, задача, страница, дословные ситуация
  и адрес, версия классификатора, основание эталона, `teacher_review=not_reviewed`.
- Телефоны заявителей заменены учебными `+7900000…`; ФИО из билетов вымышлены.
- Пакет `packs/tickets-01.json` (draft). Seed загружает сценарии и пакет идемпотентно.
- Сборка и проверка: `uv run --package arm112-scripts python scripts/build_ticket_scenarios.py [--check]`.
  Тест `scripts/tests/test_ticket_scenarios.py` сверяет схему, службы с 046_24 и то, что
  эталонное прохождение получает полный балл по маршруту, статусам и адресу.

Лифтовых и коммунальных ситуаций в билетах нет: для МОСЛИФТ и ЖКХ остаются синтетические
golden-сценарии. Остальные 86 задач — кандидаты следующих пакетов.

## Тренировка без преподавателя: семь происшествий

`practice/*.json` — готовые происшествия для самостоятельной тренировки ступеней 2–3:
задымление в квартире, застревание в лифте с плохим самочувствием, ДТП с зажатым водителем,
запах газа в квартире, прорыв трубы в подвале газифицированного дома, плохо с сердцем на
улице, драка на улице. Службы карточки — по правилам классификатора для типа происшествия;
для каждой службы — два сценария (`app/seed/practice.py`):

- уровень 1 (ступень 2) — полный цикл: доклады о выезде, прибытии, работах и завершении;
- уровень 2 (ступень 3) — после прибытия бригада докладывает, что работы не проводились, и
  называет причину («Отказ от выполнения работ»); у 103 вместо отказа — «Работы завершены»
  (памятка ДДС, стр. 23).

Каждый доклад ждёт статуса диспетчера (`requires_state`). Тексты докладов — учебные, команды,
в стиле `scripts/voices/brigade_texts.py`, не регламентные формулировки служб. Озвучка —
`voices/practice/` (Piper, голос службы, `scripts/voices/practice_generate.sh`); доклад без
файла или с изменённым текстом уходит текстом. Загружает `python -m app.seed.training`,
идемпотентно; уже загруженный сценарий не меняется — правка текста требует нового ключа.
