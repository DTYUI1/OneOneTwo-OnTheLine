# Стенд одной командой

`up.sh` поднимает стенд ARM112 в Docker (build → база → миграции → seed → api/worker/web
→ ожидание `/api/health`), `down.sh` его останавливает. `deploy/docker-compose.yml` при
этом не меняется — свой override и секреты лежат в `scripts/stand/.local/<проект>/`.

Общая установка из репозитория (не для занятия, без `--lan`) описана в
`docs/submission/documentation/03_install.md` — там же требования к CPU/диску и офлайн-установка.

```
scripts/stand/up.sh --project arm112-ralph --ports 45080:45443
scripts/stand/down.sh --project arm112-ralph
```

## Занятие в классе по сети

### Требования

- Docker Desktop (Mac/Windows) или colima с Docker Engine на macOS, Docker Compose ≥ 2.24.
- Память: без ИИ — около 1,5 ГБ, с ИИ (`--ai local`) — ещё около 4 ГБ сверху. Для colima —
  `colima start --memory 8` (по умолчанию у colima 2 ГБ, этого мало даже без ИИ).
- Компьютер преподавателя и ученические — в одной сети (Wi-Fi/LAN), без изоляции клиентов
  друг от друга (см. таблицу симптомов ниже).

### Порядок

1. Поднять стенд с доступом из сети:
   `scripts/stand/up.sh --project arm112-ralph --ports 45080:45443 --lan` (или `--ip АДРЕС`,
   если автоопределение IP ошиблось).
2. Проверить, что всё поднялось и видно по сети:
   `scripts/stand/check.sh --project arm112-ralph` — код выхода 0 и все пункты «ok».
3. Подготовить браузеры учеников: доверить корневой сертификат стенда
   (`scripts/stand/ca.sh --project arm112-ralph`), иначе браузер покажет «Не защищено» или
   не даст ввести пароль.
4. Раздать адреса:
   - преподаватель и ученики — `https://<IP>:<порт>/app/login` (IP и порт печатает `up.sh` в
     конце и `check.sh` в разделе про сеть);
   - вход в «комнату» без пароля — `https://<IP>:<порт>/`.
5. Остановка без потери данных после занятия: `scripts/stand/down.sh --project arm112-ralph`
   (просто `stop`, тома с базой и записями остаются).
6. Сброс перед новым занятием «с чистого листа» (удаляет все данные стенда, включая учётные
   записи и сохранённые ответы): `scripts/stand/down.sh --project arm112-ralph --reset --yes`.

### Симптом → причина → что сделать

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| С другого ноутбука страница не открывается вовсе | Стенд поднят без `--lan`/`--ip` (слушает только 127.0.0.1), или ученик не в той же сети, или сеть изолирует клиентов друг от друга | `check.sh --project ИМЯ` — проверить пункты про IP и порт; переподнять с `--lan`; на Wi-Fi отключить «изоляцию клиентов» (AP/Client isolation) в настройках роутера |
| Браузер пишет «Не защищено» / ругается на сертификат | Корневой сертификат стенда не доверен на этом компьютере | `ca.sh --project ИМЯ` на компьютере ученика, довериться по инструкции для его ОС/браузера, перезапустить браузер |
| `migrate` падает с ошибкой пароля к базе | Пароль в `DATABASE_URL` не совпадает с паролем, который сохранён в уже существующем томе базы (пароль тома фиксируется при первом создании) | Не менять `stand.env` вручную; если пароль потерян — только `down.sh --project ИМЯ --reset --yes` и новый `up.sh` (данные будут потеряны) |
| `up.sh` падает или порт не открывается — порт уже занят | Другой процесс или другой стенд (`arm112`, `arm112-lan`, ещё один `arm112-ralph*`) уже слушает этот порт | `check.sh --project ИМЯ` покажет, кто слушает порт; выбрать свободный `--ports` |
| На colima стенд поднимается, но всё работает очень медленно или падает | VM colima поднята с памятью по умолчанию (2 ГБ) — мало даже без ИИ | Пересоздать VM с большей памятью: `colima stop && colima start --memory 8` |
| ИИ (`--ai local`) отвечает медленно или не отвечает | Локальной модели не хватает памяти/CPU, отведённых VM (colima/Docker Desktop) | Увеличить память VM (см. выше) и CPU в настройках Docker Desktop/`colima start --cpu`; при нехватке ресурсов — вести занятие с `--ai off` |

## Доступ из локальной сети (`--lan`)

```
scripts/stand/up.sh --project arm112-ralph --ports 45080:45443 --lan
scripts/stand/up.sh --project arm112-ralph --ports 45080:45443 --ip 192.168.1.23
```

`--lan` открывает web на всех интерфейсах машины (`WEB_BIND=0.0.0.0`) и включает IP машины
в сертификат (`CERT_HOSTNAMES=localhost,127.0.0.1,<IP>`), чтобы браузер на другом компьютере
не ругался на сертификат. IP определяется сам: на macOS — `ipconfig getifaddr en0`/`en1`, на
Linux — `ip route get 1` или `hostname -I`, в Git Bash и WSL на Windows — `ipconfig`. `--ip`
задаёт адрес вручную и тоже включает `--lan`.

Если сертификат проекта уже выпущен без нужного IP, `up.sh` пересоздаёт только том
сертификатов (том базы данных не трогает) и перезапускает web.

В конце команда печатает адрес для других компьютеров сети:
`https://<IP>:<порт>/app/login`.

**Не проверено на Windows** (Git Bash, WSL) — код определения IP там нужно проверить
перед использованием на занятии.

## Диагностика («не подключается»)

```
scripts/stand/check.sh --project arm112-ralph
scripts/stand/check.sh --project arm112-ralph --ip 192.168.1.23
```

По каждому пункту печатает «ok» или «ошибка» с советом: контейнеры проекта и их health,
`/api/health`, кто слушает порт на хосте, IP машины и есть ли он в сертификате, открывается
ли `/api/health` по этому IP с этой же машины, состояние брандмауэра macOS, проброс порта
colima. В конце — что проверить, если с другого компьютера не открывается. Код выхода:
0 — всё в порядке, 1 — есть ошибки. Ничего не поднимает и не останавливает.

## Смоук стенда

```
scripts/stand/smoke.sh --project arm112-ralph
```

Запускает по-настоящему поднятому стенду (`up.sh`, база данных) минимальный набор
`qa/e2e` в Chromium: `foundation.spec.ts` (вход, перезагрузка, выход трёх ролей),
`welcome.spec.ts` (приветствие), `help-mode.spec.ts` (справка по окну). В конце —
сводка `passed`/`failed`, трассы упавших тестов — `qa/results`. Код выхода: 0 — все
тесты прошли, 1 — иначе. Ничего не поднимает и не останавливает — стенд должен уже
работать (`up.sh`).

## Сертификат для браузеров («Не защищено»)

```
scripts/stand/ca.sh --project arm112-ralph
```

Достаёт корневой сертификат стенда из тома сертификатов проекта в
`scripts/stand/.local/<проект>/ca.crt` и печатает, как довериться ему: macOS
(`security add-trusted-cert`), Windows (`certutil -addstore -f Root` из PowerShell от
администратора, или `deploy/certs/install-ca.ps1`), Linux (`deploy/certs/install-ca.sh`) и
отдельно Firefox — у него своё хранилище сертификатов. После доверия браузер надо
перезапустить.

## Сервер в интернете (`remote.sh`)

Для слабого сервера, где собирать образы нельзя (например 1 vCPU и 1 ГБ памяти): образы
собираются на своей машине под архитектуру сервера и переносятся по ssh, на сервер
копируются только `deploy/docker-compose.yml` и `scripts/stand`.

```sh
scripts/stand/remote.sh --host riker-ams          # сборка, перенос, запуск на 8080:8443
ssh riker-ams grep DEMO_PASSWORD /opt/arm112/scripts/stand/.local/arm112-stand/stand.env
```

- На сервере нужны `docker` и `docker compose` (Ubuntu: `apt install docker.io
  docker-compose-v2`); при 1 ГБ памяти — swap 1–2 ГБ. ИИ (`--ai local`, ~4 ГБ) и
  распознавание речи (`--stt local`, ~0,75 ГБ) на таком сервере не помещаются.
- Сборка под x86 на Mac — через `docker buildx` с эмуляцией (colima:
  `brew install docker-buildx`), около получаса. Уже собранные
  `arm112-{api,web}:<проект>` — `--skip-build`.
- Стенд открыт в интернет, поэтому пароль учётных записей случайный
  (`up.sh --random-password`) и остаётся на сервере; в вывод не попадает.
- Сертификат — свой, на IP сервера: без `ca.sh` браузер предупредит «Не защищено».
- Порт 443 может быть занят (например VPN) — поэтому 8443; другой — `--ports`.
