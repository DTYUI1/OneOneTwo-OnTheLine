# Банк фраз озвучки ДДС

Решение 16.10 (brikkerdev и тимлид): сценарии, которые готовит ИИ, собираются из заранее
озвученных фраз. Голос по API в тренажёре не синтезируется. Банк копится, пока не покроет
службы и типы происшествий. Голоса — `../casting/voices.json` (выбраны на кастинге 16.10).

```sh
python3 scripts/voices/bank/bank.py check       # проверить файлы фраз
python3 scripts/voices/bank/bank.py synth       # смета: сколько символов уйдёт
python3 scripts/voices/bank/bank.py synth --go  # озвучить новое
python3 scripts/voices/casting/casting.py serve # слушать: http://localhost:8112/bank/
```

Запись хранится по хешу «модель + голос + настройки + текст» в общем кеше
`../casting/out/cache/`: фраза, которая уже звучала, на сервер больше не уходит, и правка одной
фразы перезаписывает только её. Записи сырые (mp3 44,1 кГц): телефонную полосу и подложку
добавляет сборка (`phone.py`) локально, её можно менять без нового синтеза.

## Фраза

```json
{"id": "101.arrived.smoke.2", "slot": "arrived", "incidents": ["smoke"],
 "text": "Прибыли. Дым из окна, в подъезде сильное задымление, начинаем разведку.",
 "facts": ["no_access"]}
```

- `id` — постоянный ключ `<служба>.<место>.<происшествие или any>.<n>`. Если смысл фразы
  поменялся, это новая фраза с новым `id`: старая уже могла попасть в выданный сценарий.
- `slot` — место фразы в разговоре (таблица ниже).
- `incidents` — коды происшествий службы (список в файле службы) или `["*"]`: подходит к любому.
- `facts` — что фраза утверждает о мире. По ним сборщик сценария не ставит фразу, которая
  противоречит карточке или соседним фразам. Набор закрыт, список ниже.
- `asks` — у `clarify`: о чём вопрос. `needs` — у `request_service`, `service_coming` и
  `service_surprise`: о какой службе речь.
- `tone` — тег подачи ElevenLabs v4 на английском в квадратных скобках (`[out of breath]`,
  `[shouting]`, `[tired]`). Только там, где без него фраза врёт: тревога, срочность.
- `requires` — условие использования специальной реплики. Сейчас поддерживается только
  `["wrong_briefing"]` у `update` бригады: сообщение о расхождении первой полной вводной
  с фактическим происшествием. Обычный генератор исключает такие фразы из случайного пула;
  мир выбирает конкретную запись только после отправки по неверному поводу. `when` — лишь
  пояснение автору и не заменяет проверяемое условие.

Набор `data/voices/bank-v10` содержит только шесть новых записей такого сообщения — по одной
на службу, прежними голосами ElevenLabs. Старые записи не пересинтезированы и не изменены.
Текст, голос, длительность и SHA-256 записаны в манифесте; происхождение и границы проверки —
`data/voices/bank-v10/PROVENANCE.md`.

### Места в разговоре (`slot`)

| slot | Когда звучит | Пример |
| --- | --- | --- |
| `answer` | бригада снимает трубку на звонок диспетчера | «На связи.» |
| `intro` | бригада звонит сама: кто на связи | «Старший расчёта, на связи.» |
| `no_reply` | диспетчер ответил на вызов и молчит | «Диспетчер, слышите меня?» |
| `confirm_request` | конец доклада: подтвердите приём | «Как приняли?» |
| `repeat_report` | перед повтором последнего доклада («доложите ещё раз») | «Повторяю.» |
| `briefing_ask` | вводная неполная, бригада переспрашивает; `asks`: `address`, `what`, `both` | «Адрес принял. Что случилось?» |
| `refusal_busy` | бригаду, занятую на другом происшествии, пытаются направить | «Мы на другом пожаре.» |
| `refusal_not_assigned` | звонят бригаде, которой вызов не назначен | «Нам этот вызов не назначен.» |
| `responding` | приняли вводную, выезжают | «Принял, выезжаем.» |
| `enroute` | «доложите обстановку» по пути | «Едем, минуты через три будем.» |
| `delay` | задержка в пути | «Стоим, двор заставлен машинами, идём пешком.» |
| `wrong_place` | приехали не туда (после неисправленного повтора адреса) | «По этому адресу вызова нет. Проверьте адрес!» |
| `readback_fixed` | приняли поправку адреса | «Понял поправку, разворачиваемся.» |
| `arrived` | прибытие и первая обстановка | |
| `working` | ход работ | |
| `update` | обстановка изменилась (усложнилась или прояснилась) | |
| `status_working` | «доложите обстановку» на работах, ответ на звонок после молчания | |
| `completed` | итог, работы завершены | |
| `refused` | работ не было: ложный, не подтвердилось, ушёл, устранили сами, не наше | |
| `clarify` | вопрос диспетчеру | «Диспетчер, какой код домофона?» |
| `clarify_ok` | ответ получен | «Понял, поднимаемся.» |
| `clarify_unknown` | диспетчер не знает | «Понял, будем искать сами, это займёт время.» |
| `clarify_late` | ответ пришёл поздно | «Уже нашли сами.» |
| `request_service` | бригада просит вызвать другую службу | «Нужна скорая, срочно!» |
| `service_coming` | на просьбу о службе диспетчер ответил «уже вызвал, едут» (GP-28) | «Понял, скорую ждём.» |
| `service_surprise` | служба вызвана заранее, бригаде не сказали — приехала сама (GP-28) | «Скорая подъехала. Хорошо, конечно, но могли бы и сказать, что вызвали.» |
| `alarm` | беда с самой бригадой | «Тревога! Боец травмирован!» |
| `alarm_ack` | после помощи по тревоге | «Понял, ждём скорую.» |
| `ack` | короткое подтверждение | «Понял.» / «Принял.» |
| `not_understood` | не расслышали | «Не понял, повторите.» |
| `end_call` | конец разговора | «Принял, конец связи.» |

Реплики сюжетов связки 112 → ДДС (`app.seed.link112`) — книги `link112/<служба>.json`
рядом с `phrases/`: текст дословно как в `data/link112/plots`, сервер находит запись по
службе и тексту; в окно телефона (`web.py`) и генератору они не идут.

Живой заявитель бытового сценария (HQ-019, требования — `docs/dds_caller.md`) — книги
`callers/CALLER_<характер>.json`: одна хозяйка квартиры, одни сведения сюжета (`plot_facts`),
книга на характер (`CALLER_CALM` — спокойная, `CALLER_CONFUSED` — растерянная), голос один
(`voices.json`). Места: `answer`, `answer_again`, `ask_who`, `tell_<сведение>`,
`confirm_address` (диспетчер прочитал адрес верно), `correct_address` (с ошибкой; `wrong` —
`house` или `flat`), `unknown`, `repeat`, `not_understood`, `agree`, `no_reply`, `hangup`,
`end_call`. `tells` — какие сведения сюжета звучат в реплике. `on` — когда звучит: у `tell_*`
`first` — неполный ответ (сведения не даёт), `again` — ответ на уточнение; у `repeat`
`first` — первый повтор, `again` — второй и дальше; без `on` реплики места взаимозаменяемы.
`when` — словами, когда ставится реплика (не проверяется). Адрес — в `text` цифрами, в `say` словами. В окно телефона книги
идут целиком (`web.py`: все места, с `on`, `wrong`, `tells`), разговор ведёт
`apps/web/src/arm/softphone/caller/`; генератору не идут; запись — подложка «улица» (`port.py`).
Сюжет книги (`incidents`) сценарий называет в блоке `caller {plot, character}`. У сюжета —
таблица `callers/plots/<сюжет>.json`: вопросы диспетчера на кнопках (`facts.<сведение>.ask`),
слова, по которым окно узнаёт вопрос во фразе (`hear`, регулярное выражение), слова повода
(`reason`) и просьба подойти (`come`); код заявителя общий, новый сюжет — книги и таблица.
`web.py` и `bank.py check` не пропускают сюжет без таблицы, без реплик в книге любого характера
или со сведениями не как в `plot_facts`.

Новая редакция фразы — книга `revisions/<книга>.json` с тем же заголовком (служба, голос):
новый `id`, то же место и `number`, поле `replaces` — id старой фразы. Старая фраза и её
запись не меняются; окно телефона (`web.py`) ставит новую на место старой, когда у новой
есть запись в наборах `data/voices/bank-v*`, — до синтеза звучит старая. Id фразы, записанный
в коде (`ASK_IDS`, `PHRASE_ID`, `CONTROL_*_ID`; тесты не в счёт), после записи редакции надо
сменить на id редакции: `bank.py check` до записи пишет заметку «код: …», после — ошибку;
`web.py` не пишет выборку, где id из кода окна нет, и называет, чем его заменить (HQ-037).

Фраза, написанная под реплику сценария, встаёт в сценарий только с записью: до синтеза
реплика остаётся прежней записанной фразой. Что куда встанет — `placements.json` (сценарий,
доклад, его текст сейчас `was`, id фразы; `event` и `branches` — подмена доклада в ветках
события). После записи набора `bank-vN` — `python3 scripts/voices/bank/place.py`: ставит
записанные фразы, поднимает версии сценариев и убирает записи из плана (`--dry-run` — только
показать). План сверяет
`apps/api/tests/test_scenario_phrases.py`.

Должностные лица (`OFFICIAL*.json`): `answer`, `accepted`, `registered`, `ask_who`,
`ask_address`, `ask_what`, `ask_card`, `ask_victims`, `not_understood`, `end_call`.
`OFFICIAL.json` — общий дежурный и оператор 112. `OFFICIAL_<служба>.json` — дежурный
конкретной службы: постоянный персонаж (`character`, например «дежурный Петров»), свой голос,
может назвать себя по фамилии. `registered` — принял и назвал номер регистрации или наряда;
число словами в тексте и цифрами в поле `number`, его сверяют с комментарием диспетчера.

### Факты (`facts`)

`victims` · `no_victims` · `blocked` · `victim_male` · `victim_female` · `victim_child` · `victim_elderly` ·
`hospitalized` · `refused_hospital` · `evacuated` · `no_access` · `false_call` · `gone` ·
`self_resolved` · `other_org` · `detained` · `handed_103` · `handed_102` · `fire` · `no_fire` ·
`gas` · `no_gas`

`victims` — пострадавшие (признак карточки «Пострадавшие»), `blocked` — люди заблокированы
(признак «Заблокированы люди»: заперты, застряли в лифте), сами по себе не пострадавшие.
`victim_*` описывает того, о ком происшествие (пострадавший, заблокированный, пропавший),
и сам по себе не значит `victims`.

## Как писать фразу

- Живая служебная речь по телефону. Не дикторский текст, не протокол. Короткие рубленые
  фразы, иногда незаконченные. Начало разное: «Диспетчер,», «Докладываю:», «Так,», или сразу
  по делу.
- Длина разная: от двух слов до двадцати. Средняя — фраза на один выдох.
- Разнообразие по содержанию, а не синонимами. «Прибыли, дым из окна» и «На месте, дым
  из окна» — это одна фраза. Вариант — другая деталь обстановки.
- Ни адресов, ни номеров квартир и этажей, ни фамилий (кроме своей фамилии должностного
  лица), ни времени на часах: фраза должна
  встать в любой сценарий. Количество людей — только если это `facts` или «двое», «трое»
  там, где это не спорит с карточкой (лучше обойтись).
- Без цифр и сокращений: всё словами, как произносится. Не «ДТП», а «авария»; не «СМП»,
  а «скорая». Буква «ё» везде, где она звучит.
- Род говорящего: у скорой (103) голос женский, глаголы прошедшего времени в первом лице
  единственного числа — женского рода («Поняла», «Приняла»). У остальных — мужского.
  «Мы» и «бригада» — без рода.
- Профессиональные слова своей службы: у пожарных расчёт, звено, рукавная линия, разведка;
  у полиции наряд, экипаж, доставили в отдел; у скорой бригада, госпитализируем, давление;
  у газовой аварийная бригада, перекрыли стояк, загазованность, прибор; у ЖКХ слесарь,
  стояк, перекрыли воду, сантехник; у Мослифта механик, кабина, машинное помещение,
  обесточили.

## Как сборщик сценариев берёт фразы

Это задача для генератора GP-14 (`apps/api/app/seed/generator.py`, ветка
`feature/dds-gameplay-ai`). Сейчас там новый доклад уходит текстом без голоса.

1. **Перенос в данные.** `out/` проходит через `phone.py` (телефонная полоса и подложка, как у
   `dds-v3`) в `data/voices/bank-v1/<служба>/<id>.ogg` с манифестом SHA-256. Это делается
   локально и без нового синтеза. Набор неизменяем: новые фразы попадают в него дописыванием.
2. **Шаг сценария → место в разговоре.** План: `responding` → `responding`, `arrived` →
   `arrived`, `working` → `working`, итог → `completed` или `refused` по `expected_flow`.
   События: `clarify` — вопрос `clarify`, ветки `clarify_ok` / `clarify_unknown` /
   `clarify_late`; `request_service` — `request_service` с `needs` из служб, которых у
   обучаемого нет, ветки `already` → `service_coming`, `surprise` → `service_surprise` с тем
   же `needs` (нет в файле — загрузчик берёт их сам, `apps/api/app/seed/service_defaults.py`); `silence` — ветки `status_working`; тревога — `alarm`, ветки `alarm_ack`;
   повтор адреса — ветка `met` → `readback_fixed`, `wrong` → `wrong_place`.
3. **Отбор.** Подходят фразы происшествия сценария и фразы с `["*"]`. Факты фразы не
   спорят с карточкой (`victims`, `blocked_people`, газ, огонь) и с уже выбранными фразами
   сценария: пострадавшая женщина при прибытии не превращается в мужчину в итоге. Внутри
   сценария фраза не повторяется. Из подходящих лучше брать ту, которую обучаемый ещё не
   слышал.
4. **Роль модели.** Ход сценария, события и ловушки по уровню решает код: локальная модель
   на 4 млрд параметров его надёжно не соберёт, а целый сценарий (5–6 тыс. токенов) не влезает
   в контекст 4096. Код отбирает под каждое место 5–10 подходящих фраз (место, происшествие,
   факты), модель выбирает `id` из этого списка. Ответ проверяется просто: `id` есть в списке.
   Без модели фраза выбирается случайно среди подходящих (шаблонный путь).
5. **Чего в банке нет.** Реплика повтора адреса с ошибкой («как поняли, Дубининская
   двенадцать?») содержит адрес и заранее не записывается. Она остаётся текстом или
   берётся только из сценариев, где адрес известен заранее.
