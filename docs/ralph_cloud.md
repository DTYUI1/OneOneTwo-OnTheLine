# Ralph в облаке: промпт сессии claude.ai/code

Облачная сессия ведёт цикл одного владельца. Короткий промпт для запуска сессии:

```
Ветка feature/dds-gameplay-<владелец>: git fetch origin <ветка> && git checkout <ветка>.
Прочитай docs/ralph_cloud.md и работай по нему. ВЛАДЕЛЕЦ: <владелец>.
```

Владельцы и ветки:

| Владелец | Ветка |
|---|---|
| `gameplay` | `feature/dds-gameplay` |
| `ai` | `feature/dds-gameplay-ai` |
| `infra` | `feature/dds-gameplay-infra` |

Перед стартом облачной сессии локальный цикл этой ветки останавливается. Две сессии на одну ветку не пускать.

## Правила облачного цикла

Ты — автономный агент цикла Ralph в репозитории brikkerdev/OneOneTwoInTouch — форке командного DTYUI1/OneOneTwoInTouch, в облаке origin = форк (учебный тренажёр диспетчера
ДДС системы-112). Человека рядом нет: не спрашивай и не жди ответа, решай сам по правилам ниже.

**Подготовка**
1. Ветка — `feature/dds-<…>` по таблице выше: `gameplay` → `feature/dds-gameplay`, `ai` → `feature/dds-gameplay-ai`,
   `infra` → `feature/dds-gameplay-infra`. Выполни `git fetch origin <ветка> && git checkout <ветка> && git pull --ff-only`.
2. Установи зависимости: `uv sync --all-packages` и `pnpm install --frozen-lockfile`. Если чего-то нет, поставь (uv, node 22, pnpm 9).
3. Postgres 16 для тестов с базой:
   - если есть Docker — `docker run -d --name testdb -e POSTGRES_USER=t -e POSTGRES_PASSWORD=t -e POSTGRES_DB=t -p 127.0.0.1:55450:5432 postgres:16-alpine`;
   - если Docker нет — apt-пакет postgresql-16 на порту 55450 с пользователем, паролем и базой `t`.

   Затем `export DATABASE_URL_TEST=postgresql+asyncpg://t:t@127.0.0.1:55450/t`. Не вышло — тесты с базой пропускаются сами, запиши это в notes.
4. Прочитай `scripts/ralph/prompt.md`. Это правила ночного цикла, они действуют целиком, кроме трёх отличий:
   - ты сам выбираешь истории и ведёшь цикл;
   - после каждой истории пушишь;
   - стенд в облаке может быть недоступен.

   Затем прочитай `scripts/ralph/<владелец>/progress.txt` (паттерны и последние записи), `zone.txt` и `prd.json`.

**Цикл: повторяй, пока есть истории с `passes != true` и без `blocked`**
1. Возьми такую историю с наименьшим `priority`.
2. Сделай её по критериям приёмки и правилам `scripts/ralph/prompt.md`:
   - меняй только файлы своей зоны;
   - если меняешь контракт, сначала отдельный коммит `contract:`;
   - дизайн — по эталонам, на которые ссылается история.
3. Прогони `scripts/ralph/<владелец>/gates.sh HEAD~0`. Пока проверки красные, не коммить.
4. Стенд и e2e (`scripts/stand/up.sh`, `pnpm exec playwright test`) — только если в облаке есть Docker. Если Docker нет:
   - напиши e2e-спеку;
   - проверь, что она компилируется (`--list`);
   - в notes истории допиши: «e2e на стенде не прогнан (облако без Docker) — прогнать локально».

   Такой критерий считается выполненным условно.
5. Сделай коммит «ИД: заголовок». В `prd.json` поставь истории `"passes": true` и в `notes` запиши, чем проверено.
   Допиши запись в `progress.txt`. Закоммить это.
6. Отправь ветку: `git push origin <ветка>`. Если пуш отклонён, сделай `git pull --rebase origin <ветка>` и отправь
   снова. Force-push запрещён.
7. Историю нельзя выполнить? Поставь `"blocked": true`, напиши причину в notes и в `handoff.md`, закоммить, отправь
   и переходи к следующей.
8. Чувствуешь, что контекст кончается? Доведи текущую историю до коммита и пуша и закончи отчётом. Следующая сессия
   продолжит с первой незакрытой истории.

**Запрещено**
- пушить в другие ветки, трогать `main` и `dev`;
- переписывать историю (reset --hard, rebase опубликованного, push --force);
- коммитить секреты и файлы больше 5 МБ;
- удалять что-либо из `docs/`.

**В конце** короткий отчёт: какие истории закрыты (ИД и коммит), какие отложены и почему, что прогнать
локально на стенде.
