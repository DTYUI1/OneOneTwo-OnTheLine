    1. Описание работы компании, актуальность задачи и описание сервиса
     ГБУ «Система 112» является оператором системы-112 города Москвы, обеспечивающим
функционирование единого номера экстренных служб на территории столицы. Организация
отвечает за обработку вызовов и передачу информации в дежурно-диспетчерские службы (ДДС)
через автоматизированные рабочие места (АРМ).
     В настоящее время существует необходимость в создании специализированного
программного обеспечения для подготовки операторов ДДС. Актуальность разработки
обусловлена следующими факторами:
     • отсутствие специализированного ПО для обучения операторов работе с реальным
программным обеспечением системы-112;
    • потребность в систематическом обучении персонала с возможностью отработки
навыков в условиях, максимально приближенных к реальным;
     • необходимость объективной оценки знаний и навыков операторов с использованием
технологий машинного обучения;
    • отсутствие аналогов подобного обучающего программного обеспечения на рынке.
    Разрабатываемый тренажер должен представлять собой комплексное программное
решение для подготовки операторов экстренных служб, включающее следующие ключевые
компоненты:
    • система эмуляции вызовов с использованием IP-телефонии и технологий VoIP;
    • модуль управления обучением с возможностью распределения заданий по уровням
сложности;
    • компонент оценки эффективности подготовки операторов на основе анализа их действий;
    • интерфейс преподавателя для контроля процесса обучения.
    Разработка позволит:
    • автоматизировать процесс обучения операторов;
    • повысить качество подготовки специалистов;
    • объективно оценивать компетенции обучаемых;
    • сократить время адаптации новых сотрудников;
    • систематизировать процесс обучения с использованием современных технологий ИИ.
    При разработке необходимо учесть:
    • интеграцию с существующей инфраструктурой системы-112;
    • соответствие системным требованиям к аппаратному обеспечению;
    • обеспечение безопасности обрабатываемых данных;
    • возможность масштабирования решения под различные группы пользователей.

    2. Предназначение разрабатываемого сервиса
     Сервис создается для организации комплексного обучения и повышения квалификации
операторов ДДС, взаимодействующих с системой-112 города Москвы, с использованием
современных технологий ИИ.
    Система должна решать следующие задачи:
    • обучение операторов работе с программным обеспечением системы-112;
    • отработка навыков обработки различных происшествий и чрезвычайных ситуаций;
    • контроль качества подготовки специалистов через автоматизированную оценку
    • моделирование ситуаций с использованием эмуляции вызовов;
    • управление учебным процессом с возможностью распределения заданий по уровням
сложности;
    • анализ эффективности обучения на основе машинного обучения.
    Сервис должен быть предназначен для обучения операторов различных городских
служб, включая:
    • специалистов ГБУ «Гормост»;
    • работников жилищных служб;
    • операторов других ДДС, взаимодействующих с системой-112;
    • преподавателей и инструкторов учебных центров;
    • руководителей диспетчерских служб.
    Сервис должен использоваться для:
    • базового обучения новых сотрудников;
    • периодической переподготовки действующих операторов;
    • аттестационных мероприятий;
    • контроля знаний и практических навыков;
    • отработки нестандартных ситуаций в безопасной среде;
    • мониторинга эффективности учебного процесса.
    Результатом использования сервиса станет:
    • стандартизация процесса подготовки операторов;
    • повышение качества обучения персонала;
    • сокращение времени адаптации новых сотрудников;
    • объективная оценка компетенций специалистов;
    • создание единой системы подготовки операторов ДДС.

    Сервис должен обеспечивать:
     • реалистичную имитацию рабочих процессов и интерфейса системы-112 без доступа
к внешним сетям (локальный контур);
     • автоматизированный контроль соблюдения временных нормативов и действий
обучающихся, в том числе при ручном вводе информации (сравнение с эталоном);
     • снижение нагрузки на преподавательский состав за счет автоматизации генерации
сценариев и первичной оценки действий обучающихся;
    • защиту данных пользователей и учебных материалов;
    • масштабируемость под различные группы пользователей;
    • возможность удаленного контроля учебного процесса.
    3. Постановка задачи
    Сервис должен позволить:
    • автоматизировать процесс подготовки операторов ДДС;
     • моделировать реальные ситуации с использованием эмуляции вызовов в изолированном
контуре;
     • контролировать качество обучения через автоматизированную систему оценки
(на базе ИИ);
    • анализировать эффективность подготовки на основе машинного обучения;
    • вести учет результатов обучения и прогресса операторов.
    Необходимо, чтобы сервис решал следующие задачи:
    • обеспечение обучения операторов работе с эмулятором ПО системы-112;
    • отработка практических навыков обработки происшествий и ЧС;
    • контроль выполнения рабочих функций операторов (соблюдение тайминга и регламента);
     • оценка уровня подготовки специалистов, в том числе на основе анализа ручного ввода
текста;
    • формирование отчетности по результатам обучения;
    • управление учебным процессом с распределением заданий по уровням сложности.
    Требования к сервису
    1. Реализовать эмуляцию рабочих процессов оператора 112 в локальном учебном
комплексе.
     2. Обеспечить имитацию     входящих   вызовов   (через     виртуальную   IP-телефонию
или текстовые сообщения).
    3. Предоставить инструменты управления обучением для преподавателя.
    4. Внедрить систему оценки действий операторов на основе нейросетевого анализа.

     5. Поддерживать работу с различными уровнями сложности заданий.
     6. Имитировать функционал и интерфейс системы-112 в изолированном контуре без доступа
к внешним сетям.
     4. Границы решения
     Сервис НЕ должен:
     • обрабатывать реальные экстренные вызовы;
     • содержать функционал основной системы-112 (только имитация);
     • работать с конфиденциальной информацией вне учебного процесса;
     • выполнять функции реального диспетчерского центра.
     Сервис обязан обеспечить:
     • защиту данных пользователей и учебных материалов;
     • соответствие требованиям информационной безопасности;
     • масштабируемость под различные группы пользователей;
     • совместимость с аппаратным обеспечением учебного центра;
     • работоспособность на заданных программно-аппаратных платформах;
     • ведение учета всех действий пользователей;
     • формирование детальной отчетности по результатам обучения;
     • поддержку удаленного контроля учебного процесса.
     5. Общие требования к сервису
     Сервис должен обеспечивать:
     • эмуляцию работы оператора системы-112 в режиме реального времени;
     • обработку вызовов через виртуальную IP-телефонию (VoIP);
     • систему управления учебным процессом с распределением заданий;
     • контроль действий обучаемых операторов (тайминг, регламент);
     • оценку эффективности обучения на основе машинного обучения (ИИ);
     • ведение статистики по результатам обучения.
     Необходимо реализовать:
     • многоуровневую систему аутентификации пользователей;
     • разграничение доступа к данным по ролям;
     • защиту каналов передачи данных;
     • резервное копирование данных с периодичностью не реже 1 раза в сутки.

     Система должна интегрироваться:
    • с форматами данных и визуальными стандартами ГБУ «Система 112» (для обеспечения
реалистичности обучения);
     • с локальной системой управления доступом (для администрирования учетных записей

     • с локальными средствами мониторинга работоспособности (для отслеживания

     6. Опциональные требования к сервису
     Все обязательные функции должны быть реализованы в полном объеме. Опциональные
модули могут быть добавлены по желанию команды при условии сохранения изолированности
контура.
     Рекомендуется реализовать:
     • дополнительные модули аналитики — расширенная визуализация эффективности
обучения (графики, тепловые карты ошибок);
     • экспорт отчетности — возможность выгрузки отчетов в стандартные форматы (Excel, PDF)
для последующего использования во внешних системах;
     • механизм импорта обновлений — инструмент для пакетного обновления учебных
материалов и сценариев (в ручном режиме);
     • адаптивный веб-интерфейс — поддержка работы с мобильных устройств (в рамках
локальной сети учебного центра);
     • внутренний API — архитектурное решение для расширения функционала системы
собственными модулями (без взаимодействия с внешними системами).
     7. Требования к производительности
     Система должна обеспечивать (в рамках локальной сети):
     • время отклика интерфейса не более 2 секунд при нагрузке до 100 пользователей;
     • пропускную способность не менее 20 одновременных сессий (вызовов/карточек);
     • задержку при передаче голоса (VoIP) не более 150 мс;
     • работоспособность при кратковременных сбоях сети (до 30 секунд) с автоматическим
восстановлением сессий без потери данных.
     Обработка данных
     • Скорость записи данных в БД не менее 100 операций в секунду.
     • Время формирования аналитических отчетов не более 30 секунд.
     • Буферизация данных при временных сбоях для предотвращения потери информации.
     Масштабируемость
     • Поддержка вертикального масштабирования (увеличение ресурсов сервера).

     • Возможность горизонтального масштабирования (добавление узлов в локальный
кластер) при росте нагрузки.
    Минимальные требования к рабочему месту обучающегося (АРМ)
    • Процессор: Intel Core i5 или аналогичный.
    • Оперативная память: от 16 ГБ.
    • Накопитель: SSD от 256 ГБ.
    • Сетевая карта: поддержка Gigabit Ethernet.
    • Периферия: Гарнитура с поддержкой VoIP (программная эмуляция IP-телефона).
    • IP-телефон с гарнитурой и поддержкой VoIP.
    Минимальные требования к серверу (для работы ИИ-модуля)
    • Процессор: Intel Core i7 / Xeon (или аналог) от 6 ядер.
    • Оперативная память: от 32 ГБ.
    • Накопитель: NVMe SSD от 512 ГБ.
    8. Пользовательские требования
    Интерфейс системы должен обеспечивать:
    • интуитивную понятность для всех категорий пользователей;
    • единую стилистику оформления всех компонентов;
    • адаптивность под различные устройства;
    • локализацию на русском языке.
    Роль: Администратор системы
     Система должна обеспечивать администратору полный контроль над техническим
состоянием и конфигурацией локального учебного комплекса. Для управления системой
администратор должен иметь возможность:
    • запускать и останавливать сервисы системы;
    • контролировать состояние всех компонентов в реальном времени;
    • настраивать параметры производительности системы;
    • выполнять обновление программного обеспечения (пакетное обновление);
    • проводить резервное копирование данных.
    Для управления пользователями администратор должен иметь возможность:
    • создавать учетные записи пользователей всех категорий;
    • назначать роли и права доступа;
    • блокировать/разблокировать учетные записи;

    • настраивать параметры работы виртуальной IP-телефонии;
    • конфигурировать взаимодействие с локальной базой данных;
    • управлять настройками безопасности и политиками доступа;
    • настраивать параметры резервного копирования;
    • конфигурировать параметры журналирования (логов).

возможность:
    • просматривать системные журналы;
    • анализировать статистику использования системы;
    • формировать отчеты об ошибках и сбоях;
    • отслеживать нагрузку на сервер;
    • контролировать показатели работоспособности системы.
    Для выполнения функций безопасности администратор должен иметь возможность:
    • управлять политиками безопасности и правилами доступа к данным;
    • контролировать целостность системы;
    • вести аудит безопасности (логирование действий пользователей).
    Система должна ограничивать администратора в:
     • прямом вмешательстве в учебный процесс (администратор не может менять оценки

    • удалении критически важных данных без процедуры резервного копирования;
    • модификации базовых настроек безопасности без соответствующих прав;
    • доступе к персональным данным пользователей без необходимости (соблюдение
принципа минимальных привилегий).
    Роль: Преподаватель
    Система должна обеспечивать преподавателю полный контроль над учебным процессом,
включая управление ИИ-модулем и оценку действий обучающихся.

сгенерированные нейросетью;
    • назначать учащимся конкретные задания и группы;
    • контролировать выполнение учебных задач в режиме реального времени;
    • отслеживать прогресс обучения и историю успеваемости.

    9. Нефункциональные требования

    • Резервное копирование данных с периодичностью не реже 1 раза в сутки.

    • Аудит всех действий пользователей.
