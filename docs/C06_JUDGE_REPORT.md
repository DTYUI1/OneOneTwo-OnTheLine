## Реальный локальный вызов (второй ПК)

- Модель: `unsloth/Qwen3-4B-Instruct-2507-GGUF`, файл `Qwen3-4B-Instruct-2507-Q4_K_M.gguf`
  (2 497 281 120 байт, лицензия Apache-2.0), в Git не входит (`models/` игнорируется).
- Сервер: образ `ghcr.io/ggml-org/llama.cpp:server@sha256:9dc0a0f4…` с локальным тегом
  `arm112-llm:0.1.0`, CPU, `--threads 4 --ctx-size 4096 --n-gpu-layers 0`, 8 ядер / 7 ГБ ОЗУ.
- Три ключевых факта: адрес «улица Грина, д. 11», «пожар: балкон», решение «принята, силы направлены».

| Комментарий обучаемого | Время | Полнота | Понятность | Итог слоя |

| «Принята. Пожар балкона и двух окон на 13-м этаже… улица Грина, д. 11. Направлено подразделение.» | 15,9 с | 1,00 | 1,00 | все факты найдены |

Первый прогон до страховки: в тексте инъекции модель отметила «Происшествие» найденным
(ложное срабатывание 4B-модели). Добавлена детерминированная проверка: найденный факт должен
иметь общую основу слова с текстом, для адреса — и номер дома; иначе факт отсутствует.

## Границы

- Время ~16–27 с на комментарий: оценка идёт в worker после terminal-события (FR-4.7 допускает
  батч после занятия); по таймауту 120 с оценка остаётся partial по правилам.
- Судья оценивает только комментарий; адрес по доступному основанию, грамотность и сведения
  бригады — V-02 (слои address/grammar/information в разборе остаются unavailable).
- Замер выполнен скриптом в scratchpad через `LocalLlamaJudge`, а не через полный путь
  worker → БД; путь worker проверен тестами с подставным судьёй (`test_c06_judge.py`).
