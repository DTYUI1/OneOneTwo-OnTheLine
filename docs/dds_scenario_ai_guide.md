# Сценарии ДДС для генератора: что делает система и что ждёт от сценария

Для команды ИИ-генерации сценариев (HQ-001) и её агентов. Документ отвечает на два вопроса:
что движок тренажёра уже делает сам, чтобы генератор этого не писал, и по каким правилам
файл сценария принимается в каталог. Формат и пошаговое добавление сценария руками —
`data/scenarios/README.md`, события и ветки — `contracts/scenario-events.md`, эталон игрового
процесса — `docs/dds_gameplay.md`, решения пользователя — `docs/decisions.md`.

Состояние на 17.10.2026, ветка `feature/dds-gameplay`.

## 1. Что генерирует генератор

Один файл `data/scenarios/<код>.json` — один сценарий одной службы и одного уровня
(`contracts/scenario-file.schema.json`):

- **карточка** (`card`) — что видит диспетчер: адрес, класс происшествия, описание,
  пострадавшие, заявитель;
- **эталон** (`reference`) — ход статусов, адрес, ожидаемый звонок, комментарий;
- **бригады** и **план докладов** (`plan`) — доклады бригады до завершающего статуса:
  каждый ждёт статуса диспетчера (`requires_state`) и разрешает следующий (`justifies_state`);
- **события** (`events`) — то, что ломает ровный ход: уточнение (`clarify`), просьба о
  другой службе (`request_service`), повтор адреса с ошибкой (`readback_error`), молчание
  (`silence`), тревога (`alarm`); у события — ветки исхода `met` / `late` / `missed` /
  `wrong` с репликой бригады и последствиями (`delay`, `replace` доклада плана);
- **варианты частей** (`input_parts`) — ввод без микрофона, по шагу на часть;
- **исход** (`outcome`) — «Что было дальше» в разборе.

Код при добавлении сценария не меняется: сценарий — данные.

## 2. Реплики — только из банка озвученных фраз

Все голоса тренажёра — записи ElevenLabs (`data/voices/bank-v*`), синтетического голоса нет
(`docs/decisions.md`, «Голос: только записи банка»). Поэтому генератор **не пишет реплики**, а
выбирает их из банка: `scripts/voices/bank/phrases/<служба>.json` — книга службы, у фразы
`slot` (место в разговоре: `arrived`, `working`, `completed`, `clarify_ok`, `request_service`,
`readback_trap`…) и `incidents` (к каким происшествиям подходит, `*` — к любым). Текст
копируется дословно; `audio` — путь записи в `data/voices`.

Если нужной фразы нет — генератор её не придумывает: оставляет место и называет, что нужно
(служба, место, смысл). Фразу допишут в книгу и озвучат локально (ключ синтеза — только у
владельца банка). Правила связности фраз (факты не спорят с карточкой, одна фраза — один раз на
сценарий, в том числе в разных ветках) — `contracts/scenario-events.md`, «Реплики — из банка».

У каждого абонента — один голос: бригада говорит голосом своей службы, дежурные 101–104 —
своим персонажем. Дежурные отвечают официально: служба, должность, фамилия, «слушаю».

## 3. Что движок делает сам — генератору писать не нужно

- **Повтор адреса вводной.** Бригада повторяет адрес, который услышала, фразой «Повторяю: …»
  (записанной заранее для адресов сценариев). «Выезжаем» говорит доклад о выезде, не повтор.
  Генератор задаёт адрес в карточке; ловушку «повтор с ошибкой» — событием `readback_error`.
- **Неверный адрес во вводной.** Бригада едет туда, что услышала, и докладывает о прибытии
  позже фразой «по тому адресу никто не вызывал… переехали» — подмену делает движок.
- **Просьба о службе, которую уже вызвали.** Ветки `already` («уже вызвал, едут») и
  `surprise` (служба приехала, бригаде не сказали: «могли бы и сказать») и варианты ответа
  достраивает загрузчик (`apps/api/app/seed/service_defaults.py`), если их нет в файле.
  О вызванной службе бригаде сообщает диспетчер (перезвоном или вернувшись с удержания), бригада
  отвечает «Понял, ждём …» и сама ради «Понял» не перезванивает — движок доделывается (HQ-055).
- **Вызванная служба едет.** Доклад, который держит просьба о службе, приходит не раньше чем
  через 20 с после звонка диспетчера в службу (`SERVICE_ARRIVAL`), а не в момент звонка.
- **Сроки ответа.** На вопрос бригады (`clarify`) и на повтор с ошибкой срок отсчитывается от
  того, как диспетчер реплику услышал (бригада могла перезванивать), а не от срабатывания.
- **Пауза между докладами.** Обучаемый не ждёт доклада дольше 40 с: задержку ветки сервер
  обрезает сам; срок события — данные, он должен укладываться в бюджет
  (`after_s + within_s ≤ 40`, проверка `apps/api/tests/test_report_wait_budget.py`).
- **«Как приняли?»** бригада спрашивает только после доклада плана — не после своего вопроса и
  не после ответа на реакцию диспетчера (`DeliveredMessage.answer`).
- **Доклад в службу.** Части памятки ДДС, с. 32: кто вы, адрес и повод, карточка, что
  изменилось. Карточку называют только в звонке в 112. Если бригада попросила службу,
  обстановка, ради которой звонят («горит квартира» в 101), засчитывается и поводом, и «что
  изменилось» (`evalcore.report.SERVICE_NEEDS`). Доклад складывается за звонок, служба
  переспрашивает по одной недостающей части.
- **Адрес голосом.** «Люблинская, сто» — Люблинская улица, если другой тип не назван;
  бульвар, переулок, шоссе называют (у них часто есть тёзки).
- **Отдел контроля** звонит, если у карточки долго нет «Принята»/«Не принята» (`control_call`).

## 4. Правила, по которым файл принимается сейчас

Проверки — в загрузчике (`app.seed.scenarios`: файл с ошибкой не загружается, причина в
журнале seed) и в тестах:

```bash
uv run --package arm112-scripts python scripts/validate_contracts.py
uv run pytest -q -n auto apps/api/tests/test_scenario_files.py \
  apps/api/tests/test_scenario_phrases.py apps/api/tests/test_report_wait_budget.py
```

- схема `contracts/scenario-file.schema.json`; известная служба и класс происшествия;
- план доходит до завершающего статуса эталона: на каждый статус «Прибытие», «Проведение
  работ», «Работы завершены», «Отказ…» — доклад бригады;
- звонок своей службе не обязателен (диспетчер ДДС работает с бригадами);
- реплики — фразы банка своей службы, каждая один раз; факты не спорят с карточкой;
- бюджет ожидания 40 с;
- событие сразу после доклада о выезде говорит «из дороги»: в его реплике и ответе `met` нет
  «поднимаемся», «заходим», «вижу», «внутри», «прибыли»;
- изменили файл — новая `version` (выданные планы неизменны).

## 5. Прогон связности и линтер

Чтобы не чинить сценарии по одному, а ловить классы ошибок автоматически. Подробно —
`docs/coherence_night.md`.

- **Линтер** (`app/seed/scenario_lint.py`) — в загрузке: ломаный файл не попадает в каталог,
  причина в журнале seed. Работает без БД.
- **Прогон с расшифровкой** (`apps/api/app/tools/coherence/`). Каждый сценарий проходится через
  настоящий движок: по эталону, по каждой ветке каждого события и по типовым отклонениям
  диспетчера (медленно отвечает, не берёт трубку, кладёт трубку после доклада, отвечает не то,
  ставит статус сразу). Часы виртуальные и прыгают к следующему событию, проходы идут
  параллельно. Результат — отчёт: сводка нарушений по классам и расшифровка каждого прохода с
  нарушением, как в окне телефона (время, кто говорит, откуда реплика, действия диспетчера).
- **Инварианты связности** — правила, которые не нарушаются ни в одной ветке, например:
  `stage_regress` (реплика не спорит с этапом: выехали — не «выезжаем», в пути — не
  «поднимаемся»), `answer_after_target` (ответ ветки не звучит после доклада, который событие
  держит), `talks_over_question`, `duplicate_meaning`, `service_presence` (служба на месте только
  после вызова и не раньше, чем доехала), `called_service_ignored`, `callback_without_news`,
  `not_closed`, `report_wait`. Полный каталог — в начале каждого отчёта.

```bash
cd apps/api
COHERENCE_DATABASE_URL=postgresql+asyncpg://t:t@127.0.0.1:55471/t \
  uv run python -m app.tools.coherence --only <код> --out tmp/coherence/report.md
```

Нужен PostgreSQL с правом `CREATE DATABASE`. Код выхода 1 — есть нарушения. `--only` — свои
сценарии; весь каталог (37 сценариев, 681 проход) — около 5 минут.

Как этим пользоваться генератору: сгенерировал файл → линтер → прогон `--only` своего кода →
нарушения из отчёта возвращаются генератору обратной связью (класс, ветка, реплика, время) →
исправленный файл. Расшифровка удобна и для ИИ-критика: она читается как живой звонок.
Нарушение класса, которое повторяется во многих сценариях, — повод чинить движок, а не файл.

## 6. Чего генератор делать не должен

- писать реплики своими словами или озвучивать их;
- править чужие сценарии ради своего (общие правила — в движке);
- придумывать ветки `already`/`surprise` и повтор адреса — их строит движок;
- ставить звонок своей службе обязательным;
- писать в исходе (`outcome`) факты, которых нет в карточке и репликах сценария.
