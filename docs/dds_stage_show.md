## Подготовка (до показа, 5–10 минут)

1. Стенд со свежей базой — скрипт подготовки рассчитан на один запуск:

   ```
   scripts/stand/down.sh --project ИМЯ --reset --yes
   scripts/stand/up.sh --project ИМЯ --ports HTTP:HTTPS --stt local
   ```

   `--stt local` — для доклада голосом (шаг 3); без него доклад делается вариантами, остальное
   не меняется. Шаг 4 со вводной — только если в стенде есть #94; без него шаг 4 идёт без вводной.

2. Занятия для показа:

   ```
   python scripts/demo/dds_stage_show.py --base-url https://127.0.0.1:ПОРТ_HTTPS
   ```

   Скрипт (около 30 с) готовит два занятия от `teacher`:
   - «Показ ДДС — готовый результат» — trainee05 уже прошёл «Задымление в квартире» за Мосгаз
     (70005131), занятие завершено, оценка готова (шаг 6);
   - «Показ ДДС» — черновик на три места, начинается на показе (шаг 1):
     АРМ 1 — trainee01, служба 102, ДТП 10000001; АРМ 2 — trainee02, 101, карточка оператора-бота
     10271704; АРМ 3 — trainee03, 101, «Задымление в квартире» 70005101.

   Адрес — `127.0.0.1`, не `localhost` (см. справку скрипта). Если у кого-то из trainee01…05 уже
   идёт занятие, скрипт остановится и назовёт его: завершите его в кабинете преподавателя.

3. Окна браузера — по одному на роль, чтобы входы не вытесняли друг друга: обычное окно Chrome —
   `teacher`; окно инкогнито Chrome — trainee01, потом trainee02; обычное окно Firefox — trainee03;
   приватное окно Firefox — trainee04, потом trainee05. Пароль — `demo-local` (или из `stand.env`).
   Учётную запись в одном окне сменять кнопкой «Выйти». Звук включить: реплики бригады озвучены.

## Что не успели (на 15.10)

- **Макет B** (DT-15…DT-20, brikkerdev): связь службы колонкой справа от АРМ, голос с бригадой,
  зона «Тренажёр». Собран в `integration/dds-b`, в `dev` не влит, с `dev` после #93 конфликтует
  в 21 файле. На показе — интерфейс `dev`.
- **Вводные** (#94 не влит): подаётся только «Тревога бригады». Повторный звонок, дубль карточки,
  «служба не отвечает» — новые виды событий.
- **Тревога без ответа не даёт критической ошибки** — неотвеченная тревога засчитывается «ответили,
  позже срока», когда реплика приходит в звонке за докладом (`docs/dds_stage_check.md` §6, дефект 6).
- **«Что было дальше» не знает о событиях бригады**: исход «передали скорой» и тогда, когда скорую
  не вызывали.
- **Связка 112 → ДДС**: у диспетчера в разборе не видно, что карточка от оператора-бота и какие
  ошибки сделал оператор (#79); живой пары оператор + диспетчер нет; один сюжет, служба 101.
- **События живой бригады** — только у 101 («Задымление в квартире»).
- **Голос**: проверка капитаном на обычном ноутбуке без GPU не проведена; сервер верит браузеру,
  каким способом сделан доклад (замечание ревью #78).
- **Разминка** у преподавателя — только через API, экрана результатов нет.
- Визуальная приёмка «Оператора 112».
