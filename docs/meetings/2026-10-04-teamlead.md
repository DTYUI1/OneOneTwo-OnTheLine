# Встреча с тимлидом, вс 04.10: что решаем

Повестка дня 3 по доске: #65 (выбор основы), #66 (связка со 112), общий формат событий для

Рядом с каждым вопросом — предложение. Где предложения нет, решают люди.

## 1. Основа (#65)

- Макеты B и C отброшены: перекраска A без исследования. Основа — прототип A, дорабатываем
  по моментам процесса из исследования.
- Уже решено 04.10 (`docs/decisions.md`): выбор бригады за диспетчером; субтитры доклада
  всегда; подсказка только когда обучаемый застрял.
- **Решить:** что проверяем в комментарии. По памятке ДДС: причину у «Не принята» и «Отказ»,
  новое с места по ходу работ, итог перед закрытием. В A сейчас — пересказ карточки при
  «Принята».
- **Решить:** схема доклада. В `docs/decisions.md` варианты строятся по «где — что — люди —
  опасности — силы», но эту схему придумали мы. В памятке ДДС (с. 32) есть официальный
  порядок звонка в 112. Предложение: брать его.

## 2. Связка 112 → ДДС (#66, шаг 1 — оператор-бот)

Что выяснилось. Сборка карточки ДДС из попытки оператора уже есть (`_card_for_dispatch`).
Шаг 1 — это seed обычных сценариев ДДС, без новых таблиц и API. Сюжеты оператора (4) и
тренировки ДДС (7) — разные происшествия, поэтому к сюжетам оператора нужно дописать доклады
бригад: 11 пар «сюжет — служба».

| # | Вопрос | Предложение |
| --- | --- | --- |
| 1 | Источник для шага 1 | Готовая запись оператора в `data/link112/records/` поверх сценария оператора; попытка обучаемого — источник шага 2 |
| 2 | Сколько сюжетов к демо | Один: пожар, на нём ловушка Дубнинская/Дубининская; остальные три — если успеем |

| 5 | Карточка пришла не в ту службу: «принять», «не принята» или «перенаправить» | Решить по памятке ДДС |

Принцип, который черновик закладывает: диспетчер работает с карточкой такой, как её заполнил
оператор, бригада живёт по правде сюжета. Диспетчер оценивается по тому, что мог знать;
ошибки оператора видны в разборе обоих и на балл диспетчера не влияют.

## 4. Адрес: решение 04.10 расходится с тренажёром

Решение 04.10 (`docs/decisions.md`, ветка `docs/decisions-0410`): диспетчер ДДС адрес не
вводит. На скриншотах `arm_dds` адрес у ДДС только для чтения, уточнённый адрес по памятке
(с. 16) пишется в комментарий. В тренажёре же есть ручной ввод адреса обучаемым
(`apps/web/src/arm/AddressInput.tsx`, D-03). Его основание — ответ капитана от 24.09: «Адрес
они просто указывают, но могут ошибиться при наборе» (`docs/CUSTOMER_QUESTIONS_2026-09-24.md`).

**Решить:** кто «они» в этом ответе. Если операторы 112 — убираем ввод адреса у ДДС. Если
диспетчеры ДДС — пересматриваем решение 04.10.
