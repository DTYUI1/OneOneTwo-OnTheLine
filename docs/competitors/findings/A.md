### Fosh1er/MCHS_hack_AIskra — https://github.com/Fosh1er/MCHS_hack_AIskra

- **Суть:** копии АРМ-112 и АРМ ДДС; ИИ генерирует сценарий вместе с эталоном (легенда и эталонная карточка строятся из одних признаков); детерминированная взвешенная автооценка по эталону; ИИ — только «судья смысла» и актёры. Сквозное смешанное занятие: оператор 112 заполняет карточку → она падает в очередь ДДС одногруппника.
- **Интересное для нас:**
  - **Автооценка ДДС — готовая рубрика**, очень близкая к нашему скоупу: решение (вес 3, критическое), время реакции (2; 1 в нормативе, линейно до 0 к 3×нормативу, позже 3× — критическое), порядок и полнота цепочки статусов (2; не по порядку ×0,7), номер наряда при «Принята» (1), доля статусов с комментарием (1), звонок старшему группы (1), грамотность ИИ (0,5). Критическая ошибка режет балл ниже порога 70. Каждый критерий несёт текст ошибки для обучаемого. `backend/src/aiskra/modules/assessment/domain/scoring.py` (`assess_dds`, `WEIGHTS_DDS`, `finish`).
  - **Бенчмарк мутаций для доказательства достоверности оценки:** из эталона строится идеальная попытка, затем копии с одной типовой ошибкой («Не принята» вместо «Принята», решение позже 3 нормативов, нет номера наряда, статусы без комментариев, нет звонка старшему); меряют чувствительность, специфичность, локализацию (снизился только нужный критерий), согласие вердикта и κ Коэна; плюс MAE с экспертными правками преподавателя. Отчёт генерируется утилитой. `backend/src/aiskra/modules/assessment/domain/validation.py`, `docs/validation/Достоверность_автооценки.md`, `backend/tools/validate_ai.py`. Прямо закрывает вопрос жюри «а почему верить вашей оценке».

  - **Нормативная база с цитатами:** 75 с на карточку — ПП РФ № 1931 п. 9 «р»; форма 1/112 (приказ МЧС № 192: доля в нормативе, медиана, p90); профстандарт 12.002; ГОСТ Р 22.7.01 для разбора смены. `docs/research/Подготовка_персонала_112_и_ЕДДС.md` — готовые ссылки для нашей записки.
  - **Психологический модификатор заявителя:** состояние держит детерминированный движок, а не LLM — уровень по шкале ECCS IAED 1–5, доверие, «ворота» (какие факты легенды заявитель выдаёт на каком уровне); запрещённое действие оператора («Успокойтесь!») поднимает уровень сразу, снижение — только серией правильных (асимметрия). Оценка воспроизводима при одном seed. 15 профилей. `backend/src/aiskra/modules/training/domain/psy.py`, `psy_acts.py`, `data/dictionaries/psy_profiles.yaml`, `docs/research/psychology/`.
  - **Софтфон ДДС по мотивам РТУ Т16Р:** DSS-клавиши абонентов (старший группы, заявитель, смежные службы карточки), журнал звонков по карточке; **старший группы сам перезванивает с докладом через 12 с после смены статуса** и отвечает строго по текущему статусу («не опережай события»). `frontend/src/pages/dds/DdsSoftphone.tsx`, `backend/src/aiskra/ai/prompts/brigade_actor/v1.md`, `service_actor/v1.md`.

## Топ-находки группы

1. **Доказать достоверность автооценки бенчмарком мутаций:** из эталона строится идеальная попытка, в копии вносится по одной типовой ошибке ДДС, меряются чувствительность / специфичность / локализация / κ Коэна, отчёт генерируется утилитой — Fosh1er/MCHS_hack_AIskra (`assessment/domain/validation.py`).
2. **Статус засчитывается, только если поставлен по факту доклада старшего бригады** («статус раньше доклада» = «угадал»); бригада идёт по скрытой шкале этапов, сама звонит с задержкой, проактивный звонок даёт знание раньше — Den4ikAI/arm112-trainer_final (`domain/brigade.rs`), bukhanka/trainer-112-dds (`src/lib/dds/crew.ts`).
3. **Эталон ДДС на каждую службу карточки с `commentMustHave` и `traps`**, плюс сценарии «ошибка в карточке 112» (бригада на месте называет расхождение, диспетчер обязан позвонить в 112) и «чужая территория → верный мотивированный отказ, кому передано» — bukhanka/trainer-112-dds (`data/scenarios.json`, `data/scenarios-card-errors.json`).
4. **Звонок «вышестоящему начальнику» как второй голосовой собеседник ДДС** (по ответу заказчика в чате 27.09, сообщение 781, — обязателен вместе с бригадой): доложенное отмечается только по дословной цитате, проверенной кодом; вопросы начальника не подсказывают ответ — Den4ikAI/arm112-trainer_final (`domain/chief.rs`, `CHAT-FINDINGS.md`).
5. **Прогноз и рекомендации, которые фиксируются до факта и потом сверяются** с базовой линией, — закрывают пункты финальной экспертизы «проверка прогнозирования/рекомендаций», которые обычно пустуют; Эло отдельно для 112 и ДДС как прозрачная адаптивность — Den4ikAI/arm112-trainer_final (`forecast.rs`, `advice.rs`), bukhanka/trainer-112-dds (`docs/methods.md` §6).
6. **Телефонный тракт и русское произношение для TTS без нейросети:** полоса 300–3400 Гц + μ-law для голосов «по телефону» (ELABS, `voice/server.py`); телефоны группами, раскрытие сокращений адреса и аббревиатур служб, контекстные ударения (Any1Key/ARM-112-Enterprice, `services/voice-silero/`).
