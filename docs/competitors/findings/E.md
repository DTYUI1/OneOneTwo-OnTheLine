### Stan-Mazaev/sim112-trainer — https://github.com/Stan-Mazaev/sim112-trainer
- **Команда:** Playful Universe Studio (не финалист) · **создан / последний коммит:** 26.09 / 27.09 · **коммитов:** 9 · **стек:** FastAPI, SQLite (не используется, всё в памяти), vanilla JS, faster-whisper, pyttsx3/SAPI5, reportlab
- **Скоуп:** оператор 112 (README говорит «ДДС», по факту приём вызова от заявителя) · **зрелость:** прототип, но продуманный; статическое демо на GitHub Pages
- **Суть:** заявитель — детерминированная стейт-машина на 4 шкалах (паника/доверие/комплаенс/кооперация), LLM не подключена, ответы шаблонные. Оценка = 100 − Σ весов 15 типов нарушений, PDF-отчёт со сравнением с эталоном.
- **Интересное для нас:**
  - Таблица дельт «действие курсанта → изменение шкал заявителя» (успокоение −10 паники, хамство +15 паники −15 доверия, молчание +8 паники) и фазы shock → panic → coordination → resolution по порогам: [app/sim112/caller/state.py](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/app/sim112/caller/state.py). Принцип: «что происходит — решает стейт-машина, LLM только озвучивает» — воспроизводимость оценки. Годится нам для поведения должностного лица в IP-телефонии.
  - Скрытые факты заявителя (`hidden_facts`) раскрываются только на релевантный вопрос — то же можно для должностного лица ДДС: [app/sim112/scenarios/tickets/ticket_20.json](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/app/sim112/scenarios/tickets/ticket_20.json).
  - Голос заявителя зависит от паники: rate/volume TTS по 4 уровням, кэш синтеза по md5(text|rate|volume): [app/sim112/voice/tts.py](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/app/sim112/voice/tts.py).
  - Матрица триггеров «фраза заявителя → служба → норматив в секундах» (не дышит → скорая за 10 с, пожар/газ → 15 с), нарушения LATE_ACTIVATION / MISSED_ACTIVATION: [app/sim112/audit/triggers.py](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/app/sim112/audit/triggers.py). Аналог наших 30 с, но привязан к моменту, когда прозвучал факт.
  - Метрика Airtime Control — доля речи диспетчера (норматив 30–60 %) с текстовым советом; нарушения INTERRUPTED_CALLER, NO_GROUNDING_FIRST_30S, UNPROFESSIONAL_TONE по regex: [app/sim112/audit/metrics.py](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/app/sim112/audit/metrics.py), [violations.py](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/app/sim112/audit/violations.py).
  - PDF-отчёт: шкала оценок (≥90 отлично … <40 провал), таблица «эталон / курсант / OK-X», нарушения с секундой и весом, подпись инструктора: [app/sim112/report/pdf.py](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/app/sim112/report/pdf.py), образец [docs/demo/sample_report.pdf](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/docs/demo/sample_report.pdf).
  - Данные: 24 сценария из «Билеты-задачи по C 112. АГС_ГСИ.pdf» (8 билетов × 3 случая) с эталоном ЕКП, признаками L1–L3 и службами; классификатор свежее нашего — `Классификатор_происшествий_v_046_24_корректировка_МВД_+_Департамент.xlsx` в [docs/](https://github.com/Stan-Mazaev/sim112-trainer/tree/main/docs), парсер [scripts/parse_ekp.py](https://github.com/Stan-Mazaev/sim112-trainer/blob/main/scripts/parse_ekp.py).
  - Демо для жюри без бэкенда: `mock.js` подменяет fetch предзаписанными ответами, всё на GitHub Pages: [docs/demo/](https://github.com/Stan-Mazaev/sim112-trainer/tree/main/docs/demo).
- **Слабые места / чего нет:** TTS только Windows (SAPI5), whisper качается из интернета при первом запуске; нет БД, ролей, назначения заданий; инструктор только смотрит поток событий, не вмешивается.

### fancybear01/sirena-112 — https://github.com/fancybear01/sirena-112
- **Команда:** «Ваш звонок важен для нас» (не финалист; 5 авторов: Artem Malov, Polina Galaktionova, Nikita, Максим, Artem) · **создан / последний коммит:** 15.09 / 29.09 · **коммитов:** 74 · **стек:** React+Mantine, Kotlin Core (Spring, PostgreSQL+Flyway), Go Media Gateway, Python AI (Vosk, Piper, Whisper), Asterisk (SIP/ARI/RTP), Prometheus, Docker Compose, CI на 7 workflow
- **Скоуп:** оператор 112 (карточка + голос), статусы служб ДДС только отображаются · **зрелость:** полноценное решение, самое инженерно зрелое в группе
- **Суть:** «Сирена-112» — микросервисный тренажёр: курсант по опросной карте выбирает признаки, тип и службы вычисляет Core по классификатору; AI-абонент на правилах через реальный SIP; объяснимая оценка по 8 критериям. Всё измерено и задокументировано с цифрами.
- **Интересное для нас:**
  - Замеры моделей на CPU без GPU с выводами: Qwen2.5-1.5B (llama.cpp Q4) по скорости проходит (0,5 с до первого слова), по качеству нет — путает роль («Ваше сообщение принято»); поэтому в живом разговоре правила, LLM только для генерации сценариев с утверждением преподавателем. Vosk для диалога (×0,21 от длительности), Whisper small для пост-расшифровки к оценке. Бюджет паузы 1,2 с разложен по этапам: [docs/ai-benchmark.md](https://github.com/fancybear01/sirena-112/blob/main/docs/ai-benchmark.md). Прямо подтверждает или опровергает наши допущения по локальной LLM.
  - Лицензии TTS: Silero CC BY-NC-SA — нельзя поставлять госзаказчику; piper-tts MIT только до 1.2.0, дальше GPL; голос irina — данные RHVoice с лицензией Unknown, чистые CC0 — denis/dmitri: [docs/voice-shipping-stack.md](https://github.com/fancybear01/sirena-112/blob/main/docs/voice-shipping-stack.md). Стоит сверить с нашим выбором TTS.
  - Ответ абонента собирается только из фактов эталона (выдумать нечем), не больше 2 фактов за реплику, шкалы паника/доверие/терпение, реплики без прошедшего времени первого лица, чтобы не выдать пол: [services/ai/app/engines/rule_dialogue.py](https://github.com/fancybear01/sirena-112/blob/main/services/ai/app/engines/rule_dialogue.py), интенты вопросов — [question_intents.py](https://github.com/fancybear01/sirena-112/blob/main/services/ai/app/engines/question_intents.py).
  - Оценка делит ошибки по источнику: ошибка курсанта снижает балл, неполнота эталона или расхождение версии классификатора — «вопрос к данным», курсанту не вменяется; к каждому критерию — готовая рекомендация; порог зачёта 60, штраф за время 10: [services/ai/app/engines/rule_scoring.py](https://github.com/fancybear01/sirena-112/blob/main/services/ai/app/engines/rule_scoring.py).
  - Разбор текста карточки без нейросети (по начальным формам), с честной валидацией: пороги подбирались на одних темах, мерились на других, macro-F1 0,85 против 0,54 у сравнения «как есть»; вывод о смысле всегда помечен «требует проверки преподавателем»: [docs/ai-text-review.md](https://github.com/fancybear01/sirena-112/blob/main/docs/ai-text-review.md), датасет `services/ai/benchmarks/text_review/dataset.json`.
  - Правка оценки преподавателем не трогает исходный отчёт: append-only журнал `training_feedback` (автор, время, причина, старое/новое), `originalReport.score` + `effectiveScore`; эталон студенту не отдаётся до оценки: [docs/training-history.md](https://github.com/fancybear01/sirena-112/blob/main/docs/training-history.md). Ровно наш кейс «преподаватель переопределяет вердикт ИИ».
  - Сравнение адресов по значимым частям (улица/дом/корпус/подъезд), «д. 21» = «дом 21»: [address_match.py](https://github.com/fancybear01/sirena-112/blob/main/services/ai/app/engines/address_match.py); рекомендации группе, если критерий провален в ≥30 % занятий: [group_advice.py](https://github.com/fancybear01/sirena-112/blob/main/services/ai/app/engines/group_advice.py); аналитика группы (распределение баллов, топ ошибок, по дням): [docs/training-analytics-75.md](https://github.com/fancybear01/sirena-112/blob/main/docs/training-analytics-75.md).
  - Эксплуатация: внешнее учебное табло без ПДн, переподключение WS по `afterEventId` с replay из PostgreSQL, профиль с двумя Core за gateway, бэкап с проверкой восстановления, матрица «требование → доказательство»: [docs/resilience.md](https://github.com/fancybear01/sirena-112/blob/main/docs/resilience.md), [docs/requirements-coverage.md](https://github.com/fancybear01/sirena-112/blob/main/docs/requirements-coverage.md), офлайн-поставка — [docs/offline-full-stack.md](https://github.com/fancybear01/sirena-112/blob/main/docs/offline-full-stack.md).
- **Слабые места / чего нет:** обучаемый — оператор 112, не ДДС; живая LLM в диалоге отвергнута, абонент шаблонный; 4 примера сценариев в `contracts/examples`.
- **Куда смотреть следующему агенту:** `docs/ai-benchmark.md`, `services/ai/app/engines/`, `docs/training-history.md`.

### alex-indi/training-simulator-112 — https://github.com/alex-indi/training-simulator-112

- **Скоуп:** диспетчер ДДС (сквозной сценарий ДДС 101) — **ближе всех к нашему скоупу** · **зрелость:** полноценный MVP, публичный стенд https://112.rzd-learning.ru/
- **Суть:** преподаватель собирает занятие и очередь карточек (общий пул с атомарным захватом или персональная очередь), обучаемый на АРМ ДДС ведёт статусы вручную, виртуальная «учебная бригада 101» шлёт сообщения по таймлайну, оценка = 100 − Σ весов отклонений, преподаватель подтверждает или отклоняет каждое.
- **Интересное для нас:**
  - Учебная бригада 101 шлёт «Выехали / Прибыли / Приступили / Работы завершены» на 15/75/135/195 с; обучаемый обязан сам проставить соответствующий статус за 45 с, иначе SLOW_BRIGADE_REACTION или MISSING_BRIGADE_STATUS (критическое); сообщения статус не меняют: [backend/app/modules/incidents/activity.py](https://github.com/alex-indi/training-simulator-112/blob/main/backend/app/modules/incidents/activity.py).   - Разбор преподавателя поштучно: каждое отклонение CONFIRMED/DISMISSED с обязательной причиной, можно добавить ручное отклонение с весом, финальный балл с комментарием, всё в `AssessmentAudit`; итоговое резюме генерирует LLM (задача ASSESSMENT_SUMMARY) — там же.
  - Вмешательство преподавателя во время занятия: пауза всего занятия или одного обучаемого, ручная отправка карточки, «вводная преподавателя» в карточку (`scenario-events`), заметки по прогону, журнал действий преподавателя: [backend/app/modules/training/control.py](https://github.com/alex-indi/training-simulator-112/blob/main/backend/app/modules/training/control.py).
  - «Зеркало АРМ» для преподавателя — единая лента истории карточки (поступила, открыта, статусы, вводные, сообщения бригады, события служб): [frontend/src/WorkstationMirror.jsx](https://github.com/alex-indi/training-simulator-112/blob/main/frontend/src/WorkstationMirror.jsx), [LiveMonitor.jsx](https://github.com/alex-indi/training-simulator-112/blob/main/frontend/src/LiveMonitor.jsx).
  - Данные: 4638 реальных объектов Москвы из data.mos.ru (1718 детсадов, 1376 школ, 491 поликлиника, 255 больниц, 257 станций метро, 143 подстанции СМП) с отчётом импорта — адреса карточек берутся из них; связка «тег объекта ↔ признак классификатора»: [backend/seed/city_objects/](https://github.com/alex-indi/training-simulator-112/tree/main/backend/seed/city_objects), [backend/seed/incident_classifier/](https://github.com/alex-indi/training-simulator-112/tree/main/backend/seed/incident_classifier) (rules, rule_services, rule_features).
  - LLM пишет только текст карточки, сообщений бригады и резюме, с версионированными промптами (`incident_operator_entry_v7` и т. п.), детерминированным fallback и учётом токенов; факты и оценку не трогает: [backend/app/services/text_generation/renderer.py](https://github.com/alex-indi/training-simulator-112/blob/main/backend/app/services/text_generation/renderer.py).
  - Поставка: portable-архив со встроенным Python и PostgreSQL, запуск одним `Start.cmd`/`Start.command`; Docker-лаунчер сам генерирует пароль БД и грузит демо-данные: [scripts/build_portable.py](https://github.com/alex-indi/training-simulator-112/blob/main/scripts/build_portable.py), [start-demo.ps1](https://github.com/alex-indi/training-simulator-112/blob/main/start-demo.ps1).

## Топ-находки группы

1. **Бригада/служба как внешний источник событий с нормативом реакции.** Сообщения «выехали / прибыли / работают / завершили» по таймлайну, ДДС обязана сама проставить статус за 45 с, иначе нарушение; следующий доклад ждёт регистрации предыдущего (alex-indi/training-simulator-112 `incidents/activity.py`, Ruslikru/DDS112 «Телефон и доклады 0.8.17»).
2. **Готовые критерии оценки звонка ДДС должностному лицу:** «адрес из карточки передан службе», «статус соответствует сообщению службы», «в комментарии отражено сообщение службы» — поиск фраз с защитой от отрицания, сомнение уходит преподавателю; плюс правила памятки M21–26 (норматив от направления, а не от открытия; 103 без «Не принята») (chigakss/112 `docs/domain.md`).
3. **Правка оценки без потери исходной:** append-only журнал правок (автор, причина, старое/новое), `originalReport` + `effectiveScore`; поштучное «подтвердить / отклонить» каждого отклонения с причиной; поздний ответ ИИ не перезаписывает решение преподавателя (fancybear01/sirena-112 `docs/training-history.md`, alex-indi `assessment.py`, Ruslikru `semantic_review.py`).
4. **Замеры LLM на CPU с выводом:** Qwen2.5-1.5B проходит по скорости (0,5 с до первого слова), но путает роль, поэтому в живом диалоге правила, а LLM — генерация сценариев с утверждением; Vosk для диалога, Whisper для пост-расшифровки; лицензии TTS: Silero CC BY-NC-SA не годится для госпоставки, piper-tts MIT только ≤1.2.0, голоса CC0 — denis/dmitri (fancybear01/sirena-112 `docs/ai-benchmark.md`, `docs/voice-shipping-stack.md`).
5. **Предгенерация TTS-реплик при публикации сценария** с привязкой к версии и хешу, блокировка запуска до готовности, перевод цифр в слова перед синтезом, «заполняющие» реплики при задержке ответа > 1,5 с (Ruslikru/DDS112 `docs/Голосовые_сообщения_и_настройки_ИИ_ТЗ.md`).
6. **Объяснимая сложность и адаптивность:** звёзды сложности из фактов сценария с текстом причины, «освоенная сложность» = ≥3 работ со средним ≥80, рекомендуемая на ступень выше, лимит параллельных карточек по уровню; плюс 4638 реальных объектов Москвы из data.mos.ru для адресов (Ruslikru/DDS112 `learning.py`, alex-indi `backend/seed/city_objects/`).
