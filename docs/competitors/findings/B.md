Все 96 вызовов из билетов заказчика переведены в YAML-сценарии с кодом ЕКП, маршрутизацией служб, профилем заявителя и правилами оценки. https://github.com/Andrchest/112-maxxing/tree/main/scenarios/tickets
  - **Оценка — декларативные правила внутри сценария**: `evaluator_type` (WORKFLOW_ACTION, DEADLINE…), события-источники, баллы, штраф, `critical`, категория; норматив 30 с берётся из таймера занятия, так что преподаватель может его переопределить. Звонки ДДС: «Позвонить старшему · <служба>», «заявителю», «в 112». https://github.com/Andrchest/112-maxxing/blob/main/docs/guide/trainee.md

Уверенность меряют **разрывом до второго кандидата**, а не абсолютной оценкой: на их корпусе разрыв 0,08 даёт 1,7 % ложных ответов, абсолютный порог не опускается ниже 6 %. Кандидаты ограничены слотами сценария, поэтому «не знаю» — правильный ответ. https://github.com/tulasu/emergency/blob/master/dialog/core/nlu/cascade.py

Политика — чистая функция, тестируется без моделей. https://github.com/tulasu/emergency/blob/master/dialog/core/dialog/policy.py
  - **Готовые ответы в четырёх стилях на каждый факт**: `plain`, `short` (раздражённо: «Драка здесь, говорю же»), `confirm` («Да, драка»), `correct` (оператор ошибся в предположении — «Нет, это драка, а не…»); у сценария список `critical` фактов; уточнения «в скобках» из билета раскрываются только по прямому вопросу. Все 96 вызовов билетов оформлены так. https://github.com/tulasu/emergency/tree/master/traineebox/cmd/initializer/data/scenarios

## Топ-находки группы

1. **Звонок должностному лицу как слот-машина**: руководитель заранее озвученными репликами переспрашивает недостающее (адрес / что случилось / пострадавшие / меры) и ловит похожую улицу (Дубнинская ↔ Дубининская) просьбой «по буквам»; непонятые фразы ночью размечает локальная LLM, в граф они попадают только после одобрения преподавателя. Ложится прямо на наш TTS-звонок. — DestYchen/dispatcher112-trainer
2. **«Карточка с ошибкой от 112» как отдельный вариант сценария**: истина мира, знания заявителя, ввод оператора и снимок, полученный ДДС, — четыре разных слоя; ДДС получает ошибочный тип или адрес и получает баллы за то, что отметил ошибку; плюс варианты «не наша служба → отказ». — Andrchest/112-maxxing
3. **ИИ-вердикт, который не может навредить**: LLM видит одно поле без эталона и балла, сдвигает его не больше чем на 25 % веса поля, нужны два согласных вердикта, уверенность ≥0,85 и цитаты; спорное остаётся формальным баллом с пометкой; поправки преподавателя копятся в RAG-память и подмешиваются в следующие проверки. — LewFdtnkv/112-system
4. **Пять форматов упражнения и три глубины подсказки**: освоение интерфейса с подсветкой → полная ситуация с помощью → отработка навыка (остальное предзаполнено и не оценивается) → повторение → контроль; подсказка «цель → как действовать → решение», помощь логируется без штрафа. Готовый каркас для наших уровней сложности и обучения интерфейсу. — LewFdtnkv/112-system
5. **Рейтинг Эло «ученик против сценария»** с априорной сложностью и честной проверкой прогноза: дешёвая основа для адаптивности и калибровки сложности сценариев. — DestYchen/dispatcher112-trainer
6. **Готовые данные и мелочи для TTS**: 96 ситуаций из билетов заказчика уже разобраны в JSON с разметкой ловушек (DestYchen; ещё в YAML у Andrchest и JSON с ответами в четырёх стилях у tulasu); подготовка русского текста к TTS — телефоны группами с нулями, номера домов числительными, аббревиатуры по буквам, словарь ударений (yaro-s-lav/hacka); правило заказчика «в 03 уходят только первые 100 символов описания» (Everrain17, источник — «Инструкция по заведению карточки»).
