  - Граф переходов статусов реагирования строго по «Памятке АРМ-112 для ДДС» с обязательными комментариями и исключением для 103 («Работы завершены: Завершение работ без бригады» вместо отказа); фронт рисует список только из `allowedNext` бэкенда — `frontend/src/shared/mocks/reactionTransitions.ts`, `go-core/internal/reaction/reaction.go`.   - Итог оценки `final_score GENERATED ALWAYS AS (COALESCE(override_score, total_score))` + CHECK «override требует автора и причины» + запись в аудит; слои оценки (поля / грамматика / семантика / тайминг) отдельными колонками, AI-слои доезжают асинхронно (`status='partial'`) — `docs/db-design.md` Р9.
  - Тайминг как метки событий (`attempt_events` — источник истины), идемпотентное автосохранение по `client_seq`, очередь AI-задач в PostgreSQL через `SKIP LOCKED`, глобальный TTS-кэш по хэшу содержимого — `docs/db-design.md` Р5–Р7, Р12–Р13.
  - Голосовой режим: push-to-talk, полудуплекс (микрофон закрыт, пока говорит заявитель), stateless ai-service, которому каждый ход присылают историю и **`revealed_fact_ids`** — заявитель не выдаёт факты, о которых не спросили; аудио оператора не хранится, только транскрипт — `docs/voice-mode.md`, `go-core/internal/dialogue/turn.go`.

## Топ-находки группы

1. **Карточки, которые ДДС должна не принять:** подвохи «чужая территория» и «дубликат» с эталоном «Не принята» и обязательным обоснованием (akenjasi/112-simulator-core); очередь со «своими» и «чужими» по профилю карточками, где чужую нельзя брать своей бригадой (qwasxxx/112hack).
2. **Сложность ДДС через дефекты во входящей карточке:** на среднем уровне 112 «теряет» пострадавших, на сложном — телефон заявителя; диспетчер должен заметить и исправить (qwasxxx/112hack, `incoming-card.ts`).
3. **Звонок ДЛ с проверяемым результатом:** собеседник по ступенчатому промпту или правилам не подтверждает заявку без адреса и называет номер наряда, а оценка сверяет записанный номер (qwasxxx/112hack); один раз переспрашивает адрес, если его нет в докладе (N1ck6/112-Helper).
4. **Входящие звонки к диспетчеру ДДС:** доклад старшего группы («прибыли / ведём работы / завершены / требуется другая служба»), который нужно подтвердить и отразить статусом, и перезвон заявителю (N1ck6/112-Helper, `ml/integration/dialogue.py`).
5. **Оценка ДДС как чистая функция:** итоговое решение, норматив **первого** решения, отдельный штраф за «необоснованный отказ» (сначала «Не принята», потом «Принята»), обязательные статусы из версионируемого эталона, override только с автором и причиной (anddr28/112-project, `go-core/internal/dds/dds.go`, `docs/db-design.md`).
6. **Заявитель без LLM в рантайме:** rubert-tiny2 на 10 интентов оператора + заранее сгенерированные реплики и уровень паники 0–100 (повтор вопроса → раздражение) дают мгновенный ответ на CPU (akenjasi/112-simulator-core); сверка карточки с эталоном с раздельным сравнением чисел и LLM-судьёй максимум на 3 поля (akruserg/WhiteCoders, `services/scoring.py`).

Финалисты: у akenjasi/112-simulator-core последний коммит 16.10.2026 — «TAG -- VERSION BEFORE FINALS», почти наверняка финалист, но название команды не найдено. В остальных репо группы названия финалистов нет; WhiteCoders (Сочи) в список финалистов не входит.
