## Сверить с нами в первую очередь

1. **Нормативы прочитаны иначе.** ELABS, bukhanka, Any1Key, System112 и Dema-koder ссылаются на ответ заказчика
   в чате кейса от 27.09 (сообщение 781): 30 с — от появления карточки до её **открытия**, 3 мин — до **первой
   записи** «статус + текст», дальше без норматива. У нас ([PRD](../../requirements/prd.md) §FR-1.4) 30 с — от
   направления до «Принята/Не принята», открытие норматив не закрывает. Чата от 27.09 у нас нет (в `docs/fromTG`
   только Q&A от 16.09); пересказ есть у DanK1-PRO и andrewgein — [C.md](findings/C.md).
2. **Звонок вышестоящему начальнику.** По тому же чату, у ELABS голосовой диалог ДДС обязателен и с бригадой,
   и с начальником (`domain/chief.rs`) — [A.md](findings/A.md).
3. **Доклады бригады входящими звонками.** Шесть команд независимо сделали одно и то же: старший бригады сам
   звонит на каждом этапе («выехали → прибыли → работают → завершили»), статус засчитывается только после доклада,
   поставленный раньше считается угаданным. ELABS, bukhanka, Training112, alex-indi, Ruslikru, N1ck6 —
   [A](findings/A.md), [C](findings/C.md), [D](findings/D.md), [E](findings/E.md).

## Оценка

- **Доказать, что оценка ловит ошибки** (Aiskra, `assessment/domain/validation.py`): идеальная попытка по эталону,
  в копии вносится по одной типовой ошибке ДДС; меряют полноту обнаружения, ложные замечания на верной попытке,
  что снизился только нужный критерий, κ Коэна. Сильный аргумент на питче — [A](findings/A.md).
- **ИИ не может навредить вердикту.** Правила задают нижнюю границу, LLM может только ужесточить (kwik112,
  `enforceLocalSafetyFloor`); LLM сдвигает балл поля максимум на 25 % его веса, нужны два согласных вердикта
  с уверенностью ≥ 0,85 и цитатами (LewFdtnkv) — [F](findings/F.md), [B](findings/B.md).
- **Сбой не превращается в ноль:** статусы критерия «не проверено / нет подтверждения / техническая ошибка»,
  к вердикту приложены события; при старте фиксируются версии сценария, эталона, рубрики и модели — [C](findings/C.md).
- **Правка преподавателя не стирает исходное:** журнал только дописывается (автор, причина, было/стало), поздний
  ответ ИИ не перезаписывает решение преподавателя — [E](findings/E.md), [C](findings/C.md).
- **Дешёвые правила ДДС** (Dema-koder, с весами): штраф за статусы подряд слишком быстро («не читали»), за «Отказ»
  без «Прибытия»; просрочка остаётся, даже если потом всё сделано; сначала отказ, потом принятие — отдельный
  штраф (anddr28) — [C](findings/C.md), [D](findings/D.md).
- **Критерии звонка должностному лицу** (chigakss, `docs/domain.md`): адрес из карточки передан, статус совпадает
  с сообщением службы, сообщение отражено в комментарии; поиск фраз с защитой от отрицания — [E](findings/E.md).
- **Прогноз балла до попытки и сверка с фактом** (ELABS `forecast.rs`, `advice.rs`) закрывает пункт экспертизы
  о проверке прогнозов — [A](findings/A.md).

## Сценарии и сложность

- **Карточки, которые ДДС должна отклонить:** чужая территория, дубликат открытого происшествия, чужой профиль;
  верно — «Не принята» с причиной и кому передано (akenjasi, qwasxxx, bukhanka) — [D](findings/D.md), [A](findings/A.md).
- **Ошибка в карточке от 112:** «пострадавшие: есть» → «нет», стёрт телефон; бригада на месте называет
  расхождение, диспетчер обязан позвонить в 112. Четыре слоя правды хранятся раздельно (Andrchest) —
  [B](findings/B.md), [D](findings/D.md).
- **Ситуация меняется посреди обработки:** доклад с места — больше пострадавших, нужна деблокировка
  (dispecerat112, `maybeEscalateMission`) — [F](findings/F.md).
- **Сложность без LLM:** интенсивность потока карточек и число фоновых чужих карточек в журнале (Dema-koder);
  звёзды сложности с текстовой причиной, «освоено» после трёх работ со средним от 80 (Ruslikru) —
  [C](findings/C.md), [E](findings/E.md).
- **Эло «ученик против сценария»** (DestYchen, bukhanka, 67-420) как прозрачная адаптивность — [B](findings/B.md).
- **Готовые данные:** 96 вызовов из билетов заказчика уже разобраны в JSON/YAML у DestYchen, Andrchest, tulasu,
  N1ck6 (у N1ck6 с разметкой ЕКП). Исходник у нас — `docs/dataset/Датасет/Билеты- задачи по C 112 . АГС_ГСИ.txt`.
  4638 объектов Москвы из data.mos.ru для адресов (alex-indi `backend/seed/city_objects/`).

## Голос и ИИ-собеседник

- **В живом разговоре без LLM.** Классификатор намерений на CPU (E5-small у Training112, rubert-tiny2 у akenjasi)
  + заранее озвученные реплики; LLM только размножает формулировки при подготовке сценария, преподаватель
  утверждает — [C](findings/C.md), [D](findings/D.md).
- **Собеседник по слотам:** руководитель переспрашивает недостающее (адрес, что случилось, пострадавшие, меры),
  похожую улицу просит по буквам; непонятые фразы размечает LLM, в диалог — после одобрения преподавателя
  (DestYchen). Автомат «выслушать → уточнить → повторить понятое → подтвердить» (67-420) — [B](findings/B.md), [C](findings/C.md).
- **Заявитель знает только факты сценария,** на остальное «не знаю»; каждое замечание разбора подкреплено цитатой
  («Игры и теория», `quotes.py`) — [F](findings/F.md).
- **Предгенерация TTS при публикации сценария,** привязка к версии и хешу; если ответ не готов за 1,5 с — заранее
  записанное «сейчас посмотрю» (Ruslikru) — [E](findings/E.md).
- **Русский текст для синтеза:** телефоны группами, номера домов числительными, аббревиатуры по буквам, словарь
  ударений (yaro-s-lav, Any1Key). Телефонный звук: полоса 300–3400 Гц + μ-law (ELABS) — [B](findings/B.md), [A](findings/A.md).
- **Лицензии:** Silero CC BY-NC-SA не годится для госзаказчика; piper-tts MIT только до 1.2.0. У нас Piper 1.2.0
  только как инструмент сборки — в порядке — [E](findings/E.md).
