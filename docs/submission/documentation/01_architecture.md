# 1. Назначение, функциональная и компонентная архитектура

## 1.1 Назначение

Учебный симулятор рабочего места диспетчера дежурно-диспетчерской службы (ДДС) системы 112
города Москвы (задача № 9, ЛЦТ-2026). Обучаемый в роли диспетчера ДДС получает готовую карточку
происшествия из системы 112, принимает решение («Принята / Не принята»), выбирает бригаду,
передаёт сведения через учебный IP-телефон, отмечает этапы реагирования и завершает карточку.
Система оценивает действия по детерминированным правилам и локальной ИИ-модели, показывает
преподавателю разбор и аналитику. Работает полностью локально, без интернета и без GPU.

## 1.2 Роли и функции

| Роль | Основные функции | Где в интерфейсе |
|---|---|---|
| Обучаемый | АРМ ДДС: строка состояния с новыми карточками в реальном времени, карточка «формата 112», статусы с комментариями, выбор бригады, софтфон (набор 3-значного номера, реплики адресата, запись доклада), справочные материалы, свои результаты | `/app/arm` |
| Преподаватель | Занятия: состав и рабочие места, адресная выдача заданий пачкой, старт/стоп; live-доска и replay; вердикты и переопределения («согласен/не согласен»); отчёт и аналитика; студия сценариев (конструктор, предпросмотр, генерация и утверждение пакетов); учебные материалы | `/app/teacher` |
| Администратор | Учётные записи и роли, блокировка, нормативы и веса оценки, службы, состояние системы | `/app/admin` |

Процесс занятия: преподаватель создаёт занятие (снимок настроек и методики времени) → выдаёт
каждому рабочему месту свою очередь сценариев с задержками от старта → запускает занятие →
worker в нужный момент создаёт карточку и оповещает АРМ → обучаемый работает с карточкой →
терминальный статус создаёт мгновенную оценку по правилам и фоновую задачу ИИ-оценки →
преподаватель видит разбор, переопределяет вердикт, выгружает отчёт.

Жизненный цикл карточки (универсальный для служб, памятка ДДС стр. 21–25):
`received → accepted | rejected`; `rejected → accepted` (исправление) или перенаправление;
`accepted → responding → arrived → working → completed | refused`, этапы только вперёд,
пропуски допустимы (обязательные задаёт эталон сценария). Отказ без причины не принимается.
Завершающий статус закрывает карточку для правок.

## 1.3 Компонентная архитектура

| Компонент | Технология | Ответственность |
|---|---|---|
| Веб-клиент | React 18 + TypeScript, Vite, TanStack Query | АРМ, пульт преподавателя, админка, комната входа; очередь действий в IndexedDB с повтором после обрыва; общий расчёт времени `shared/timing.ts` |
| Обратный прокси | nginx (TLS, локальный CA) | HTTPS 8443, раздача SPA, `/api` и `/ws` к API |
| API | Python 3.12, FastAPI, SQLAlchemy async, asyncpg | REST по OpenAPI-контракту, WebSocket, RBAC и CSRF, аудит мутаций, конечный автомат карточки |
| Worker | тот же образ, `python -m app.worker` | планировщик выдачи карточек, очередь заданий (генерация, оценка, транскрипция), ИИ-судья, heartbeat |
| Оценщик | пакет `evalcore` (чистый Python) | критерии оценки, агрегирование, расчёт времени I-TIME, проверка эталона, генератор сценариев, парсер классификатора |
| База данных | PostgreSQL 16 | занятия, карточки, журнал событий (append-only), оценки и переопределения, прогнозы, материалы, аудит |
| Локальная LLM | llama.cpp server + Qwen3-4B Q4_K_M (профиль `llm`) | ИИ-оценка комментария, нарратив сценария; выключается `AI_PROVIDER=off` |
| Backup | контейнер на PostgreSQL 16 | ежедневный `pg_dump` + архив пользовательских файлов, SHA-256, восстановление в отдельный проект |

Взаимодействие:

- браузер ↔ nginx ↔ API по HTTPS (REST) и WSS (события `card.appeared/updated`,
  `evaluation.*`, `training.updated`, синхронизация часов `clock.ping/pong.v2`);
- API и worker пишут в PostgreSQL и публикуют `NOTIFY`; API держит `LISTEN` и рассылает
  события авторизованным клиентам; при потере `LISTEN` клиенты получают свежий snapshot;
- worker ↔ llama.cpp по OpenAI-совместимому HTTP внутри Docker-сети;
- все контракты стыков — в `contracts/` (OpenAPI, JSON Schema, WS-события, I-TIME и др.).

## 1.4 Данные

- **Классификатор происшествий 046_24** (1283 типа, 3835 правил оповещения шести служб) —
  справочник типов и служб-получателей; парсер определяет редакцию по шапке.
- **Сценарии**: карточка 112 + эталон (решение, статусы, службы, адрес, звонок, комментарий),
  уровень 1–4 и вес 1–10, происхождение (шаблон, ИИ, импорт по билетам, обучаемый).
  10 сценариев построены по билетам заказчика (32 билета / 96 задач), эталоны — учебная
  разметка команды, до проверки преподавателем — черновики.
- **Журнал событий карточки** — неизменяемый, с временем клиента и сервера и ссылкой на
  проверенный образец часов; из него восстанавливаются replay, время и оценка.
- **Снимок занятия**: нормативы, веса и методика времени фиксируются при создании занятия;
  последующие изменения настроек прошлые занятия не меняют.
