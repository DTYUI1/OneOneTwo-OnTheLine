# 1. Назначение

Тренажёр учит диспетчеров дежурно-диспетчерских служб (ДДС) системы-112 города Москвы работать с карточками происшествий: 101, 102, 103, 104, ЖКХ, Мослифт.
Обучаемый получает карточку из системы-112 и принимает решение «Принята» или «Не принята». Затем он звонит бригаде своей службы по виртуальному IP-телефону, выслушивает её доклады, ставит статусы и закрывает карточку.

Схема занятия: преподаватель выдаёт задания, обучаемый работает диспетчером ДДС, система оценивает результат, а преподаватель и обучаемый получают рекомендации к дальнейшему обучению. Для самостоятельной работы есть «Тренировка», «Мой путь» и «Каталог сценариев».

Тренажёр работает полностью локально: без интернета и без графического ускорителя. Внешние службы не вызываются.
Все данные в нём вымышленные.

Рабочее место обучаемого повторяет интерфейс АРМ диспетчера системы-112 по методическим материалам и скриншотам, менять его нельзя. Интерфейс преподавателя и администратора свободный и проще.
Этот комплект описывает обучение диспетчера ДДС. Модуль оператора 112 по умолчанию скрыт; администратор может включить его отдельно в разделе «Модули». Его собственный рабочий процесс в эти руководства не входит.

# 2. Функции

## 2.1. По ролям

| Роль | Что делает | Где |
|---|---|---|
| Обучаемый | Принимает карточки, ставит статусы с комментариями, звонит бригадам и службам по телефону ДДС, отвечает на входящие доклады, смотрит разбор и «Мой путь», тренируется самостоятельно | `/app/arm` |
| Преподаватель | Создаёт занятия, выдаёт задания каждому месту, подаёт вводные во время занятия, проверяет вердикты, смотрит отчёт и рекомендации, ведёт студию сценариев и материалы | `/app/teacher` |
| Администратор | Следит за состоянием сервера, задаёт нормативы и веса оценки, ведёт учётные записи, службы, резервные копии, читает журнал аудита | `/app/admin` |

Руководства: администратора, преподавателя и обучаемого — отдельные документы этого комплекта.

## 2.2. Основные возможности

- **Карточки и статусы** по памятке ДДС: «Получена службой», «Принята» или «Не принята», «Начало реагирования», «Прибытие», «Проведение работ», «Работы завершены», «Отказ от выполнения работ», перенаправление. Статус по докладу можно поставить только после самого доклада.
- **Виртуальный IP-телефон ДДС.** Звонок бригаде, руководству, другой службе или системе-112; входящие доклады бригады, пропущенные вызовы, удержание линии. Список абонентов (до 10 номеров на ДДС) задаёт преподаватель.
- **Живая бригада.** Бригады выезжают по вводной диспетчера, повторяют адрес (иногда с ошибкой), докладывают о выезде, прибытии, работах и итоге, задают вопросы, просят другие службы. Реплики — из банка озвученных фраз.
- **Ввод голосом и по частям.** Голос распознаётся локально; без распознавания или микрофона сведения собираются по частям, на каждом шаге до трёх коротких вариантов.
- **Сценарии как данные.** Каталог сценариев ДДС — файлы JSON; набор на финал: 101, 102, 103, 104, «не наша карточка» и бытовой сценарий со звонком заявителю.
- **Оценка.** Десять критериев с весами: время реакции и отработки, последовательность статусов, маршрутизация, обязательные поля, адрес, доклад по телефону, грамотность и ключевые сведения комментария, работа с бригадой. Критическая ошибка ограничивает итоговый балл. Преподаватель может изменить оценку и указать причину.
- **Рекомендации.** Разбор для обучаемого («Что сделать иначе», «Главное на следующую попытку»), отчёт и рекомендация уровня сложности для преподавателя, типичные ошибки группы, «Мой путь» из четырёх ступеней.
- **Самостоятельное обучение.** «Тренировка» («Смотрю — Вместе — Сам»), «Мой путь», «Каталог сценариев», «Проверьте себя», «Разминка», справка по окнам кнопкой «?». Подсказка в «Смотрю» и «Вместе» появляется рядом с нужным действием; в «Сам», каталоге и занятии преподавателя её нет. Завершённую тренировку можно пройти ещё раз из разбора с тем же сценарием.
- **Генерация сценариев.** Пакеты сценариев по службе и уровню собираются автоматически, при включённой локальной модели текст описания пишет модель; преподаватель проверяет и утверждает пакет.
- **Администрирование.** Учётные записи, службы, нормативы, резервные копии, журнал аудита, сообщения об ошибках.

## 2.3. Что не входит

- Приём входящего звонка заявителя — вне рамок: обучаемый получает готовую карточку от системы-112.
- Полностью автономный цикл с генерацией новой карточки именно моделью не следует считать подтверждённым по одной успешной ИИ-оценке. В «Моём пути» система сама подбирает карточки по ступени; когда новых готовых сценариев не хватает, создаёт проверенный сценарий шаблонным генератором. Этот путь работает без модели. В студии преподавателя модель может участвовать в генерации текста; фактический источник каждого результата нужно проверять отдельно.
- Эталонные ответы к билетам заказчик не предоставил: эталоны — учебная разметка команды, утверждаемая преподавателем.

# 3. Состав и устройство

| Компонент | Технология | Ответственность |
|---|---|---|
| Веб-клиент | React 18, TypeScript, Vite | АРМ диспетчера, кабинет преподавателя, администрирование; очередь действий в браузере: при обрыве связи действия сохраняются и отправляются повторно |
| Обратный прокси | nginx, TLS с локальным корневым сертификатом | HTTPS на порту 8443, раздача страниц, проксирование `/api` и `/ws` |
| API | Python 3.12, FastAPI | REST, WebSocket, права по ролям, защита от подделки запросов, журнал аудита, автомат карточки |
| Worker | тот же образ, `python -m app.worker` | Выдача карточек по расписанию, игра бригад, звонки, очередь заданий (оценка, генерация, распознавание), проверка текста моделью |
| Оценщик | пакет `evalcore` (Python) | Критерии, время по методике I-TIME, проверка эталона, генератор сценариев |
| База данных | PostgreSQL 16 | Занятия, карточки, журнал событий, оценки, материалы, аудит |
| Локальная модель (необязательно) | llama.cpp и Qwen3-4B Q4_K_M, профиль `llm` | Проверка понятности комментария, текст описания сгенерированных сценариев |
| Распознавание речи (необязательно) | faster-whisper small int8, профиль `stt` | Голосовой доклад диспетчера |
| Резервное копирование | контейнер `backup` | Ежедневный `pg_dump` и архив файлов с контрольными суммами |

Устройство связей: браузер — nginx — API по HTTPS и WebSocket; API и worker пишут в PostgreSQL; события доставляются клиентам в реальном времени, а при потере канала клиент перечитывает данные.
Озвучка бригад и дежурных — готовые записи банка `data/voices/bank-v*` и файлы, привязанные к сценарию. Банк подготовлен заранее; происхождение, текст, голос, длительность и контрольная сумма записи указаны в манифесте соответствующего набора. Основные актуальные записи подготовлены с ElevenLabs, воспроизводятся локально: обращения к облачному синтезу во время занятия нет. Старые файлы Piper могут оставаться в репозитории для совместимости и не описывают текущий основной банк.

Данные: сценарии `data/scenarios`, банк фраз озвучки (около двух тысяч фраз), классификатор происшествий (1283 типа), справочник служб и телефонов.
Подробнее об архитектуре — в документах 01–06 этой папки.

# 4. Требования

| Что | Требование |
|---|---|
| Сервер | Linux (Ubuntu) или Windows 10/11 с Docker Desktop (WSL2), Docker Compose версии 2.24 и выше |
| Процессор и память | x86-64; 8 ГБ оперативной памяти (без модели около 1,5 ГБ используется, с моделью на 4 ГБ больше); GPU не нужен |

| Рабочее место | Chromium или Firefox актуальной версии; для голоса — микрофон и доверенный сертификат (HTTPS) |
| Права | Пользователь с доступом к Docker; порты 8080 и 8443 (или выбранные) свободны |

# 5. Монтаж (установка)

Два способа: одной командой и по шагам.

## 5.1. Одной командой

Из корня репозитория:

```sh
scripts/stand/up.sh --project arm112-stand --ports 8080:8443
```

Команда собирает образы, поднимает базу, применяет миграции, загружает справочники, сценарии и учётные записи, запускает API, worker и веб и ждёт готовности `/api/health`.
В конце она печатает адрес для входа. Секреты проекта создаются один раз в `scripts/stand/.local/<проект>/stand.env` и переиспользуются при повторном запуске.

Основные параметры:

| Параметр | Что делает |
|---|---|
| `--project ИМЯ` | Имя проекта Docker Compose; у разных стендов оно разное |
| `--ports HTTP:HTTPS` | Порты сервера (по умолчанию 8080:8443) |
| `--lan` или `--ip АДРЕС` | Открыть сервер для других компьютеров сети; адрес входит в сертификат |
| `--ai local` | Включить локальную модель (нужен файл модели в `models/`) |
| `--stt local` | Включить распознавание речи |
| `--no-build` | Не собирать образы, взять готовые: для слабого сервера |
| `--random-password` | Случайный пароль учётных записей вместо `demo-local`: для сервера, открытого в сеть |
| `--no-demo-accounts` | Не показывать логины и пароль на экране входа |

Остановка без потери данных: `scripts/stand/down.sh --project arm112-stand`.
Полный сброс с удалением всех данных: `scripts/stand/down.sh --project arm112-stand --reset --yes`.
Проверка, если страница не открывается: `scripts/stand/check.sh --project arm112-stand` — по каждому пункту «ok» или «ошибка» с советом.
Сервер без возможности сборки (мало памяти): `scripts/stand/remote.sh --host ХОСТ` собирает образы на другом компьютере и переносит их по ssh.

## 5.2. По шагам

```sh
cp .env.example .env     # задайте API_MODE=database, JWT_SECRET (не короче 32 байт), DEMO_PASSWORD
docker compose build api web
docker compose up -d --wait db
docker compose run --rm --no-deps migrate
docker compose run --rm --no-deps api python -m app.seed
docker compose run --rm --no-deps api python -m app.seed.training
docker compose up -d --wait api worker web
```

Явно указывайте образы `api web`: общая команда `docker compose build` пытается собрать один образ несколько раз.
Миграции и справочники безопасно запускать повторно: правки данных они не перезаписывают.

Вход: `https://localhost:8443/app/login`. Учётные записи после загрузки справочников: `admin`, `teacher`, `trainee01` … `trainee05`; пароль — значение `DEMO_PASSWORD`.

## 5.3. Сертификат

Сервер использует собственный корневой сертификат. Чтобы браузеры не показывали «Не защищено», а микрофон работал, доверьте его на каждом рабочем месте:

```sh
scripts/stand/ca.sh --project arm112-stand
```

Команда кладёт сертификат в `scripts/stand/.local/<проект>/ca.crt` и печатает, как доверить его на macOS, Windows, Linux и в Firefox.
Для доступа из сети сертификат должен содержать адрес сервера: запускайте `up.sh` с `--lan` или `--ip`.
Ключ корневого сертификата не распространяйте.

## 5.4. Установка без интернета

На подготовительной машине с интернетом `python3 deploy/offline.py create --output <каталог> --model <файл.gguf> …` собирает образы, модель, файлы запуска и манифест с контрольными суммами.
На сервере `deploy/offline.sh load` (Linux) или `deploy/offline.ps1` (Windows) проверяет суммы и загружает образы; далее запускайте по шагам раздела 5.2 с параметрами `--pull never --no-build`.
Сборщик отказывает при неполных входных данных.

# 6. Настройка

## 6.1. Параметры сервера

Параметры задаются в файле `.env` (или в `stand.env` при запуске одной командой) до первого запуска. Основные:

| Параметр | Назначение |
|---|---|
| `API_MODE` | `database` — рабочий режим; `mock` — статический режим для разработки, в нём данные не сохраняются |
| `JWT_SECRET` | Постоянная случайная строка не короче 32 байт для подписи сеансов. Не меняйте без необходимости: все пользователи выйдут |
| `DEMO_PASSWORD` | Пароль учётных записей, которые создаёт загрузка справочников |
| `DEMO_ACCOUNTS_SHOWN` | `true` — на экране входа показаны учётные записи и пароль (для демонстрации); на рабочем сервере — `false` |
| `COOKIE_SECURE` | `true` при работе по HTTPS |
| `SESSION_TTL_SECONDS` | Срок сеанса, по умолчанию 8 часов |
| `POSTGRES_PASSWORD`, `DATABASE_URL` | Доступ к базе. Пароль тома базы задаётся при первом создании и потом не меняется |
| `WEB_BIND` | Адрес прослушивания веб-сервера: `127.0.0.1` — только с этого компьютера, `0.0.0.0` — из сети |
| `CERT_HOSTNAMES` | Имена и адреса, которые войдут в сертификат: `localhost,127.0.0.1,<адрес сервера>` |
| `AI_PROVIDER` | `off` — без модели; `local` — локальная модель |
| `LLM_MODEL_FILE` | Путь к файлу модели `.gguf` относительно `deploy/` |
| `STT_PROVIDER` | `off` или `local` — распознавание голоса |
| `STT_MIN_CONFIDENCE` | Порог уверенности распознавания, по умолчанию 0,45: ниже — «Не расслышал, повторите» |
| `BACKUP_DIR` | Каталог резервных копий на сервере |

После смены параметров перезапустите сервисы: `docker compose up -d --wait api worker web`.

## 6.2. Локальная модель

Положите файл `qwen3-4b-instruct-2507-q4_k_m.gguf` в каталог `models/`, задайте `AI_PROVIDER=local` и запустите `docker compose --profile llm up -d --wait llm worker` (при запуске одной командой — параметр `--ai local`).
Модель читается только из локального файла, из интернета ничего не загружается. Без модели тренажёр работает, а оценки помечаются «предварительно».
Проверка одного комментария на процессоре занимает от нескольких секунд до десятков секунд: при плотной нагрузке класса оценка по тексту может завершиться позже.

## 6.3. Распознавание речи

`docker compose --profile stt up -d --wait --build stt worker` с `STT_PROVIDER=local` (при запуске одной командой — `--stt local`). Без него доклад голосом заменяется вариантами ответа по частям: окно телефона само предложит их.

## 6.4. Настройки в интерфейсе

Нормативы времени, число параллельных карточек, подсказки, веса критериев и штраф за доклад вариантом администратор задаёт в разделе «Нормативы и оценка».
Учётные записи, службы и их включение — разделы «Пользователи» и «Службы ДДС». Подробнее — в руководстве администратора.
Абоненты телефона ДДС и нормативы занятия — в карточке нового занятия у преподавателя.

## 6.5. Сеть класса

1. Поднимите сервер с `--lan` (или `--ip`).
2. Проверьте `scripts/stand/check.sh`: должны быть «ok» по контейнерам, `/api/health`, порту и адресу в сертификате.
3. Доверьте сертификат на рабочих местах (раздел 5.3).
4. Раздайте адрес `https://<адрес сервера>:<порт>/app/login`.
5. Убедитесь, что сеть не изолирует клиентов друг от друга (на некоторых точках доступа Wi-Fi это включено).

# 7. Эксплуатация

- **Состояние.** `https://<адрес>/api/health` показывает режим, базу, worker и ИИ-провайдера; раздел «Состояние системы» в интерфейсе администратора показывает то же и нагрузку; `docker compose ps` — контейнеры.
- **Остановка без потери данных.** `docker compose stop` или `scripts/stand/down.sh`. Не используйте `down -v`, если данные нужны.
- **Обновление.** Сначала сделайте резервную копию и выберите согласованную версию кода. Затем выполните `docker compose build api web`, `docker compose run --rm --no-deps migrate`, `docker compose run --rm --no-deps api python -m app.seed.training` и `docker compose up -d --wait api worker web`. Для стенда, созданного через `scripts/stand/up.sh`, повторите его запуск с теми же именем проекта, портами и режимами ИИ/распознавания: он использует сохранённые настройки своего проекта. Простой перезапуск оставит старый образ.
- **Новые версии сценариев.** Загрузка справочников не обновляет уже загруженные сценарии. Изменённый файл сценария нужно выпустить новой версией (поле `version`), иначе на работающем сервере ничего не изменится. Описание — `data/scenarios/README.md`.
- **Журналы.** Действия пользователей и изменения данных пишутся в журнал аудита в базе (бессрочно, входит в копию). Журналы контейнеров: `docker compose logs <сервис>`; для хранения дольше нескольких недель выгружайте их по расписанию, например `docker compose logs --no-color --since 24h > /var/log/arm112/$(date +%F).log` раз в сутки.
- **Проверки разработчика.** `uv sync --all-packages --frozen && pnpm install --frozen-lockfile`, затем `uv run pytest -q`, `pnpm lint`, `pnpm typecheck`, `pnpm test`; браузерные проверки — `pnpm exec playwright test -c qa/playwright.config.ts` на поднятом сервере.

# 8. Резервное копирование и восстановление

- Контейнер `backup` ежедневно в 02:00 UTC делает `pg_dump` и архив записей докладов и материалов, пишет контрольные суммы SHA-256 и публикует копию только после проверки.
- Вручную: `docker compose run --rm --no-deps backup backup-once` или кнопка «Сделать копию сейчас» в разделе «Копии и корзина» (копия сделается в течение минуты).
- Копии автоматически не удаляются: держите папку `BACKUP_DIR` на отдельном диске и предусмотрите место и вывоз копий.
- Удалённые учётные записи обезличиваются только после успешной копии, начатой позже удаления.
- Восстановление выполняется только в новый проект и пустые тома: `sh deploy/restore.sh <новый-проект> backup-YYYYMMDDTHHMMSSZ`. Восстановление в рабочий проект отклоняется.

# 9. Возможные неисправности

| Что наблюдается | Причина | Что делать |
|---|---|---|
| Страница входа не открывается | Сервер не запущен, не тот адрес или порт, порт занят | `scripts/stand/check.sh --project …`; `docker compose ps`; выберите свободные порты `--ports` |
| С другого компьютера страница не открывается | Сервер запущен без `--lan` или сеть изолирует клиентов | Запустите с `--lan` или `--ip`; проверьте `check.sh`; подключите компьютеры к одной сети без изоляции |
| Браузер пишет «Не защищено» | Корневой сертификат не доверен на этом компьютере | `scripts/stand/ca.sh`, доверьте сертификат, перезапустите браузер |
| Микрофон не работает | Страница открыта без доверенного HTTPS или нет разрешения | Доверьте сертификат, разрешите микрофон в браузере; без микрофона докладывайте по частям |
| «Распознавание речи на сервере выключено» | Не включён `STT_PROVIDER=local` | Включите (раздел 6.3) или докладывайте по частям |
| `/api/health` пишет `mock` или `database: not_connected` | Нет `.env` с `API_MODE=database` | Задайте `API_MODE=database`, `JWT_SECRET`, перезапустите |
| Карточки не приходят | Не работает worker | В «Состоянии системы» плитка «Фоновый обработчик»; `docker compose restart worker`; `docker compose logs worker` |
| `migrate` падает с ошибкой пароля | Пароль в `DATABASE_URL` не совпадает с паролем тома базы | Не меняйте пароль вручную; используйте сохранённые секреты проекта или пересоздайте том (с потерей данных) |
| Бригады молчат или звук не слышен | Браузер не разрешил воспроизведение или звук выключен в окне телефона | Нажмите «звук вкл.»; проверьте громкость; текст реплик показывается в любом случае |
| Новые версии сценариев не появились | Загрузка справочников не заменяет сценарии | Поднимите `version` в файле сценария и повторно выполните `app.seed.training` |
| Оценки «предварительно» | Модель выключена или не успела проверить текст | Баллы по правилам действуют; включите модель (раздел 6.2) или подождите |
| Модель отвечает очень медленно | Не хватает памяти или процессора | Увеличьте память Docker, закройте лишнее; для занятия оставьте оценку по правилам |
| Сервер на macOS работает очень медленно | Виртуальная машина Docker с малой памятью | Выделите не менее 8 ГБ (`colima start --memory 8`) |
| `docker compose build` падает на тегах образов | Общая сборка собирает один образ несколько раз | Собирайте по одному: `docker compose build api web` |
| Сертификат не подходит для адреса | Адрес не вошёл в сертификат при первом запуске | Перезапустите `up.sh` с `--ip АДРЕС`: том сертификатов пересоздастся, база не тронется |
| Не хватает места на диске | Копии и записи докладов копятся | Вывезите копии из `BACKUP_DIR`; проверьте плитку «Место на диске» |

# 10. Условия и ограничения

- Решение рассчитано на учебный класс: один сервер и до 23 рабочих мест. Прежние проверки на i7-11800H / 16 ГБ и i5-1155G7 / 7,5 ГБ не заменяют нагрузочную приёмку обновлённой сборки с выбранной моделью и распознаванием речи. Перед занятием полного класса повторите её на оборудовании класса.
- Алгоритм работы служб универсальный; исключения памятки для службы 103 (нет «Не принята» и «Отказ от выполнения работ») учтены, остальные специализации не реализованы.
- Норматив реакции 30 секунд — из памятки ДДС; методика «трёх минут активной отработки» — решение команды, а не норматив памятки. Время в тренажёре сжато: бригада действует в 10–100 раз быстрее, чем в жизни.
- Проверка адреса опирается на текстовые данные карточки; справочник улиц не подключён, опечатки в названии улицы не прощаются.
- Основная озвучка — заранее подготовленный банк фраз; сведения об источниках лежат в манифестах `data/voices/bank-v*` и `scripts/voices/bank/`. У старых записей Piper отдельное происхождение в `scripts/voices/PROVENANCE.md`; его нельзя переносить на весь актуальный банк.
- Распознавание речи и локальная модель — необязательные опции: без них тренажёр работает, голос заменяют варианты ответа, а оценка текста помечается «предварительно».
- Резервные копии не удаляются автоматически, журнал контейнеров ротируется: для хранения ≥ 6 месяцев нужна выгрузка по расписанию.
- Проверенные платформы: Linux (Arch, Ubuntu), Windows 11 с Docker Desktop; Chromium и Firefox. Яндекс.Браузер не проверялся.
- В учебных карточках — вымышленные ФИО и номера. Учётные записи пользователей, учебные результаты и записи голосовых ответов сохраняются на сервере; администратор отвечает за доступ к ним. Юридическая сертификация не заявляется.
