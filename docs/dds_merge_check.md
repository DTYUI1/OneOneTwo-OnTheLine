## Решения капитана и штраф за доклад

- Живая бригада остаётся на ступени 2, в проверенном полном цикле.
- По умолчанию готовый вариант даёт 50 % балла за содержание голосового доклада.
- Преподаватель задаёт штраф 0–100 % для конкретного занятия. В форме теперь
  показываются проценты штрафа вместо коэффициента 0…1. В API остаётся существующий
  report_choice_factor: (100 − штраф) / 100; он сохраняется в settings_snapshot.
- Это штраф за содержание доклада, а не вычитание процентов из всего результата.
  Остальные составляющие оценки звонка сохраняются.

В team-integration преподаватель создаёт занятия со штрафами 70 % и 20 % в двух
браузерах. Проверяются снимок созданного занятия и неизменность настроек класса.
test_teacher_sets_choice_factor дополнительно проверяет промежуточную долю 0,25.

## Что остаётся за пределами этого слияния

- Проверка голоса капитаном и замер распознавания на обычном ноутбуке без GPU.
- Оценка голосового доклада пока использует report_modes/report_parts из браузера
  в call_hangup. Подделанный запрос может выдать вариант за голос; настройки штрафа
  сами по себе это не исправляют. Это открытое замечание ревью #78.
- В разборе ДДС пока не показаны источник карточки от оператора-бота и ошибки оператора
  (замечание #79); DT-04 не объявляется полностью принятым.
- DT-06, дополнительный макет B (#89 и следующие задачи), личный показ DT-13 и
  визуальная приёмка оператора 112 не объявляются выполненными этим PR.
