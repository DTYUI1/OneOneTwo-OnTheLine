OpenAPI использует относительный сервер `/api`; путь `/cards` означает `/api/cards`.
Мок с состоянием работает на `http://127.0.0.1:8000/api`, WS — `/ws`.
Prism (`pnpm mock`) служит только для статических HTTP-примеров, не заменяет сессии и WS.

Времена — ISO-8601 UTC, UUID — v4; баллы нормированы **0..1**, UI при необходимости умножает на 100.
Неизвестные поля входных объектов запрещены. Ошибки: `{code, message, details}`.
Каждый метод содержит `x-roles`; обучаемый имеет доступ только к своим карточкам/результатам.
Эталоны сценариев доступны только преподавателю/администратору; `Card` не содержит `reference`.
JWT хранится в httpOnly-cookie `session`. Все мутации после входа требуют cookie `csrf` и
такого же `X-CSRF-Token`. Login — публичный, logout удаляет обе cookie и серверную сессию.
В дев-режиме HTTP cookie не Secure; в Compose за TLS — Secure.

`uv run --package arm112-scripts python scripts/validate_contracts.py` проверяет OpenAPI,
схемы, примеры и golden. `pnpm gen:api` генерирует `apps/web/src/api-client/schema.d.ts`;
типизированный транспорт `openapi-fetch` расположен в `shared/api.ts`. CI проверяет отсутствие
расхождений между экспортом/клиентом и исходным контрактом.

Для C-01 порядок: правка `c01.schema.json` → `python scripts/sync_c01_contracts.py`
→ `python -m app.tools.export_openapi` → `npm --prefix apps/web run gen:api`.
Новые URL редактируются в draft, CardEvent — в `card-event.schema.json` и одноимённом
компоненте (равенство проверяет validate_contracts). Generated TS вручную не редактировать.
`python scripts/sync_c01_contracts.py --check` проверяет отсутствие drift общих объектов.

Полный CRUD админки, ревизия сценариев, backup/audit и расширенные отчёты добавляются
капитаном через `contract:` до соответствующих T-015/T-016/T-029, а не угадываются frontend.
Результаты мока — синтетические: они не доказывают готовность оценки, БД, телефонии или MVP.
