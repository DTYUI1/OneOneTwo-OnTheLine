# Ход занятия: присутствие, пауза, сообщение ученику — TC-12

Источник: `docs/competitors/touches.md`, «Преподаватель»; разбор — `docs/dds_touches.md`.
Как и выключатель модуля 112 (`operator/module-switch.md`), эти операции не входят в
`openapi.json`: они аддитивны и ничего не меняют в существующих схемах. Тело и ответ — JSON,
POST требует `X-CSRF-Token`. Времена — ISO UTC.

## Присутствие (WS `presence`)

- Клиент шлёт `clock.ping` каждые 5 с (`ws-events.md`). Сокет, который молчит дольше **45 с**,
  сервер закрывает с кодом `4408`; если у пользователя не осталось других сокетов, всем
  уходит `presence {user_id, online: false}`. Обрыв сети без закрытия TCP виден не позже 45 с.
- Сразу после `snapshot` преподаватель получает `presence {online: true}` по каждому, кто
  уже в сети: открытая позже доска не считает учеников «не в сети».

## Пауза

`participant_id` — `user_id` обучаемого, как в назначениях. Только преподаватель-владелец
идущего (`running`) занятия; чужое — `404`, не идущее — `409`.

- `POST /sessions/{id}/pause` — тело `{"participant_id": UUID | null}`; `null` — всё занятие.
  Уже на паузе — `409`. Пауза одного ученика во время паузы занятия — `409`.
- `POST /sessions/{id}/resume` — то же тело. Не на паузе — `409`.

Ответ обеих операций `200` — `LivePause`:
`{"paused_at": string | null, "participants": {"<user_id>": "<paused_at>"}}`.

Пока занятие или ученик на паузе, scheduler не выдаёт новых карточек. При снятии паузы
сроки ещё не выданных карточек (назначения без карточки, `pending`, не отменённые)
сдвигаются на длину паузы: `due_at := coalesce(due_at, planned_at) + (now − paused_at)`.
Пауза ученика, начатая до паузы занятия, при снятии паузы занятия сдвигается на ту же
длину, чтобы общий отрезок не учитывался дважды.

Не останавливаются: нормативы уже выданных карточек (I-TIME), доклады бригад, события
сценария. Пауза — между карточками, а не внутри них.

Хранение: `sessions.paused_at`, `session_participants.paused_at` (nullable).

## Сообщение ученику

`Message`: `{"id", "session_id", "user_id", "text", "sent_at", "read_at": string | null}`.

- `POST /sessions/{id}/messages` — преподаватель-владелец идущего занятия.
  Тело `{"user_id": UUID, "text": string}`; текст после обрезки пробелов 1…500 символов
  (иначе `422`), `user_id` — участник занятия (иначе `422`). Ответ `201` — `Message`.
- `GET /sessions/{id}/live` — преподаватель-владелец: `LivePause` и
  `"messages": Message[]` занятия по `sent_at`.
- `GET /messages` — обучаемый: свои сообщения идущих занятий по `sent_at`.
- `POST /messages/{id}/read` — обучаемый, только своё (чужое — `404`). Ответ `200` —
  `Message`; повтор не меняет первое `read_at`.

Хранение: `teacher_messages (id, session_id FK, user_id FK, teacher_id FK, text, sent_at,
read_at)`. Доставка — опрос раз в 5 с: новых типов WS нет.
