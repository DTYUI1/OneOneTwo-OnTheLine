# Сохранение и оценка попытки — `POST /api/operator/save`

Модуль «Оператор 112». Обучаемый нажимает «сохранить» на экране `/operator` — карточка
оценивается детерминированно (без сети и GPU) и попытка сохраняется. Частный API модуля
описан здесь и в `dialog.md`; маршруты `/api/operator/*` не включены в общий OpenAPI.

Доступ: обучаемый, преподаватель, администратор; без входа — 401, без `X-CSRF-Token` — 403.

## Хранение попытки (пока нет своих таблиц — OP-01 отложена)

Попытка не создаёт свою строку в БД: `POST /save` кладёт результат в общий журнал
`audit_log` через `request.state.audit_after` (`app/core/audit.py`) — тот же механизм, что
у материалов и событий карточки (`entity = "operator_attempt"`, `entity_id` — id попытки,
`action` = `operator_save`, `actor_id` — обучаемый). `GET /attempts*` читает эти строки по
`actor_id`: обучаемый видит только свои попытки, преподаватель и администратор — группу.

## `POST /save`

`card.address` дополнительно принимает необязательные строки `object`, `structure`,
`entrance`, `floor`, `code`, `descriptive` (до 200 знаков, пустое значение — пустая строка).
`card.caller_status` — пустая строка или «очевидец», «пострадавший», «родственник»,
«знакомый», «ребенок», «участник» (инструкция, раздел 4.1).
Полная введённая карточка хранится в `audit_log.after.operator_card` и возвращается в
`operator_card` ответов `/save` и `/attempts/{id}`; у старых попыток — `null`.
`card.emergency` — явный признак ЧС (по умолчанию `false`); колокольчик его не меняет.
`phone_provided` и `phone_scene` нормализуются в `+7` и десять цифр: принимаются десять цифр
номера, перед ними — `+7`, `7` или `8` (маска АРМ `+7 (___) ___-__-__`, снимки `card_112`);
пустая строка допустима, иначе — 422. Экран вводит номер по той же маске и неполный номер
не отправляет: называет поле, которое нужно дописать или очистить.

```json
{
  "scenario_id": "fire_apartment_smoke",
  "state": { "panic": 0, "asked": ["address", "what_happened", "victims"], "facts": [] },
  "elapsed_s": 90,
  "card": {
    "incident_type_code": "1050102",
    "tags": ["victims", "gasification"],
    "services": ["101", "102", "103", "104", "MOSLIFT"],
    "address": {
      "city": "Москва", "okrug": "САО", "district": "Западное Дегунино",
      "street": "Дубнинская улица", "house": "12", "building": "", "apartment": "47"
    },
    "description": "Задымление в квартире 47…",
    "caller_name": "Соснина Ольга Викторовна",
    "phone_provided": "", "phone_scene": "", "off_site": false
  },
  "journal": {
    "events": [
      { "t": 0, "action": "opening", "reply": "Алло! Алло, это пожарные?!…",
        "panic_before": 3, "panic_after": 3,
        "mark": { "kind": "info", "text": "Звонок начался: заявитель в истерике." } },
      { "t": 7, "action": "question", "key": "address", "said": "Назовите точный адрес…",
        "reply": "Я не знаю! Там дым! Сделайте что-нибудь!", "outcome": "unheard",
        "panic_before": 3, "panic_after": 3,
        "mark": { "kind": "bad", "text": "Вопрос не услышан: заявитель в истерике…" } },
      { "t": 90, "action": "end", "note": "Карточка сохранена, разговор окончен." }
    ],
    "steps": [{ "step": 1, "t": 31 }, { "step": 2, "t": 44 }]
  }
}
```

- `state` — итоговое состояние заявителя из разговора (`contracts/operator/dialog.md`):
  `panic`, `calm_reason`, `calm_order`, `pauses`, `escalated`, `escalation_handled` —
  критерий «Работа с заявителем»; `escalated` добавляет к описанию факт ухудшения; `asked` и
  `confirmed` — критерий «Порядок опроса».
- `journal` (этап 3, необязательно) — журнал звонка для разбора, его ведёт экран (ниже).
- `scenario_id` — один из сценариев в ротации `data/operator/scenarios/` (с 29.09 их четыре;
  сценарии вне ротации — `data/operator/archive/`).
- `elapsed_s` — время от начала звонка до нажатия «сохранить» (веб считает сам).
- `card.tags` — ключи тегов маршрутизации (`victims`, `no_access`, `offense`,
  `gasification`), `card.services` — id служб с полосы «Службы:».
- `card.emergency` (необязательно, по умолчанию `false`) — признак ЧС карточки 112
  (`card.schema.json`). На экране оператора отметки пока нет; поле ставит запись
  оператора-бота связки (`contracts/link-112-dds.md`, DT-04).
- Карточка 112 попытки (`after.card` в журнале) собирается только из ввода оператора, кроме АОН:
  пустое имя заявителя остаётся пустым; телефоны приводятся к `+7XXXXXXXXXX`, номер, который
  так не разобрать, в карточку не идёт (`card_for_dispatch`, `apps/api/app/operator/router.py`).
- Сценарий не найден — 404.

## Ответ 200

```json
{
  "id": "3c9a1e2e-...",
  "scenario_id": "fire_apartment_smoke",
  "scenario_title": "Пожар в многоквартирном доме: дым в квартире",
  "created_at": "2026-09-28T00:00:00Z",
  "total": 100,
  "max_total": 100,
  "criteria": [
    { "key": "incident_type", "title": "Тип происшествия", "weight": 15, "score": 1.0,
      "points": 15, "explanation": "Тип происшествия определён верно: «задымление: квартира»." },
    "... tags, services, address, description, order, caller, timing"
  ],
  "journal": { "events": ["..."], "steps": ["..."] }
}
```

`journal` — журнал звонка в том виде, в каком его сохранил сервер (ниже); у попытки без
журнала — `{ "events": [], "steps": [] }`.

## Журнал звонка (этап 3)

Экран ведёт журнал сам: каждое действие оператора и ответ заявителя, первая реплика и конец
разговора. Сервер проверяет его (`apps/api/app/operator/router.py`, `CallJournal`) и кладёт
в попытку (`audit_log.after.journal`); окно результата показывает по нему разбор звонка.

- `events` — до 300 событий, время `t` не убывает (иначе 422):
  - `t` — секунды от «Принять вызов», 0…86 400;
  - `action` — `opening` (первая реплика), `question`, `calm`, `hold`, `silence`, `advice`,
    `escalate` (как в `POST /ask`), `senior_called` (позвал старшего),
    `end` (разговор окончен: срыв, нет контакта, сохранено);
  - `key` — ключ вопроса карты, лишнего вопроса, приёма «Успокоить» или совета;
  - `said` — что сказал оператор, `reply` — что ответил заявитель, `note` — служебная
    строка (до 500 символов каждая);
  - `voice` — необязательный ключ готовой голосовой записи ответа (до 120 символов),
    например `fire_apartment_smoke/opening`; повторяется только запись из локального набора;
  - `outcome` — исход из ответа `POST /ask` (`contracts/operator/dialog.md`);
  - `panic_before`, `panic_after` — паника 0…3 до и после действия (обучаемому цифрой не
    показывается — в разборе видно только «паника выросла / снизилась» в пометке);
  - `mark` — пометка `{ kind, text }` из ответа `POST /ask` (`good` — помогло, `bad` —
    навредило, `warn` — внимание, `info` — событие); у `opening` и `end` её ставит экран.
- `steps` — пройденные шаги опроса и время, когда шаг пройден (`progress.done` из ответа
  `POST /ask`): `step` 1…5 без повторов, `t` — как у событий.

`senior_called` — информационное событие кнопки «Важное происшествие» (п. 11.5 инструкции,
рис. 79). Экран добавляет его один раз за принятый, ещё не завершённый звонок:
`{ "t": 8, "action": "senior_called", "note": "позвал старшего" }`.
Повторное нажатие показывает «Уже оповещён» без нового события. Событие сохраняется в
попытке и показывается в ленте разбора. Оно не меняет состояние заявителя, баллы или штрафы.
Уведомление тренажёра содержит номер АРМ и имя обучаемого; это имитация оповещения.

## Веса и норматив (настройки модуля)

`apps/api/app/operator/evaluation.py`, `DEFAULT_WEIGHTS` — сумма 100. Этап 3: веса — как в
одобренном прототипе (`docs/operator_112_review/prototype/`): добавлен «Порядок опроса» (10),
тип и службы — по 15 вместо 20.

| критерий | вес | что проверяет |
|---|---|---|
| `incident_type` | 15 | выбранный тип совпадает с эталоном сценария или равнозначен ему; близкий тип — половина, см. ниже |
| `tags` | 10 | теги маршрутизации совпадают с `expected_tags`; спорные `optional_tags` сценария («Нет доступа» у запертой квартиры, «Пострадавшие» у больного) службы не меняют — не требуются и не штрафуются |
| `services` | 15 | службы на полосе совпадают с `expected_services`; лишние — штраф |
| `address` | 20 | поля адреса; несовпадение улицы — критично, весь критерий 0 (Дубнинская ≠ Дубининская, Q&A 16.09); тип улицы можно не писать или сократить, но написанный должен совпасть («Кутузовский пр-т» = «Кутузовский проспект» ≠ «Кутузовский переулок»), «к2»/«кв. 47» — то же, что «2»/«47»; округ и район — см. ниже |
| `description` | 15 | доля фактов `description_facts` сценария, найденных в описании; в пояснении — какие не учтены |
| `order` | 10 | «Порядок опроса» (этап 3): адрес первым, адрес подтверждён повтором, номер для обратной связи, ориентир — см. ниже |
| `caller` | 10 | «Работа с заявителем» (этап 2): итоговая паника, успокоение просьбой с причиной, паузы, совет при ухудшении — см. ниже |
| `timing` | 5 | `elapsed_s` относительно норматива `NORMATIVE_S` = 180 с (как `OPERATOR_SETTINGS.normativeS` на вебе) — только при верных типе и адресе, см. ниже |

Своей таблицы настроек для весов пока нет — они меняются правкой `DEFAULT_WEIGHTS` вместе
с кодом, как `OPERATOR_SETTINGS` на вебе.

### Правила оценки v2 (29.09, `docs/operator_112_review/README.md`, раздел 2, п. 7)

- **Округ и район.** Проверяются, если заявитель их называет (`named_address_fields`
  сценария) или обучаемый их заполнил. Пустое поле, которое заявитель не называл, не
  штрафуется; заполненное неверно — ошибка адреса, как и прежде.
- **Описание.** Сверяется не со словами `description_reference`, а с явным списком фактов
  сценария `description_facts` (5–7, у каждого — синонимы). Факт учтён, если в описании есть
  все слова хотя бы одного синонима; окончания нормализуются, как у вопросов опросной карты,
  а числа, опечатки и отрицания — см. «Тип и описание» ниже. Балл — доля учтённых фактов.
  `description_reference` покрывает все факты своего сценария — это проверяет тест.
- **Полный адрес.** `object`, `structure`, `entrance`, `floor`, `code`, `descriptive`
  проверяются только при наличии в `named_address_fields`; неназванные значения не
  штрафуются. Подъезд, этаж и код принимают числа словами и цифрами. Описательный адрес
  сверяется с `landmark_synonyms` сценария по правилам фактов описания. Каждое проверяемое
  поле имеет равную долю: `score = 1 − ошибки / число проверяемых полей`, вес адреса — 20.
  Без новых названных полей прежний балл сохраняется. В разборе видны все введённые поля.
- **Время.** Баллы за время начисляются, только если тип происшествия верен (или близок, см.
  ниже) и в адресе верны улица и дом (для сценария без происшествия — только тип). Иначе 0 с
  пояснением: быстро сохранённая неверная карточка помощь не ускоряет.

### Тип и описание (разбор капитана 29.09)

- **Равнозначный тип** (`accepted_incident_type_codes` сценария) — полный балл. В
  классификаторе один случай бывает в двух группах: «Ребенок застрял в лифте» (Ребенок в
  опасности) = «Застревание в лифте (ребенок без взрослых)» (ЛИФТ), «Боль в грудной клетке» =
  «Плохо с сердцем». Службы по `routing_rules` у равнозначного типа те же — это проверяет тест.
- **Близкий тип** (`close_incident_type_codes`) — та же ситуация без важного признака
  («Застревание в лифте» вместо «…(ребенок без взрослых)», «ДТП с пострадавшими» вместо «…-
  разлитие горючих жидкостей»): половина балла, в пояснении — какой тип точнее; время не
  отнимает. Любой другой тип — 0.
- **Факты описания** ищутся мягче, чем вопросы опросной карты (`caller.py: mentions`):
  числа словами и цифрами равны («между четвёртым и пятым» = «между 4 и 5»,
  «пятьдесят восемь» = «58»); одна опечатка в
  слове от пяти букв прощается («несовершенолетний», «ребёнка»); отрицание засчитывается,
  только если стоит рядом со своим словом в той же фразе («не пострадал», «света нет»), а
  утверждение под отрицанием не засчитывается («без сознания» — не «в сознании»). У каждого
  факта — синонимы разными словами («погас свет» = «нет электричества» = «темно»).

## Карточка для ДДС

Если `card.incident_type_code` задан (не ошибочный звонок), в `audit_log.after.card`
сохраняется карточка в формате `contracts/card.schema.json` — чтобы её мог получить
диспетчер ДДС. Адрес содержит все введённые поля, статус заявителя передаётся отдельным
`caller_status`. Пустое имя не заменяется именем из сценария; `emergency` берётся из
входной карточки. Записи оператора-бота, их схема и выдача диспетчеру (шаг 1, DT-04) —
`contracts/link-112-dds.md`. Попытка живого оператора в АРМ ДДС пока не выдаётся — это шаг 2.

## `GET /attempts`

Список попыток, новые сверху: `[{ id, scenario_id, scenario_title,
created_at, total, max_total, actor_id, actor_login, actor_name }]`.
Обучаемый видит только свои попытки; преподаватель и администратор — все.
Необязательный `trainee_id` (UUID) фильтрует список, сохраняя ограничение прав обучаемого.
Имена берутся из локальных учётных записей; старые попытки остаются доступны.

## `GET /attempts/{id}`

Полный результат попытки (как ответ `/save`), включая владельца, введённую карточку и
журнал. Обучаемому доступна только своя; преподавателю и администратору — любая.
Чужая для обучаемого или не найденная попытка — 404.

### Работа с заявителем (этап 2, 29.09)

Критерий `caller` вместо «Итоговой паники»: доли 0,4 · (1 − паника/3) + 0,2 · успокоение +
0,2 · паузы + 0,2 · ухудшение.

- **Успокоение** — 1, если персонаж стартовал в истерике и её снимали просьбой с причиной
  (`calm_reason` > 0) или истерики не было; «Успокойтесь!» без причины — минус 0,5.
- **Паузы** — 1 без пауз, 0,5 за одну, 0 за две и больше.
- **Ухудшение** — 1, если его не было или на него дан нужный совет (`escalation_handled`).
- **Описание** после ухудшения ищет и факт `escalation.fact`.
- **Статус заявителя** сравнивается с `scenario.caller.status`: пояснение «верно» или
  выбранный и нужный статус дописывается в критерий `caller`. Балл, доли и веса не меняются.

### Порядок опроса (этап 3, 29.09)

Стандарт приёма вызова APCO/NENA (`docs/operator_112_review/README.md`, раздел 3): адрес —
первым и подтверждён повтором, номер для обратной связи, ориентир. Доли:
0,4 · адрес первым + 0,2 · повтор адреса + 0,2 · номер для связи + 0,2 · ориентир.

- **Адрес первым** — 1, если заявитель услышал вопрос об адресе (`address` в `asked`, в том
  числе адрес после «Успокоить» с причиной) раньше любого вопроса шагов 2–5.
- **Повтор адреса** — 1, если адрес подтверждён повтором (`state.confirmed`): оператор
  повторил вслух адрес из карточки и заявитель согласился.
- **Номер для связи** — 1, если заявитель услышал вопрос `callback`.
- **Ориентир** — 1, если заявитель услышал вопрос `landmark`.

Сценарий без опросной карты (ошибочный звонок, сейчас вне ротации) — 1: порядок не оценивается.
