# Разговор с заявителем — `POST /api/operator/ask`

Модуль «Оператор 112». Одно действие оператора → одна реплика заявителя по правилам
(`apps/api/app/operator/caller.py`, без генерации — Q29). Эндпоинт вне
`contracts/openapi.draft.yaml` (`include_in_schema=False`), пока модуль не получил свой
OpenAPI-фрагмент (OP-01).

Доступ: обучаемый, преподаватель, администратор; без входа — 401, без `X-CSRF-Token` — 403.

Попыток в базе пока нет (OP-01 отложена): состояние заявителя хранит клиент и присылает с
каждым действием. Ответ — чистая функция от сценария, состояния и действия.

## Запрос

```json
{
  "scenario_id": "fire_apartment_smoke",
  "state": { "panic": 3, "asked": [], "facts": [] },
  "action": "question",
  "questionnaire_id": "fire_apartment",
  "key": "confirm_address",
  "address": { "street": "Дубининская улица", "house": "12", "building": "", "apartment": "47" }
}
```

- `scenario_id` — `id` сценария из `data/operator/scenarios/`; нет такого — 404.
- `state` — необязательно; нет — начало звонка: `panic` = `start_panic` сценария, остальное
  пустое. Поля — как в ответе (ниже); `panic` — 0…3, списки — до 50 ключей.
- `action` (этап 2, по умолчанию `question`):

| action | что делает оператор | что нужно |
|---|---|---|
| `question` | задаёт вопрос | ровно одно: `text` (свой вопрос, 1…500 символов — режим «Сложно»), `questionnaire_id` + `key` (вопрос карты; карта не та — вопрос идёт её текстом, как свой; ключа нет — 422) или `distractor` (этап 3: лишний вопрос шага — `distractors[].key` сценария; нет такого — 422) |
| `calm` | «Успокоить» | `kind`: `reason` — просьба с причиной, `soft` — поддержка без просьбы, `order` — «Успокойтесь!» |
| `hold` | «Я вас слышу, записываю» | — |
| `silence` | молчит дольше паузы (веб: 18 с без действий, пока заявитель не говорит) | — |
| `advice` | даёт совет | `kind` — `advice[].key` сценария; нет такого — 422 |
| `escalate` | — (время вышло) | веб присылает, когда подошёл срок `escalation` сценария |

- `address` (этап 3, необязательно) — адрес из карточки оператора: `street`, `house`,
  `building` (корпус), `apartment`, строки до 200 символов. По нему заявитель отвечает на
  повтор адреса (`confirm_address`), в том числе когда свой вопрос в режиме «Сложно» узнан
  как повтор. Нет поля — карточка пуста.

## Правила заявителя

Паника 0…3. С 2 — панический вариант ответа, факт не засчитан. 3 — истерика: выше порога
истерии заявитель не слышит вопросов и советов (IAED).

- **Вопрос в истерике** — `unheard`: реплика из `reactions.hysteria` по кругу; вопрос **не**
  считается заданным (`asked` не меняется), паника та же.
- **Вопрос ниже истерики**: заявитель отвечает в том состоянии, в каком его спросили
  (вариант по панике до вопроса); затем вопрос по шагу снижает панику на 1, вопрос раньше
  адреса — повышает (ниже). Спокойный ответ даёт факт (`facts`). Повтор вопроса, на который
  уже был спокойный ответ, — `repeated`, `reactions.repeat`, паника +1. Повтор после
  панического ответа — уточнение: отвечает по нынешней панике, без наказания.
- **Шаги опроса** (этап 3). У вопроса карты — шаг 1–5 (`questionnaire.schema.json`):
  1 — адрес, 2 — номер для обратной связи, 3 — что случилось, 4 — угроза людям, 5 — детали и
  доступ (APCO/NENA). Вопрос шагов 2–5, пока адрес не прозвучал (`address` нет в `asked`), —
  `early`: заявитель отвечает, но паника +1 — без адреса помощь не отправить. Вопросы шага 1 —
  в любое время. Прежнее правило `late` (вопрос позже своего места в карте) заменено шагом.
- **Повтор адреса вслух** (этап 3, вопрос `confirm_address`) — ответ по адресу из карточки
  (`address` запроса), реплики — `address_confirmation` сценария. Сверяются улица и те из
  дома, корпуса, квартиры, что есть в адресе сценария (`address_components_match`, как в
  оценке):
  - в истерике — `unheard`;
  - в карточке нет улицы — `unconfirmed`, `empty`: «Я же говорю…» — адрес ещё раз;
  - улица записана и паника 2 — `unconfirmed`, реплика `panic`: в панике «да» ненадёжно;
  - улица не та — `corrected`, `wrong_street` (ловушка «Дубининская»); дом, корпус или
    квартира не те или не записаны — `corrected`, `wrong_details`; паника та же;
  - всё сходится — `confirmed`, `ok`: паника −1, `confirmed` = true.
  Повтор адреса в `asked` не входит: его можно повторить после исправления карточки.
  В вариантах шага 1 повтор появляется только после записи улицы: «Проверю адрес: ….
  Верно?». До этого на шаге три варианта. Свой вопрос в режиме «Сложно» доступен всегда.
- **Лишний вопрос** (этап 3, `distractor`) — `irrelevant`: реплика `distractors[].reply`
  сценария, паника +1; в истерике — `unheard`.
- **Свой вопрос словами** («Сложно») сопоставляется с картой по синонимам; не распознан —
  `not_understood` (или `irrelevant` с `reactions.irrelevant`, если это вопрос другой карты),
  паника +1.
- **`calm` / `reason`** — метод повторяющейся настойчивости: из истерики — `calming`, паника 2;
  с 2 — паника 1, и если адреса ещё нет, заявитель сразу называет адрес спокойно (просьба
  просила именно его); иначе `calmed`. Повторять подряд, пока паника не ниже 2.
- **`calm` / `soft`** — ниже истерики паника −1; в истерике не слышно.
- **`calm` / `order`** — «Успокойтесь!» злит: паника +1 (в истерике выше некуда), `calm_order` +1.
- **`hold`** — `reactions.hold`, паника та же; в истерике не слышно.
- **`silence`** — `reactions.pause` (первая, затем следующая), `pauses` +1,
  `silence_streak` +1. Первый переспрос подряд не повышает панику; второй и каждый
  следующий подряд — паника +1. Любое действие оператора (`question`, `calm`, `hold`,
  `advice`), даже не услышанное в истерике, обнуляет `silence_streak`; автоматическое
  ухудшение `escalate` его не обнуляет. Общий счётчик `pauses`, штраф за паузы и пометка
  «навредило» в разборе сохраняются. Экран дописывает изменение паники только при её изменении.
- **`advice`** — в истерике не слышно; иначе ответ совета, паника −1; если ситуация уже
  ухудшилась и это совет `escalation.advice` — `escalation_handled`.
- **`escalate`** — один раз: `escalation.text`, паника +1 (не ниже 2), `escalated`. Повторно
  или без `escalation` в сценарии — `noop` с пустой репликой.

## Ответ 200

```json
{
  "state": {
    "panic": 2, "asked": [], "facts": [], "pauses": 0, "silence_streak": 0, "unheard": 1,
    "calm_reason": 1, "calm_order": 0, "escalated": false,
    "escalation_handled": false, "advice": [], "confirmed": false
  },
  "reply": {
    "outcome": "calming",
    "text": "Я... хорошо... я пытаюсь. Там дым, понимаете?",
    "question_key": null,
    "variant": null,
    "voice": "fire_apartment_smoke/calming",
    "mark": { "kind": "good", "text": "Просьба с причиной сработала, но паника ещё высокая. Повторите её подряд." }
  },
  "progress": { "step": 1, "done": [] }
}
```

- `outcome`: `correct`, `early`, `repeated`, `irrelevant`, `not_understood`, `no_incident`,
  `unheard`, `calming`, `calmed`, `order`, `hold`, `silence`, `advice`, `escalation`,
  `confirmed`, `corrected`, `unconfirmed`, `noop`.
- `variant`: `calm` или `panic` — какой вариант ответа карты прозвучал; `null` для реплик вне
  карты. Уровень паники обучаемому цифрой не показывается — только тоном голоса и реплик.
- `voice` — голосовой файл реплики (`contracts/operator/voice.md`); `null` — реплики нет.
- `question_key` — вопрос карты (или `confirm_address`), на который ответил заявитель;
  у лишнего вопроса — его `distractors[].key`.
- `mark` (этап 3) — пометка для разбора звонка: `kind` — `good` (помогло), `bad`
  (навредило), `warn` (внимание), `info` (событие); `text` — почему, по-русски. Пометки
  считает `apps/api/app/operator/review.py`; на экране они видны в разборе после
  «сохранить» (`contracts/operator/evaluation.md`, журнал звонка), а «Паника выросла /
  снизилась» экран дописывает сам по панике до и после. `null` — без пометки.
- `state.confirmed` (этап 3) — адрес подтверждён повтором: заявитель согласился с адресом
  карточки.
- `state.silence_streak` — число переспросов «Алло?» подряд без действия оператора,
  целое 0…1000; по умолчанию 0, в том числе у ранее сохранённых состояний.
- `progress` (этап 3) — шаги опроса после действия: `step` — текущий шаг (первый не
  пройденный; все пройдены — 5), `done` — пройденные. Шаг пройден, когда заявитель услышал
  все вопросы карты этого шага (`asked`), повтор адреса — когда `confirmed`. Лишние вопросы
  шаг не проходят. У сценария без опросной карты — `{ "step": 1, "done": [] }`.

## Первая реплика

Необязательное поле сценария `opening` звучит само, когда оператор принял вызов; её голос —
`<scenario_id>/opening`. Экран берёт текст из бандла, запроса не нужно.

## Окно разговора (правки приёмки 4.4)

Учебное окно располагается поверх карточки без затемнения. При первом открытии —
по центру экрана, размер 760×340 пикселей с ограничением по экрану. Заголовок переносит окно мышью, пером или пальцем;
кнопки заголовка перетаскивание не начинают. Ручка «Переместить окно разговора» двигает
его стрелками на 20 пикселей. При движении и изменении размера браузера окно остаётся
целиком в экране. Угол «Изменить размер окна разговора» меняет ширину и высоту мышью,
пером или пальцем, а в фокусе — стрелками на 20 пикселей. Минимум — 600×320 пикселей
или доступный размер экрана. «В центр» возвращает окно в центр. Положение, размер и
свёрнутость сохраняются в браузере; новый звонок их сохраняет.
Без доступа к хранилищу окно работает до конца сеанса. Сворачивание оставляет заголовок,
сохраняет звук, таймеры, состояние и журнал. Размер раскрытого окна сохраняется при
сворачивании. Карточка занимает всю высоту правой колонки, без запаса под разговор;
при необходимости её можно открыть, переместив или свернув окно разговора.

Меню приёмов располагаются в пределах экрана: вниз у верхнего края, вверх у нижнего.
Проводник для цели внутри разговора находится над окном, а если места нет — под ним;
он не закрывает разговор и не перехватывает его щелчки. Слой разговора выше карточки,
ниже проводника и модальных окон. «?» открывает часть справки о разговоре.
Если разговор растянут почти на весь экран и снаружи места нет, проводник прижимается
к границе экрана: его текст и кнопка скрытия остаются видимыми.
