# Форматы артефактов D1

Все данные в репозитории синтетические либо из предоставленного классификатора. JSON UTF-8.
Паролей и password_hash в `data/seed/demo_users.json` нет; mock берёт `DEMO_PASSWORD` из env.

| Путь | Содержание / пример |
|---|---|

| `data/phonebook.json` | `Service[]` из OpenAPI; 6 служб ДДС и Система-112, уникальные 3-значные номера и городские номера `phone` (`+7495000…`, с 17.10) |
| `data/templates/*.json` | один Scenario по scenario.schema.json |
| `data/golden_scenarios/*.json` | `{id, description, scenario, current, events, calls, settings, expected}` |
| `data/packs/*.json` | `{id, title, status, origin, scenario_ids}`; статусы draft/approved/retired |
| `data/seed/demo_users.json` | User[]; admin, teacher, trainee01..05 |
| `data/seed/workstations.json` | `{id: int, number: int}[]`, 1..23 |
| `data/seed/settings.json` | Settings из OpenAPI, нормативы 30/180, семь весов |
| `data/voices/manifest.json` | `{version, status, phrases: string[], profiles: {id, files, status}[]}` |

`services.category`: fire/police/medical/gas/utilities/lift — службы ДДС; `system112` —
Система-112 (`id`, `code`, `phone_ext` = `112`, с 16.10, GP-04). Система-112 — адресат
звонка в справочнике связи (доклад об изменении обстановки, памятка ДДС, с. 32; скорая через
112), а не служба ДДС: учебных бригад у неё нет, место обучаемого, учётную запись и сценарий на
неё не назначают. `[ASSUMPTION]` GKH=105, MOSLIFT=106 — учебные внутренние номера, не реальные
телефоны экстренных служб. Городские номера `phone` (+7 (495) 000-…) тоже учебные: в справочнике
телефона ДДС они стоят рядом с коротким, набранный городской соединяет с той же службой.

`routing_rules.condition` = `{kind: 'classifier_column', column: 14, label: '…'}`.
Каждая колонка исходного CSV сохраняется отдельно вместе с текстом условия. Пусто и «нет
реагирования» не создают правило. Не объединять все условия в безусловный список служб!
Интерпретатор условий по признакам сценария — T-026. Парсер сохраняет 1281 уникальный тип,
не включает строки заголовков групп. `main_service_code` сохраняет исходные MCHS/Police/…;
соответствия: MCHS→101, Police→102, AMBULANCE→103, MOSGAZ→104, GKH→GKH, MOSLIFT→MOSLIFT.

Golden: события — CardEvent с дополнительными `server_ts`, `clock_offset_ms`;
звонок — `{id, service_id, phone_ext, started_at, answered_at, ended_at, transcript}`.
`expected = {criteria: {criterion_key: score}, total, tolerance}`, score/total 0..1.
Проверка: `abs(actual-expected) <= tolerance`. Уровни 1..4 и осложнения заданы явно;
значения ожидаемых оценок — контрольные примеры, проверка алгоритмов станет T-006.

Голоса: `files` содержит `{phrase_id: 'listen'|'accepted', path, sha256, duration_ms}`.
Пока `status=pending`, файл не существует и клиент не должен его запрашивать.
Происхождение, модель и лицензия фиксируются в `data/voices/README.md`; отсутствие голоса
должно оставлять доступным набор/завершение звонка (T-014).

Улицы: `streets.csv.gz` с колонками `name,okrug,district,source`, UTF-8, gzip mtime=0.
Это отдельный справочник для T-021; исходные адреса golden не считаются полным справочником Москвы.

## Загрузка T-007

`python -m app.seed` загружает данные одной транзакцией после Alembic 0001.
Повторный запуск вставляет только отсутствующие записи: существующие пароли, нормативы,
пользователи и отредактированные сценарии сохраняются. Синхронизация изменений исходных
файлов с уже работающей БД — отдельная операция, seed её не имитирует.
Параллельные seed сериализуются advisory lock; routing_rules и улицы имеют стабильные UUIDv5
из исходных записей. Требование UUIDv4 относится к новым HTTP-ресурсам.

**[ASSUMPTION T-007]** template traffic и golden case-01 используют один UUID при разных
весах. Для строки scenarios и стартового пакета приоритет имеет golden. Оба исходника
сохранены без изменений в seed_artifacts. Остальные golden не создают учебные события,
звонки и оценки: эти действия должны появляться при реальном прохождении.

В поставке D1 `streets.csv.gz` отсутствует, voices имеет `status=pending`. Seed загружает
манифест, сообщает об отсутствии улиц/аудио, не объявляет эти данные готовыми. Если справочник
улиц добавлен, его строки валидируются и загружаются идемпотентно.

## Сгенерированные сценарии и рекомендации (GP-14, 16.10)

Генератор (`apps/api/app/seed/generator.py`) выдаёт файл формата 2
(`scenario-file.schema.json`) целиком: карточка, эталон, бригады и план до завершения,
события-ловушки, варианты частей. Код — `gen-<служба>-<уровень>-<8 hex>`, версия 1, поле
`id` не задаётся. Результат проверяется той же схемой и связностью, что файлы
`data/scenarios`; негодный не записывается.

Записанный сценарий — `Scenario` с `status = draft`, `origin = template` (шаблон) или
`llm` (повествование карточки от модели, `scenario-narrative.schema.json`), без автора; он
входит в общий пакет `ScenarioPack` с id = uuid5(URL, «arm112:pack:generated»), `created_by
= null`. Черновик этого пакета тренировка выдаёт до утверждения; преподаватель утверждает
его операцией пакета (`approvePack`) или отклоняет (`retireScenario`, статус `retired` —
больше не выдаётся).

`TraineeProgress.advice` (`GET /progress`) — `Advice`: по последним пяти оценённым
закрытым карточкам — до двух слабых критериев оценки (`focus`: ключ критерия, название,
совет) и следующий шаг (`next_step` — текущая ступень пути, `next` — фраза). Нет оценённых
карточек — `null`. Поле необязательное, прежние клиенты его не читают.

## Прошлая рекомендация и повтор незачтённого сценария (TC-11, 16.10)

`Advice.previous` — `PreviousAdvice`: рекомендация, какой она была до новой попытки (до двух
слабых критериев по пяти оценённым карточкам перед последней), и отметка последней оценённой
закрытой карточки (`card_id`) у каждого слабого места (`AdviceCheck.status`): `done` — критерий
в новой попытке проверялся и получил полный балл, `not_done` — балл ниже полного, `unchecked` —
сценарий новой попытки этот критерий не проверял (в пояснении оценщика «не предусмотрен», «не
обязателен», «не заданы» или «0 из 0» — как «не требуется» в разборе обучаемого). Оценённая
карточка одна или прошлых слабых мест не было — `null`.

`TraineeProgress.repeats` — `ScenarioRepeat[]`: сценарии, по которым у обучаемого есть
незачтённая попытка (занятие или тренировка; «зачтено» — как в ступенях, `evalcore/progress.py`,
балл преподавателя главнее). `was` — балл первой незачтённой попытки, `now` — последней попытки
после неё (`null` — повтора не было), `passed` — эта последняя попытка зачтена. В список идут
только сценарии, которые тренировка может выдать: не упражнение, не параллельная смена и не
связка 112, статус выдачи (`approved` или черновик пакета генерации), полный план докладов,
открытая ступень (`step` — по уровню сценария, 2–4). Порядок: сначала не исправленные, затем
новые первыми; не больше трёх. Прежние версии сценария (`retired`) в повтор не идут.

`POST /practice?scenario_id=…` — тренировка с этим сценарием (на ступени 4 вторая карточка —
как обычно). Сценария нет в `repeats` — 409 `repeat_unavailable`; `step`, не совпавшая со
ступенью сценария, — 422. Оба поля и параметр необязательные, прежние клиенты их не читают.
