# DT-08. «Что было дальше» — исход после карточки

- Исполнитель: dwots
- День: 5
- Зависит от: DT-02
- Issue и статус: #71

## Зачем

Диспетчеры почти не получают сведений об исходе вызова (77,7 % — ни одного за месяц). Исход показывает, ради чего спешить.

## Что сделать

- После закрытия карточки — короткий исход: что случилось с людьми, как повлияли время и решения обучаемого.
- Исход задаётся в сценарии; без исхода блок не показывается.

## Готово, когда (DoD)

- [x] Исход есть у всех сценариев тренировки (data/practice).
- [x] Показан в разборе; тест на выбор исхода.
- [x] чек-лист PR из CONTRIBUTING.md

## Заметки

- Исход — блок `outcome` в каждом `data/practice/*.json`: `people` (полный ход: что стало с
  людьми), `late` (чем обернулась задержка), `why` (только с источником: UL FSRI, Larsen 1993),
  `complication` (осложнение: что было на самом деле).
- Выбор — `apps/web/src/arm/results/outcome.ts`: уровень берётся из номера карточки
  `70005{происшествие}{служба}{уровень}` (`seed/practice.py: card_number`), факты — из оценки:
  `reaction_time` < 1 → абзац о задержке, `status_flow` < 1 → абзац о статусах.
- Образ web собирается без `data/`, поэтому в вебе копия `arm/results/outcomes.json`, её сверяет
  `outcome.test.ts` (`UPDATE_PRACTICE_OUTCOMES=1 pnpm test` — пересобрать). Как у «Оператора 112».
- Контракт и сервер не менялись. Обучающее упражнение ступени 1 (карточки 70004…, не из
  `data/practice`) исхода не получает — блок не показывается.
