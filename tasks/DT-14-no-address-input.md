# DT-14. Убрать ручной ввод адреса у ДДС, адрес проверять в комментарии

- Исполнитель: brikkerdev
- День: 7–8
- Зависит от: — (согласовано с DT-04: эталон адреса связки — уточнённый адрес)
- Issue и статус: #81

## Зачем

Диспетчер ДДС учится своему навыку, а не навыку оператора 112: в АРМ-112 адрес у ДДС только
для чтения, уточнённый адрес он пишет в комментарий к статусу. Решение 04.10 в
[decisions](../docs/decisions.md) «Адрес диспетчер ДДС не вводит», проверено капитаном 07.10.

## Что сделать

- Убрать из карточки АРМ ДДС поле «Адрес — ввод диспетчера»; адрес только для чтения.
  Модуль «Оператор 112» не трогать.
- Критерий «Адрес» проверяет комментарии к статусам: верный адрес карточки можно не повторять,
  ошибка — искажённый адрес («Дубининская» вместо «Дубнинская»); уточнённый адрес обязателен.
- `field_change` адреса и `CardCurrent.address` оставить в схемах для старых событий с пометкой
  «не используется АРМ ДДС с 08.10».
- Убрать ввод адреса из проводника, подсказок «?», совета разбора.
- Поправить тесты, e2e и документацию сдачи.

## Заметки

- Как считается: адрес ищется во всех комментариях к статусам, а не только в последнем.
  Уточнённый адрес — когда `reference.expected_address` отличается от адреса карточки
  (`evalcore.criteria.address_clarified`); так же его задаёт DT-04 для связки 112 → ДДС.
  У уточнённого адреса город обязателен, только если уточнился и он.
- Другая улица — слово с заглавной буквы рядом с типом улицы или отличие от эталона на
  одну-две буквы (`evalcore.address.other_street`). Справочник улиц не используется: в нём
  есть обычные слова («Новая»), их нельзя считать адресом.
- «Ключевые сведения» комментария требуют адрес только уточнённый: иначе верный адрес карточки
  пришлось бы переписывать, а решение 04.10 этого не требует.
- Не здесь: адрес в докладе по телефону — #78, в повторе расчёта — #80. ИИ-судья
  (`worker/judging.py`) по-прежнему ищет адрес в комментарии всегда.
