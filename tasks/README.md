её из клонов сокомандников не правят.

## Где работать

- База — `dev` (решение капитана, 02.10). Доска лежит в `dev`, перед началом задачи: `git pull` на `dev`.
- Своя ветка на задачу: `feature/dt-NN-короткое-имя` от свежего `dev`, например `feature/dt-07-guide-pointer`.
  Ветку, начатую от `main`, догоняем: `git merge dev`.
- Готовую задачу вливаем в `dev` через PR с `Closes #NN`. Пока ветка по умолчанию на GitHub — `main`,
  PR в `dev` issue сам не закрывает: после влития закрыть вручную (`gh issue close NN`).
- `dev` в `main` вливает капитан после проверки и показа (DT-12, DT-13).

## Как пользоваться (людям и агентам)

Задачи ведём в GitHub Issues: метка «диспетчер служб», веха
«Диспетчер служб — до 15.10».
Статус живёт только в issue; в файлах `tasks/DT-NN-*.md` — подробности, DoD и заметки.

| Статус | В issue |
| --- | --- |
| todo | открыт, без метки «в работе» |
| in_progress | метка «в работе», в Assignees — исполнитель |
| blocked | метка «заблокировано» и комментарий с причиной |
| done | PR влит в `dev`, issue закрыт |

1. Взял задачу — `gh issue edit NN --add-label "в работе" --add-assignee @me`. Чужую задачу «в работе» не бери.
2. Новая задача: файл `tasks/DT-NN-короткое-имя.md` по образцу [_template.md](_template.md) и issue с меткой
   «диспетчер служб» и вехой этапа (`gh issue create … --label "диспетчер служб" --milestone "Диспетчер служб — до 15.10"`).
   Агент заводит задачу, только если её поставил человек или она нужна, чтобы закрыть уже начатую.
3. Готово, когда выполнен DoD из файла задачи и чек-лист PR из [CONTRIBUTING.md](../CONTRIBUTING.md);
   в описании PR — `Closes #NN`.
4. Что не получилось — комментарий в issue и метка «заблокировано».
5. Вопрос вкуса (как выглядит, как ощущается) агент не решает сам: пишет его в issue и ставит «заблокировано».
