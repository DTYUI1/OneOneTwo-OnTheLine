# Как читать архив замеров

В отчётах от 25.09.2026 строка «Запись событий в БД» до добавления `pgbench`
на самом деле измеряла **полный путь через API**: 23 клиента отправляли по одному
событию за запрос. Её отметка «НЕТ» не является результатом NFR-8 для самой
PostgreSQL. Прямой замер БД приведён отдельно в разделе `pgbench` внизу отчёта.

В тех же отчётах поле `per_card_s` и фраза «в среднем ... на карточку» означали
`last_s / finished`, где `last_s` — время от начала опроса до последней из шести
наблюдаемых ИИ-оценок. Это **не средняя задержка отдельной карточки**. Для
сравнения используйте `last_s` и долю завершённых оценок; часть оценок могла
завершиться до начала опроса.

Начиная с замера 26.09.2026 после #48, отчёт называет API-путь диагностикой,
показывает `last_s` без слова «среднее» и сохраняет прямой результат `pgbench`
в `results.json` как `db_writes_per_s`.
