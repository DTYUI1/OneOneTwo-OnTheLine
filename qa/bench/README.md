# Замеры C-09 одной командой

Нагрузочные замеры для матрицы требований и презентации. Скрипт поднимает **отдельный**
Compose-проект `arm112-bench` (свои тома и порты 44080/44443), создаёт 100 тестовых учёток,
гоняет нагрузку через nginx (HTTPS/WSS) как настоящие клиенты, пишет отчёт и гасит стенд.
Рабочий стенд `arm112` и его данные не трогаются.

| Что меряем | Цель (PRD) | Как |
|---|---|---|
| Класс 23 АРМ одновременно | 23 АРМ (S10) | 23 обучаемых: вход, WebSocket, выдача по 3 карточки, deliver → open → статусы |
| Запись в БД | ≥ 100 записей/с (NFR-8) | `pgbench`: строка в отдельной транзакции, 8 соединений, 15 с; дополнительно — всплеск правок через API (23 клиента, у каждого по событию за раз — упирается в задержку запроса, а не в БД) |
| Отчёт по занятию | ≤ 30 с (FR-6.4) | JSON, CSV и аналитика по всем карточкам класса |
| 100 пользователей, 20 активных карточек | p95 отклика ≤ 2 с (NFR-4) | 100 учёток онлайн с WebSocket, 80 опрашивают список карточек, 20 работают |
| Лаг live-доски | — | действие обучаемого → `card.updated` у преподавателя |
| ИИ-оценка комментария (`--llm`) | асинхронно (NFR-5) | время до готового ИИ-слоя по 6 карточкам через worker → llama.cpp |

## Что нужно на машине

- Docker (Linux — Engine, Windows — Docker Desktop с WSL2; команды запускать в терминале WSL
  Ubuntu), git. Свободно ≥ 6 ГБ на диске, ОЗУ ≥ 8 ГБ (для `--llm` лучше 16 ГБ).
- Интернет — только для сборки образов при первом запуске.
- На время замера закрыть браузеры, IDE и другие стенды: цифры должны отражать машину.

## Запуск

```sh
git pull                                  # ветка main
bash qa/bench/run.sh                      # без ИИ, ~10–15 мин
bash qa/bench/run.sh --llm --skip-crowd   # с ИИ-судьёй, ещё ~15–20 мин
```

Для `--llm` нужен файл модели `models/qwen3-4b-instruct-2507-q4_k_m.gguf` (2,5 ГБ, Apache-2.0,
`unsloth/Qwen3-4B-Instruct-2507-GGUF`, файл `Qwen3-4B-Instruct-2507-Q4_K_M.gguf`). Скопировать с
первого ноутбука или скачать и сверить хеш:

```sh
mkdir -p models
curl -L -o models/qwen3-4b-instruct-2507-q4_k_m.gguf \
  https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF/resolve/main/Qwen3-4B-Instruct-2507-Q4_K_M.gguf
sha256sum models/qwen3-4b-instruct-2507-q4_k_m.gguf
# ожидается 3605803b982cb64aead44f6c1b2ae36e3acdb41d8e46c8a94c6533bc4c67e597
```

Образ llama.cpp скрипт при необходимости скачает сам по зафиксированному digest.

## Результат

`qa/bench/results/<имя-машины>-<время>/report.md` — таблица «цель → результат → выполнено»
и задержки по операциям; `results.json` — те же данные для документации. При сбое рядом
появится `compose-<имя-машины>.log`.

Отправить капитану любым способом:

```sh
git checkout -b bench/$(uname -n)
git add qa/bench/results && git commit -m "Замеры C-09 на $(uname -n)" && git push -u origin HEAD
```

или просто прислать `report.md` в Telegram.

## Если запускает агент (Codex и т. п.)

Одна задача, без правок кода: «Выполни `bash qa/bench/run.sh`, затем
`bash qa/bench/run.sh --llm --skip-crowd`. Ничего не меняй в репозитории. Пришли содержимое
обоих `qa/bench/results/*/report.md`». Если скрипт упал — прислать его вывод и
`compose-*.log`, не чинить самому.

## Флаги

- `--quick` — короткая отладка на слабой машине (1 карточка, 30 пользователей);
- `--no-build` — взять готовые образы `arm112-api:bench` и `arm112-web:bench`;
- `--keep` — не гасить стенд после замера (посмотреть руками на https://localhost:44443);
- остальное уходит в `bench.py`: `--cards 5`, `--burst 60`, `--workstations 10`, `--skip-crowd`.

Не входит сюда: обрыв сети на 30 с (e2e `realtime-recovery` и очередь в IndexedDB), ручная
проверка Яндекс.Браузера и Windows.
