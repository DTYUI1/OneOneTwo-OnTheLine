# АРМ диспетчера ДДС (`apps/web/src/arm/`)

Реестр происшествий и карточка — копия интерфейса со скриншотов `docs/screenshots/arm_dds/`
и `card_112/`. Зона Dwots, кроме `softphone/` и `alert/`.

## Клавиатура и фокус (D-03)

| Где            | Клавиши                                                        |
| -------------- | -------------------------------------------------------------- |
| Реестр         | Tab — к строкам; ↑/↓ — соседняя строка; Enter/пробел — открыть |
| Карточка, окна | фокус переходит в окно; Tab не уходит за окно; Esc — закрыть   |
| После закрытия | фокус возвращается на строку, с которой открывали карточку     |
| Подсказка «?»  | Enter — открыть; Esc — закрыть подсказку (карточка остаётся)   |
| Справка окна   | F1 или «?» в углу шапки; ←/→ — части по порядку; Esc — закрыть |

Реестр показывает новые происшествия сверху, старые снизу (`newestFirst` в `cardModel.ts`,
замечание капитана 28.09); API отдаёт карточки по появлению, вкладки идут тоже по появлению.

Карточка открывается отдельной страницей `/app/arm/cards/<id>`; прямой адрес
сохраняется после входа и перезагрузки. При возврате восстанавливаются поиск,
прокрутка и фокус строки. Вспомогательные окна используют `Dialog.tsx`.
Строка в фокусе обведена рамкой цвета активного элемента.

## Справка по окну (`help/`, механизм — `shared/help/`)

Для занятия с `hints_level >= 1` в правом углу шапки есть одна «?» (и F1).
Она объясняет текущий экран: список, открытую карточку, «Мои результаты»,
«Справку». Видимые части обводятся и
нумеруются по порядку чтения; наведение мыши (как у всплывающей подсказки), щелчок или
«Далее» / «Назад» показывают объяснение части рядом с ней — что это, как работать, что
важно. Пока справка открыта, щелчки до окна не доходят; время по карточке идёт. Та же «?»
выключает справку; Esc закрывает только справку, не карточку.

- Экран объявляет свою справку хуком `useHelpGuide(guide, onOpen?)`.
  При смене страницы прежняя справка закрывается. Нет справки у экрана — нет и «?».
- Часть окна помечается атрибутом `data-help="<ключ>"`, тексты и порядок — `help/topics.ts`.
  Номер получает только то, что сейчас видно: раскрытая панель телефона закрывает часть
  карточки — закрытые части не нумеруются, а её разделы нумеруются.
- Открытие справки по карточке пишется в журнал как `hint_open` с `hint_id: "help"`;
  в «Истории статусов» такие события не показываются.

## Узкий экран и масштаб

Проверено на 390×844 (телефон), 768×1024 (планшет) и 750×500 (масштаб браузера 200 %):
страница вбок не уезжает.

- До 600 px в реестре скрыты колонки «Дата» и «Постр.»; широкая таблица прокручивается
  внутри своего блока.
- Карточка до 600 px — в одну колонку, телефоны и шапка переносятся по строкам,
  окно занимает весь экран.

Мобильное требование не отменено. На узком экране работает всё то же, что на широком.
Не поддержаны (нет ни на каком экране):

- пагинация «Записей на странице» и «уведомления» (arm_dds/02) — реестр показывает все
  карточки обучаемого, их за занятие десятки;
- колонки «Связи», «Опер.», «АРМ» — таких данных в карточке API нет;
- «Отключение», «записи звонков», «список SMS», «просмотр», «дополнение», ЧП и правка
  класса в шапке карточки (arm_dds/06) — вне скоупа тренажёра по Q&A от 16.09;
- «расширенный по параметрам» поиск — есть один поиск по номеру, типу, адресу и тексту.

Шапка приложения (часы, «Выйти») — `shared/Shell.tsx`, зона капитана: на 390 px кнопка
«Выйти» уходит за край (записано в `docs/DWOTS_FINDINGS.md`).

## Отличия от скриншотов, оставленные намеренно

- Колонка «Реакция» в реестре и таймер в шапке карточки — учебные: время по методике I-TIME.
- Блок «Адрес — ввод диспетчера» в карточке — ручной ввод адреса (D-03), на скриншотах
  адрес вводится в другой форме.
- «Тренировка», проводник в карточке и «Порядок работы» в шапке — учебные функции (27.09),
  см. ниже.
- «Мои результаты», «Справка», подсказки «?» и справка по окну — учебные функции
  (T-031, D-03, FR-1.6).

## Параллельная работа (27.09, Q11 / FR-1.5)

- **Вкладки происшествий** (`IncidentTabs.tsx`, логика — `tabsModel.ts`) над реестром и
  карточкой — как вкладки браузера реального АРМ (`arm_dds/04`, `07`): «Список
  происшествий» и каждое происшествие в работе. Появление вкладки — показ карточки:
  отсюда уходит `deliver` (с него 30 с реакции) и звучит короткий сигнал (`signals.ts`).
  На вкладке — время реакции или обработки без ожидания бригады; новая подсвечена.
- **Бригада звонит сама** (`CardTraining.incoming`): вкладка мигает «Бригада вызывает»,
  в полосе телефона карточки — «Ответить». История вызовов (`callbacks`) даёт в
  разборе «Бригада ждала ответа» (`callbacks.ts`, ориентир 30 с, без балла).
- **Переход посреди разговора** спрашивает и кладёт трубку (`callGuard.ts`,
  `SwitchCallDialog.tsx`); черновик формы статуса сохраняется по карточке.
- **Предупреждение** (`ParallelNotice.tsx`): если `min(parallel_cards, уровень) > 1`,
  при входе — окно «Карточки будут приходить параллельно» и строка над реестром.

## Подсказки орфографии (28.09)

`useSpellingHints.ts` и `spellingModel.ts`: если в снимке занятия включена галочка
«Подсказки орфографии» (`spelling_hints`), текст комментария через 0,6 с после паузы в наборе
уходит в `POST /spelling/check`. Над полями формы — строка «Проверьте написание»: слово с
ошибкой подчёркнуто волной, рядом кнопки вариантов; нажатие заменяет слово. Ответ,
пришедший после правки, показывается, только если слово ещё стоит на своём месте. Без ответа
сервера подсказок просто нет — работа с карточкой не блокируется. Грамотность и ключевые
сведения оцениваются всегда, если их вес есть в занятии; галочка влияет только на подсказки.

## Тренировка и порядок работы (`practice/`, `shared/workflow.ts`)

- **«Порядок работы»** — кнопка в шапке у обучаемого и блок в приветствии: восемь шагов
  от поступления карточки до «Работы завершены». Текст шагов один на все места —
  `shared/workflow.ts`.
- **«Тренировка»** в списке происшествий — `POST /practice`: личное занятие
  (`Session.kind = "practice"`) с обучающим упражнением своей службы. Преподаватель его не
  видит. Запускать можно сколько угодно раз; новый запуск прерывает прежнюю тренировку.
  Во время занятия преподавателя — 409 `lesson_running`.
- **Проводник** (`practice/TutorPanel.tsx`) — полоса над карточкой тренировки: «Шаг N из 8»
  и что сделать. Шаг выводится из статуса и журнала карточки (`practice/tutor.ts`), поэтому
  переживает перезагрузку. Ошибку не блокирует: пропущенный шаг (например, доклад службе)
  остаётся напоминанием «Не забудьте: …».
- В упражнении бригада докладывает только после статуса диспетчера (`requires_state`),
  панель бригад пишет, какого статуса она ждёт — `softphone/README.md`.
