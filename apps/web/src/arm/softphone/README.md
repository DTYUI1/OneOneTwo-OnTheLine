# Brikkerdev · T-014

Своя зона: эта папка; публичный вход index.ts. Первая задача: idle → dialing → ringing →
talking → ended, набор 3 цифр, гудки Web Audio. Доклад службе — голосом (DT-05, 06.10),
запасной путь — варианты ответа (`report.ts`); см. «Доклад голосом» в конце.
Телефоны — GET /services, типы Call/CardEvent — из api-client. События через
`useSession().realtime.enqueue`; обновления через `realtime.subscribe`, cleanup обязателен.
Реплики Piper собраны и лежат в `data/voices/` (B-01); манифест в статусе `ready`.
Общие файлы shared и зависимости — PR/тикет капитану, не второй клиент внутри софтфона.

## Регрессии жизненного цикла звонка

`reviewHooks.test.ts` запускается Vitest, но монтирует настоящие React-хуки и `Softphone`
в Chromium через уже имеющийся Playwright. Подменяются только сеть/очередь событий и
аудиоустройство; эффекты, отмена, переходы модели и DOM-кнопки выполняются в браузере.
Локальный Vite поднимается и закрывается самим тестом, API и БД не нужны.

Из корня репозитория:

```sh
pnpm exec playwright install chromium
pnpm --filter @112/web exec vitest run src/arm/softphone src/arm/pickup.test.ts
```

Проверяются отмена очереди при отбое/размонтировании, независимость ручного повтора,
замена звуковой и текстовой реплики, опоздавшая проверка вводной и подтверждение выезда
только по серверной выдаче. `SavedTalk.earlier` хранит исходные фразы голосового доклада:
при снятии своей линии они снова уходят в `voice-report.earlier`, в чужой звонок не попадают.
Опоздавшее распознавание отбрасывается и после возвращения к тому же `callId`:
поколение меняется при удержании, смене линии и размонтировании. Машина меняет версию
синхронно до React commit: сохранённый `callId` в `ended` не разрешает поздний результат.
Регрессия нажимает настоящие кнопки записи/правки `Softphone`, затем удерживает и возвращает
тот же звонок либо кладёт трубку/получает серверный отбой. `ArmPage` проверяется внутри
`MemoryRouter`: переход в справку отменяет задержанный resume, собственный переход resume
к своей карточке не отменяет передачу снимка.

Ту же браузерную suite можно выполнить в Firefox (браузер должен быть установлен):

```sh
PHONE_REVIEW_BROWSER=firefox pnpm --filter @112/web exec vitest run src/arm/softphone/reviewHooks.test.ts
```

Входящий доклад через hold/resume проверяется отдельно: после конца аудио кнопка «Принял»
остаётся доступной дольше таймера тишины и отправляет `report_confirmed` с исходным входящим
`call_id`, не с идентификатором предыдущего исходящего звонка, в котором выдали доклад.

Передача удержанной линии проверяется настоящими `ArmPage`, `useHold`, `Softphone` и
`ControlTalk`: снимок остаётся в `sessionStorage`, пока получатель не готов и не принял
разговор. До этого `call_resume` не отправляется; TTL, отмена, чужая карточка и ошибка
чтения `GET /calls/{id}` оставляют удержание доступным для повторной попытки. Серверный
`ended` запрещает восстановление, локальный предел удержания продолжает действовать.
Успешный локальный переход не объявляется серверным ACK: `enqueue` лишь обслуживает
outbox, а серверный отбой остаётся авторитетным. При удержании `call_hold` получает
`reportPayload(line.saved.report)`, если снимок доклада есть; пустые массивы не подменяют
отсутствующий доклад. Покрыты пустой/частичный/полный снимки, поздние данные, двойное
нажатие, перезагрузка и задержанный outbox. Быстрая фраза «Повторите доклад» продолжает
разговор только при исходе `played` и в том же поколении; `cancelled`/`failed` не дописывают
«Как приняли?». Две проверки вводной одного звонка также проверяются с обратным порядком
ответов.

## Целевая эмоция зоны — эталон, 22.09

Решение владельца зоны, дословно: «обучаемый не играет, это будет его работа и надо ему в этом
помочь, не нагнетать угрозу, а просто привлечь внимание, чтобы он своевременно отреагировал и
максимально быстро и правильно сделал нужные действия».

По этому эталону сверяются T-014, T-033 и T-035:

- сигнал зовёт один раз и гаснет, когда замечен; ничто не нарастает и не давит;
- всё для следующего действия уже на экране — искать не надо;
- норматив — ориентир «сколько осталось», а не счётчик потерь;
- ошибку не блокируем: адресат звонка оценивается (`expected_call` в `data/golden_scenarios/`),
  подсказка вместо оценки сломала бы критерий. Помощь — номер под рукой, а не запрет ошибиться;
- красное и мигающее — только там, где нужно действие прямо сейчас.

Для кого: обучаемый — не студент и не гик, это сорокалетний мужчина, которому предстоит
работать в этом интерфейсе. Отсюда — максимальная простота: крупная цель нажатия, прямая
подпись вместо иконки-ребуса, один очевидный путь вместо двух равноправных, ничего, что
надо разгадывать. Незнание горячих клавиш и жестов не должно мешать сделать работу.

Где копия, а где наша простота — решение 22.09: **реальный АРМ копируем точно**, включая его
иконки без подписей и двухуровневую полосу служб; узнаваемость для экспертов УМЦ важнее нашего
вкуса. Простота живёт в том, чего у оригинала нет и что придумываем мы: софтфон, live-доска,
реплей, звук, результаты. Там подписи словами, крупные цели, один путь.

Проверка любой правки: убирает ли она секунду из «заметил → понял → сделал». Добавляет — не делаем.

## Форма — телефон ДДС (GP-09, 16.10)

Рекомендации организаторов 16.10 (п. 8) и правка пользователя 1: колонка «Связь службы»
макета B ушла в **окно телефона**. Эталон вида и поведения —
`docs/dds_training_review/phone/index.html`; рамка — окно разговора модуля «Оператор 112»
(геометрия — `shared/floatingWindow.ts`, `shared/useFloatingWindow.ts`, общие для обоих окон).

- Значок IP-телефона (зелёный кружок с трубкой) — в полосе служб карточки, без карточки — в
  правом нижнем углу списка (`../phone/PhoneWindow.tsx`, `PhoneDial`): вызов — пульсирует со
  счётчиком, тревога — красный, разговор при свёрнутом или закрытом окне — таймер.
- Окно ставит `ArmPage` (`PhoneWindow`, контекст `PhoneContext`): шапка, плашка звонков с
  вкладками линий и «Удержать» (проверка 17.10, ниже), строки пропущенных (TC-02), тело, полоса
  размера. Открытая карточка выводит в шапку
  и тело свой разговор — `Softphone` порталами; звонок остаётся звонком карточки (`cardId`,
  события, `callGuard`). Без открытой карточки — список контактов без звонка. На стендах
  (`stand.html`) окна нет — телефон рисуется на месте.
- Пять полос макета: шапка (кому, таймер, волна «говорит / слушает», «Положить трубку»,
  звук), лента («Вы сказали» с метками ✓/✗, повтор реплики ▶), шаги по частям, ряд ответа
  («Говорить» → шкала громкости и «идёт запись» → «Закончить ответ» → «Распознаём…»; «По
  частям» держится до конца разговора), полоса размера. После отбоя — «Что прозвучало: n из 4»,
  «Перезвонить», «К контактам».
- GP-24 (`docs/dds_phone_window.md`): пустые полосы места не держат — шаги только при ответе по
  частям, ряд ответа по высоте кнопок, полоса размера только с пояснением (кнопка размера — в
  углу окна); окно того же размера, растёт лента. Пояснения, которые легко запомнить, — до
  `LEARNED_AFTER` верных действий (`../phone/learned.ts`, `../phone/useLearned.ts`), шкала
  громкости — `meter.ts`.
- Контакты группами: силы службы, руководство и аварийная бригада (абоненты занятия,
  `contacts.ts`), службы, заявитель — только если его добавил преподаватель. Набор номера
  вручную — поле «Номер» в ряду ответа списка контактов (рекомендация; в макете его нет).
  У службы два номера: короткий (101…) и городской учебный (`Service.phone`, +7 (495) 000-…);
  оба видны в справочнике, набранный городской соединяет с той же службой.

<header className={styles.head}>

запрос один на оба, второй к `/services` после вставки не уходит. Ключ не переименовывать.

## Как посмотреть своими глазами

Софтфон живёт в шапке карточки, а карточка — чужая зона, поэтому в приложении
его пока не видно. Для этого рядом лежит стенд: та же панель, подставные службы,
никакого backend.

```sh
pnpm install          # один раз
pnpm dev              # из корня репозитория
```

Открыть <http://127.0.0.1:5173/app/src/arm/softphone/stand.html>

Что смотреть: набор из справочника в одно нажатие, гудки и ответ службы,
варианты доклада, ответную реплику или уточняющий вопрос, отбой.

Стенд открывается только в dev-режиме: точка входа сборки одна — `index.html`,
в поставку эти страницы не попадают.

## Живой стенд — те же компоненты против настоящего api

Фикстурный стенд проверяет поведение, но не доказывает, что софтфона говорит с
рабочим backend. Для этого рядом лежит `stand-live.html`: настоящий вход под
`trainee01`, настоящие данные, настоящий WebSocket.

```sh
docker compose --env-file .env \
  -f deploy/docker-compose.yml -f deploy/docker-compose.dev.yml \
  --profile dev up -d --wait
```

Открыть <http://127.0.0.1:5173/app/src/arm/softphone/stand-live.html>

Нужен `.env` в корне с `API_MODE=database` и `JWT_SECRET`, а база — с миграциями
и сидами (`apps/api/README.md`). **`--env-file .env` обязателен**: с `-f deploy/…`
каталогом проекта становится `deploy/`, корневой `.env` не подхватывается, и
поднимется мок вместо рабочего api.

На macOS Vite в контейнере не всегда замечает правки на хосте через bind-mount —
если страница отдаёт старый код, `docker compose … restart web-dev`.

## Реплики служб (B-01)

Четыре профиля манифеста озвучены настоящим Piper, по две обязательные фразы Q14.
Голос выбирается по `voice_profile` набранной службы — не по номеру и не по порядку.

Происхождение, лицензии, хеши и длительности — `scripts/voices/PROVENANCE.md`.
Пересборка — `scripts/voices/generate.sh` (контейнер, `piper-tts==1.2.0`).

**Таймер не выдаётся за речь.** У реплики два исхода: `played` — звук был; `failed` —
звука не было. Текст фразы показывается всегда, но при `failed` рядом стоит причина:
нет файла для голоса, браузер не пустил автовоспроизведение, отказало устройство.
Молчание не засчитывается как состоявшийся разговор — это требование задания, и оно
проверено тестами (`voices.test.ts`, 14 проверок жизненного цикла).

Сбой звука не вина обучаемого: звонок продолжается, доклад и отбой работают как прежде.

Файлы едут **в бандле**: эндпоинта для реплик в контракте нет, а свой API заводить
задание запрещает. Карта `voiceAssets.ts` генерируется из манифеста
(`scripts/voices/manifest.py`) — руками её не правят, иначе разъедется с `data/voices/`.

Отключение звука и громкость — в панели разговора. В классе на 23 места сосед может
мешать, и это должно решаться на месте, а не через настройки.

## Учебные бригады и сведения о ходе реагирования (B-02)

`brigade/` рядом с телефоном: обучаемый сам выбирает бригады своей ДДС, звонит бригаде,
слушает доклады и сам переносит их в комментарий карточки. **Статус карточки за него не ставится.**

Три вещи в контракте разные, и здесь они разделены: служба ≠ бригада ≠ телефонный адресат.
У службы есть общий диспетчер (`brigade_id: null`) и прямые номера бригад.

**Предъявлением считается только реально состоявшееся.** Для аудио — событие `ended`,
для текста — явное подтверждение «Прочитал». Ни выдача файла, ни запрос автовоспроизведения,
ни таймер предъявлением не являются. Правила — `evidence.ts`, 16 тестов на инварианты:

- один `playback_id` разрешается ровно один раз, повтор не рождает второго сообщения;
- после успешного предъявления поздний сбой другой попытки его не отменяет;
- после сбоя повторная попытка всё ещё может предъявить;
- для аудио `audio_version` обязательна, для текста `null`;
- `available_after_s` отсчитывается от ответа собеседника, а не от набора номера.

**Источник данных — сервер (C-04).** Бригады и адресаты своей ДДС —
`/services/{id}/brigades` и `/call-targets`, выбор и выданные сведения —
`/cards/{id}/training`, аудио — `/cards/{id}/messages/{delivery_id}/audio` (`brigade/data.ts`).
План сообщений принадлежит преподавателю и в браузер не приходит: сведения выдаёт worker
в разговоре с прямым номером бригады после срока плана. WS `training.updated` только
инвалидирует чтение; в разговоре чтение повторяется раз в 2 с.

**Отклоняемое сервером не отправляется.** Очередь событий карточки останавливается на первом
4xx, поэтому номер проверяется до набора (`brigade/logic.ts`): прямой номер бригады своей
ДДС уходит как `call_dial_target` (направленной или нет — см. «Табло сил» ниже), номер
службы — как `call_dial`, неизвестный номер не набирается, причина показывается в телефоне.
Выбор бригад до «Принята» тоже не отправляется: сервер ответил бы 409.

Учебные сценарии с озвученными докладами (выезд, прибытие, работы, завершение) создаёт
`python -m app.seed.training` — по сценарию на службу, аудио из `data/voices/brigade`.
Первое поколение без доклада о завершении (`70004200…70004205`) выведено в архив;
для новых занятий используйте `70004210…70004215`.

Новых enum вроде «Прибытие» или «Проведение работ» не заводится, входящие звонки не
выдумываются: сведения — учебное дополнение, а не новый жизненный цикл карточки.

**Бригада ждёт решения диспетчера (27.09).** Доклад с `requires_state` в плане выдаётся
только после того, как в карточке поставлен этот статус: о прибытии бригада не доложит,
пока не отмечено «Начало реагирования». Раньше все четыре доклада уходили за 26 с от
ответа, и обучаемый не успевал их переносить. В занятии с подсказками панель бригад
пишет, какого статуса ждёт бригада (`CardTraining.awaiting_state`). Так устроено
обучающее упражнение `tutorial` (`python -m app.seed.training`), которое обучаемый
запускает сам кнопкой «Тренировка» (`POST /practice`); старые сценарии `audio-demo*`
не менялись.

## Входящий вызов бригады — 27.09

## Замечания после проверки капитана — 28.09

**Доклад вариантами (29.09, вместо микрофона).** Решение владельца: «убери использование
микрофона и сделай по вариантам ответа». Микрофон не запрашивается вовсе: нет записи,
загрузки записи и индикатора «вы говорите». После «Слушаю вас» в окне разговора — шесть
вариантов доклада, собранных из карточки (`report.ts`, с 08.10 — DT-11): полный по порядку
памятки ДДС, с. 32 — кто вы (ФИО, должность, служба), адрес и повод, карточка, что
изменилось (обстановка и силы); с 17.10 карточка обязательна только в звонке в 112
(`requiredParts`), в остальных звонках шага и переспроса карточки нет, — четыре без одной части (`no_who`, `no_address`, `no_card`,
`no_change`) и один с лишними сведениями: полный плюс непроверенные догадки, оценки и
просьбы. Над вариантами — строка памятки дословно, со страницей. Лишний длиннее полного, так что верный вариант
не угадать по длине кнопки. На полный служба отвечает «информация принята» и кладёт
трубку; на неверный задаёт уточняющий вопрос, разговор продолжается. Выбранные
варианты уходят в отбой (`call_hangup.report_choices`): оценщик (`evalcore` CallCriterion)
засчитывает звонок полным докладом, неверный — замечание в разборе, проводник закрывает
шаг «доклад службе» только полным. «Положить трубку» до доклада кладёт сразу, без
подтверждения приёма. Общий номер не выдаёт доклады о выезде; они принадлежат плану
карточки и прямому номеру направленной бригады. Например, у базовой карточки `10000001`
такого плана нет, а у `70004241` он есть.

**Отклонённое действие не должно оставлять карточку без пути продолжения.** Очередь
`shared/ws/outbox.ts` сохраняет отказ сервера и останавливает только его карточку:
следующие действия могут зависеть от неверного статуса. Панель «Отклонённые
действия» теперь даёт явно очистить эту очередь, после чего ученик обновляет
страницу и повторяет действие. Уже принятые сервером события не удаляются.
После ошибочной «Не принята» можно поставить «Принята» и направить бригаду;
закрывающие статусы по контракту завершают карточку.

**Разбор карточки 10000001 (капитан, 28.09, 15:11 МСК).** В журнале стенда:
общий вызов 102 в 15:12:03–15:14:39, затем прямой вызов бригаде до назначения
(отказ `not_assigned`), направление бригады и повторный прямой вызов. У базового
сценария 10000001 нет плана учебных докладов, поэтому и второй звонок не мог
привести к докладу о выезде. Статусы «Принята» → «Начало реагирования» →
«Прибытие» → «Работы завершены» сервер принял; последний в 15:19:23 закрыл
карточку по контракту. Это не отказ очереди в данном занятии. В панели бригад
теперь прямо сказано, что доклад появится только при наличии плана, а закрывающий
статус требует повторного подтверждения до отправки на сервер. Для проверки
звуковых докладов использовать новое занятие с 70004211, а не 10000001.

**Бригада дослушивает диспетчера** (`speech.ts`). Доклад бригады звучит не раньше 2 с
после ответа — диспетчер успевает представиться. Микрофона нет, правило только по времени.
Ответы бригаде — быстрые фразы с реакцией: «Принял» засчитывает текстовый доклад,
«Повторите доклад» — бригада повторяет прозвучавший.

**Панель телефона** раскрывается у правого края карточки — над правой колонкой: адрес и
описание слева остаются доступными во время разговора. «Свернуть телефон» убирает панель в
любой момент, разговор при этом продолжается. После обычного отбоя панель сворачивается
сама через 1,5 с, если не о чем предупредить (номер не принят, бригада отказала). Поле
набора после разговора пустое: новый номер набирается сразу. Цифра после трёх набранных
начинает новый номер — раньше после отклонённого номера клавиатура «замирала».

**Занятость бригад** (`CardTraining.available_brigade_ids`, `busy_brigades`, сервер —
`apps/api/app/api/training/brigades.py`). Диспетчеру доступны две бригады ДДС; с четырьмя
происшествиями в занятии — три, с шестью — четыре. Бригада, направленная на незакрытое
происшествие, на другое не едет: в панели она отмечена «занята: происшествие N», набор её
номера объясняет причину. Доклады плана приходят от той бригады, которую направил
диспетчер, а не только от первой.

**Статус по услышанному докладу (28.09).** В сценарии с учебным планом статусы
«Начало реагирования», «Прибытие», «Проведение работ», «Работы завершены» и
«Отказ от выполнения работ» доступны только после предъявления соответствующего
доклада. Сервер проверяет событие `message_presented` по выданному сообщению этой
карточки; интерфейс показывает «ждём доклад» и перечитывает сведения перед
отправкой статуса, чтобы отклонение не попало в очередь. «Принята» остаётся
решением диспетчера до направления бригады. Оценка помечает статус, поставленный
раньше доклада, критической ошибкой; отсутствующий доклад не требуется в эталоне.
Связь этапа с неизменяемыми старыми планами определяется по стабильному ID
сообщения сида. У базовых сценариев, включая 10000001, учебного плана нет:
доклад о выезде или прибытии у них не возникает, поэтому для проверки этой цепочки
нужен сценарий 70004211 или обучающее упражнение 70004231.

## Табло сил и отказ бригады — 28.09

Замечание капитана: номер бригады «разблокировался» выбором — до «Направить выбранные»
звонок ей не уходил. В реальности у диспетчера ДДС связь со всеми своими бригадами
(рация, служебный телефон); ограничено назначение — только свободная бригада и только
после решения реагировать. Заказчик 21.09: «для ДДС необходимые бригады выбираются
вручную», связь с бригадой в тренажёре — по IP-телефону.

**Табло сил** (`BrigadePicker`, `forcesBoard` в `brigade/logic.ts`). У каждой доступной
бригады — прямой номер и состояние словами: «свободна», «направлена сюда» или «занята:
происшествие N». Табло видно сразу, до решения по карточке: диспетчер знает состояние сил
заранее. Кнопка «Позвонить» — только у направленных бригад: один очевидный путь; остальные
номера на виду и набираются вручную.

**Направление — после «Принята»** (памятка ДДС, стр. 21: «реагирование будет
осуществляться»). До решения кнопка «Направить выбранные» недоступна, рядом сказано почему;
флажки отмечаются заранее. Сервер отклоняет `brigades_select` до «Принята» кодом 409
`decision_required`, клиент такое событие не отправляет (`useBrigade.commit`).

**Звонок любой бригаде своей ДДС проходит.** Ненаправленная бригада снимает трубку и
отвечает отказом: «Нам этот вызов не назначен», занятая — «Мы заняты на другом
происшествии». После фразы она сама кладёт трубку (`machine.ts`: отказ идёт фазой
`closing`, без записи и без «информация принята»). Под телефоном — что делать дальше
(`refusalNote`). Сервер принимает звонок и записывает тот же отказ в `calls.refusal`
(миграция `0013`); по такому звонку worker не выдаёт доклады, даже если бригаду направят
во время разговора. Звонок бригаде другой службы по-прежнему «не обслуживается».

**Оценка: ошибку не блокируем, а оцениваем** — без отдельного штрафа. Отказной звонок не
засчитывается обязательным (информацию никто не принял); балл берётся по лучшему звонку,
а потерянное время уже учтено нормативом. Число таких звонков видно преподавателю в
обосновании критерия `call` (`packages/evalcore`).

**Голос отказа.** Фраза отказа — не фраза Q14, в `VoiceManifest` она не входит (там только
`listen`/`accepted`), поэтому файлы лежат отдельно (`refusalAssets.ts`). Нет файла для
голоса — текст на экране с пометкой, как у реплик служб.

**После ревью 28.09.** Доклад звучит сам только в разговоре с бригадой, которая его выдала
(`Listening.brigadeId`): не после отбоя и не в звонке другому абоненту — иначе его можно
прослушать кнопкой. «Направить выбранные» перед отправкой перечитывает `/training`: бригаду
могли только что направить на другое происшествие, а отказ сервера остановил бы очередь
карточки. Бригадные номера не набираются, пока сведения о бригадах не загружены: без них
направленная бригада выглядела бы ненаправленной и «отказала» бы по ошибке.

- Нет микрофона, доступа к нему или распознавания на сервере — сообщение по-русски

  звонке, на шаге до трёх коротких вариантов (`parts.ts`). Выбранная часть сразу строкой

  `report_confirmed` (`useBrigade.confirm`): журнал карточки «доклад бригады принят: …», разбор —
  «Доклад бригады принят: …». Пока бригада ждёт ответа, трубку она не кладёт.
- Диспетчер молчит `NO_REPLY_MS` = 8 с после «Как приняли?» — «Диспетчер, слышите меня?»
  (`no_reply`) один раз за паузу (`pauseKey`): новая пауза — после фразы диспетчера или нового
  вопроса. «Повторите доклад» — бригада повторяет доклад и снова спрашивает «Как приняли?».
- Только во входящем вызове: в своём звонке бригаде доклад о выезде после вводной идёт как раньше.

## Пропущенный доклад и удержание линии — TC-02, 17.10

touches.md, «Входящий доклад бригады» 2–3; решение — docs/decisions.md. Строки линий — над лентой
окна телефона, окно не меняет размер.

- **Пропущенный.** Входящий звонит 25 с; без ответа worker гасит его (`callbacks[].end_reason =
missed`), через 40 с бригада звонит снова, второй пропуск того же доклада — `lost`: сама она
  больше не звонит. В окне — строка «Старший бригады · 201 · пропущенный вызов в 12:03 · по
  карточке N» (или «доклад потерян») с «Перезвонить», пока доклад не услышан
  (`../phone/missed.ts`). «Перезвонить» открывает карточку вызова и набирает номер бригады
  (`../pickup.ts`, `requestLine`): разговор отдаёт пропущенный доклад. Разбор и шкала
  преподавателя — «Доклад бригады потерян» (`../callbacks.ts`, `lostReports`). Тревога не
  пропускается.
- **Удержание** — вкладки линий, ниже.
- Ответ или отбой одновременно с тем, как сервер погасил вызов, — 409 `call_ended`: очередь
  событий карточку не блокирует (`shared/ws/outbox.ts`).

## Вкладки линий и удержание — проверка 17.10

«Надо звонки сделать по вкладкам на плашке звонков и добавить удержание звонков»; решение —
docs/decisions.md («Проверка вдвоём 17.10»). Финальный сценарий — смена с несколькими
карточками и перегруженным телефоном: линий несколько, их держат в голове.

- **Плашка звонков** (`../phone/PhoneWindow.tsx`, модель — `../phone/lines.ts`): вкладка на
  линию — идущий разговор, каждая линия на удержании, каждый входящий (бригада и отдел
  контроля), ненадолго — «не дождался, положил трубку». Подпись — кто («Старший бригады · 201»,
  «Служба 101», «Отдел контроля»), что с линией («говорит 0:42», «на удержании 0:42», «звонит
  0:12», «тревога 0:05») и «по карточке N»; узкой вкладке (три и больше в окне 760) карточка не
  помещается и прячется целиком, она в подсказке. Порядок — по появлению линии (`lineOrder`):
  вкладка не прыгает при ответе и удержании. Звонящая мигает цветом вызова, как значок; фокус на
  первой звонящей, Enter отвечает. Справа — «Удержать». Не помещаются — полоса прокручивается.
- **Щелчок по вкладке**: звонящая — ответить, удержанная — снять с удержания; идущий разговор
  при этом встаёт на удержание (`ArmPage.freeLine`), а не обрывается. Не удержать (набор,
  гудки, собеседник прощается) — трубка кладётся, как раньше. «Перезвонить» по пропущенному —
  так же.
- **Что удерживается** — любой разговор: бригада, служба 101–104 и прочие, абонент ДДС, отдел
  контроля; линий на удержании сколько угодно. Только в браузере (`../phone/hold.ts`, машина;
  `../phone/useHold.ts`, sessionStorage): машина звонка уходит в `held` без отбоя
  (`machine.ts`, событие `hold`), звонок на сервере в разговоре. Через 3 мин удержания
  (`HOLD_LIMIT_MS`, один срок для всех) — обычный `call_hangup` в очередь карточки, у службы — с
  докладом, сказанным до удержания.
- **Разговор помнится** (`heldTalk.ts`, `SavedTalk`): лента, доклад службе (`ReportLog` —
  уйдёт в отбой) и прозвучавшие части доклада. Софтфон карточки один и ведёт одну линию;
  удержанные — снимками. Снятие возвращает ленту (`callLog.restoredLog`, строки `held-…` второй
  раз не звучат) и разговор без `call_answer` (событие `resume`): «Снят с удержания», старший —
  «… на связи.» (место банка `answer`), служба — «Да, …» своей книги (`officialBackPhrase`),
  доклад продолжается с недостающих частей. Отдел контроля — «Да, слушаю.» и ждёт пояснения.

## Должностное лицо отвечает правдоподобно — TC-03, 17.10

touches.md, «Исходящий звонок должностному лицу» 8, 10, 13; решение — docs/decisions.md.

- **Персонаж.** Дежурный службы 101–104 — книга банка `OFFICIAL_<служба>` (`official.ts`,
  `personaBook`): ответ — место `answer`, приём доклада — `registered` с номером регистрации
  (`registeredLine`, по звонку одна и та же фраза). Записей bank-v1 нет — реплика текстом
  (`useSoftphone.spoken`), в ленте без кнопки повтора звука. Остальные абоненты — общий дежурный
  с записями Q14.
- **Номер регистрации** уходит в отбой (`call_hangup.registration_number`): «Ключевые сведения»
  засчитывают комментарий с этим числом (`evalcore/comment.py`).
- **Вопросы** — `askLine`: одна фраза `ask_*` книги о первой недостающей части памятки, без
  догадки о происшествии («Уточните, что горит: квартира, подвал?» не звучит, когда горит
  машина); перебираются по счёту вопроса в звонке, одна и та же подряд не звучит; общий
  дежурный начинает с прежних (`report.ASK_IDS`). Отбор формулировок (`askCandidates`) — по
  тексту фраз; что каждый отбор каждой книги `OFFICIAL*` находит хотя бы две фразы, сверяет
  `official.test.ts` — редакция текста (HQ-037) не опустошит его молча.
- **Похожая улица** — `twinStreet` по `confusableStreets.json` (копия `data/confusable_streets.json`,
  сверяет `official.test.ts`). На полный доклад — один раз «по буквам» (`spellLine`), доклад
  записан с `close = false`, разговор закрывает `accept` после ответа: голосом — любая фраза,
  по частям — шаг «Улица по буквам» (`spellStep`). Голосом сервер называет похожую улицу сам
  (`VoiceReport.spell_street`).
- **«Повторите»** — `wantsRepeat` на короткую фразу голосом или быстрая фраза «Повторите»
  (`callLog.quickPhrases`, `peerLine`): дежурный повторяет свою последнюю реплику.

## Пробел для разговора, статус словами, правка распознанного — TC-04, 17.10

touches.md, «Звук обоих разговоров» 16, «Исходящий звонок должностному лицу» 12, «Клавиши и ввод»;
решение — docs/decisions.md.

- **Пробел.** В разговоре пробел зажат — идёт ответ (доклад службе или слово бригаде), отпущен —
  ответ закончен (проверка 17.10; раньше было два нажатия). Запись, начатую кнопкой «Говорить»,
  пробел заканчивает (`Softphone.tsx`, слушатели `keydown`/`keyup` на окне; правила —
  `pushToTalk.ts`). По `event.code`, а не по символу: в русской раскладке
  работает так же. Поле ввода, список и кнопка оставляют пробел себе (печать, нажатие кнопки).
  Подсказка «Говорите, удерживая пробел…» — пояснение, которое прячется после трёх
  применений (`LEARNED_HINTS.space`, GP-24); у кнопки пробел подсказывает всегда (`title`,
  `aria-keyshortcuts`).
- **Статус словами** (`voiceReport.micStatus`): «слушаю · 0:03» при записи, «распознаю…», «собеседник
  говорит». Прежние «идёт запись» и «Распознаём…» заменены. Размер окна и ряда ответа не менялся.
- **Полудуплекс.** Пока говорит собеседник (`phone.speaking`, `brigade.playing`, реплика ленты
  `bankSpeaking`), запись не начинается (`canStartRecording`); если он заговорил во время записи,
  начатой в тишине, запись бросается (`cancel` в `useVoiceReport` и `useVoiceReply`).
- **Говорить чуть раньше и зажать заранее (HQ-052, `pushToTalk.ts`).** За секунду до конца
  реплики (`EARLY_TALK_MS`) запись уже начинается: остаток реплики доигрывает. Конец реплики —
  `Voices.remainingMs()` (длительность и позиция записи; текст без звука — время чтения); у
  ленты он известен только на её последней записи, иначе раннего окна нет — только по концу.
  Пробел, нажатый раньше, «взводится» (статус «запись начнётся после реплики»): запись начнётся
  сама, если он ещё зажат, отпущенный раньше — ничего. Кнопка «Говорить» во время реплики
  взводится щелчком, повторный щелчок — отмена (`aria-pressed` у кнопки всегда: нажата —
  запись ждёт). Взведение пишется в ссылку прямо при нажатии: отпускание в том же тике его
  видит (`releaseOutcome`). Запись, начатая так, — ответ на звучащую реплику: её остаток
  запись не бросает, а новая реплика (свой ключ у каждой: номер реплики службы, доклада
  бригады, записи ленты) бросает, как в тишине (`cancelsRecording`) — иначе фраза ушла бы
  ответом на вопрос, заданный уже во время записи. «Как приняли?» после озвученного доклада —
  продолжение доклада, его ключ (`bankSpeechKey`): ранний «Принял» на нём не гаснет и уходит
  подтверждением (`report_confirmed`). Микрофон доклада службе готов с начала «Слушаю» (`reportOpen`),
  варианты и подсказки — после него (`reporting`). Сервер засчитывает фразу, ушедшую до конца
  реплики, ответом к её концу (`turns_of`, `tests/test_turns.py`).
- **Правка распознанного.** Сервер не засчитал фразу из-за низкой уверенности, но текст есть
  (`VoiceReport {text ≠ "", choice: null}`): `recognitionOutcome` даёт `check`, хук показывает
  `CheckField` — поле «Проверьте адрес и нажмите Enter» с кнопками «Отправить» и «Сказать
  заново». Enter отправляет `POST /calls/{id}/voice-report` с полем `text` вместо `audio`
  (contract: e150cf3): сервер сводит текст к виду доклада и засчитывает как сказанное голосом
  (`report_modes: voice`), при выключенном распознавании тоже. Escape убирает поле без записи,
  «Сказать заново» — с записью. Подсказка у поля — `LEARNED_HINTS.check`.
- **Переспрос не штрафуется.** `afterPhrase`: считается (`voice_failures`, «голос не распознан» в
  разборе, варианты после двух неудач) только фраза без речи; проверка не растит счётчик и не
  вызывает «Не расслышал» от дежурного.
- Речь бригаде (`useVoiceReply`) осталась прежней: неуверенная фраза — «не понял». Поле правки
  есть только у доклада службе (там адрес).
