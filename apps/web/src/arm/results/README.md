# Мои результаты · T-031 (Dwots)

Экран обучаемого: закрытые карточки по занятиям и разбор каждой. Открывается из АРМ —
кнопкой «Мои результаты» над списком или «Разбор» в шапке закрытой карточки. Общую
маршрутизацию не трогает: экран живёт поверх списка, как сама карточка.

| Файл                   | Ответственность                                                   |
| ---------------------- | ----------------------------------------------------------------- |
| `resultsModel.ts`      | чистая логика: группы по занятиям, время, путь статусов, счётчики |
| `resultsModel.test.ts` | 5 тестов на эти правила                                           |
| `ResultsPanel.tsx`     | шапка со счётчиками, список закрытых карточек, WS-обновление      |
| `CardReview.tsx`       | разбор карточки: оценка, комментарий, правила, критерии           |

## Что видит обучаемый

- **Оценку** и evidence семи критериев с сервера. `partial` означает незавершённый
  или отключённый фоновый слой; fallback `unavailable:T-006` показан «без оценки».
- **Комментарий преподавателя** — поле, которое преподаватель заполняет в вердикте пульта.
  Появляется без перезагрузки: вердикты обновляются по WS `evaluation.partial/complete`
  (ws-events.md адресует их именно результатам), запасной опрос — раз в 20 с.
- **Сверку с правилами**: реакция и отработка против нормативов занятия, путь статусов
  против полного цикла «Принята → Начало реагирования → Работы завершены», служба
  карточки против службы обучаемого на занятии.
- **Разбор по критериям** — объяснения и доказательства оценщика, слабые первыми.

## Решения

**Баллы не считаем.** Средний балл и любые агрегаты оценок — дело сервера (ответ
капитана §2). В шапке только счётчики: закрыто, оценено, реакция в нормативе.

Нормативы каждой карточки берутся из `Session.settings_snapshot` её занятия.
Изменение общих настроек администратором не меняет сверку истории. Пока снимок
недоступен, сравнение не выполняется. После WS snapshot перечитываются карточки,
оценки, занятия и события; старый маршрут `/app/results` также сохранён.

**Реакция — тем же отсчётом, что таймер АРМ**, чтобы в разборе была та же цифра, что
обучаемый видел в работе: по I-TIME v3 от показа строки на АРМ (`deliver`, `delivered_at`)
до «Принята / Не принята» (дополнение 27.09 в `contracts/I-TIME.md`). Выдача карточки
сервером (`appeared_at`) в реакцию не входит: обучаемый в это время мог ещё входить.

**«Правила», а не «эталон».** Сверка идёт только с тем, что подтверждено: нормативы,
жизненный цикл, адресат карточки. Эталон сценария обучаемому пока недоступен —
экран так и пишет, не подменяя его догадкой.

## Границы

- Эталон сценария, подсказки «нулевого уровня» (FR-1.6) и справочная база (FR-1.7)
  ждут данных и контракта — подробно в `docs/DWOTS_FINDINGS.md`.
- Подписи критериев и функции вердикта берутся из `teacher/console/model.ts`, чтобы
  пульт и обучаемый называли одно и то же одинаково.
- На телефоне экран результатов укладывается по ширине; таблица списка происшествий
  АРМ (T-013) — нет, девять колонок на 390 px. АРМ — рабочее место класса, под телефон
  его не делали.
