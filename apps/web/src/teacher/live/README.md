# Brikkerdev · T-033

Live-доска: вход index.ts; Card/Session/WsServerEvent из контракта. Источник обновлений —
`realtime.subscribe(listener)`; начальное состояние — HTTP и snapshot. Компонент возвращает
unsubscribe при размонтировании. До T-008 presence и данные занятия в моке ограничены.
Соседний TeacherPage и teacher/studio/reports принадлежат Qwots.

Целевая эмоция зоны — эталон в `apps/web/src/arm/softphone/README.md`: привлечь внимание и
помочь сделать быстро и правильно, не нагнетать. Сигнал зовёт и гаснет; норматив — «сколько
осталось», а не «сколько потеряно»; красное только там, где нужно действие прямо сейчас.

| ----------------- | ---------------------------------------------------------------------------------- |

Время считает общий модуль C-02 (`shared/timing.ts`) через адаптер АРМ
(`arm/timingAdapter.ts`) — по версии методики из снимка занятия, чтобы доска, карточка
обучаемого и оценка видели одно число. Новые занятия идут по
[v3](../../../../../contracts/I-TIME.md#v3): реакция — от направления карточки до первого
«Принята» / «Не принята» (открытие её не закрывает), обработка — от первого открытия до
терминала, а норматив сравнивается с активной обработкой — без подтверждённого ожидания
сведений. Ожидание берётся из разбора попытки (`/cards/{id}/analysis`, `timing.waiting_s`):
журнала ожидания у клиента нет; пока он неизвестен, считается полная обработка, как на
карточке обучаемого. Занятия со снимком v2/legacy считаются по своей версии.
Карточки на этапах «Прибытие» и «Проведение работ» остаются в работе.
При параллельных карточках плитка показывает самую горящую и считает остальные.

**Три уровня внимания, а не два.** Доска зовёт в последние секунды норматива («скоро»,
5 с на реакции и 30 с на обработке — `extra_features` 5.3), а не только после провала.
Красное после срыва — отчёт; помощь — это янтарное до него.

Янтарный цвет объявлен локально в `LiveBoard.module.css`: в `shared/tokens.css` его нет,
а взят он с метки ЧП на `arm_dds/06.png`. Капитану — кандидат в общие токены.

## Как посмотреть своими глазами

Доска живёт в пульте преподавателя — чужая зона, поэтому в приложении её пока
не видно. Рядом лежит стенд: занятие на 23 места, живые таймеры, без backend.

```sh
pnpm install          # один раз
pnpm dev              # из корня репозитория
```

Открыть <http://127.0.0.1:5173/app/src/teacher/live/stand.html>

Что смотреть: АРМ 5 и АРМ 11 за пять секунд до норматива реакции становятся
янтарными, а после норматива — красными; АРМ 14 проходит тот же путь на
нормативе обработки, там порог тридцать секунд. АРМ 5 и 19 карточку уже открыли,
но «Принята» не поставили — по v3 у них всё ещё реакция («Статус не поставлен»). Заголовок всё время называет
номера мест, к которым идти. Когда просрочится всё, сценарий начнётся сам;
«Начать заново» делает то же немедленно.

Стенд открывается только в dev-режиме: точка входа сборки одна — `index.html`.

## Живой стенд — те же компоненты против настоящего api

Интеграция 23.09: `<LiveBoard sessionId={id} />` привязывает доску к выбору в пульте.
`sessionId={null}` оставляет доску без выбранного занятия. Вызов `<LiveBoard />`
на отдельном стенде сохраняет прежний автоподбор первого running-занятия.

Фикстурный стенд проверяет поведение, но не доказывает, что доски говорит с
рабочим backend. Для этого рядом лежит `stand-live.html`: настоящий вход под
`teacher`, настоящие данные, настоящий WebSocket.

```sh
docker compose --env-file .env \
  -f deploy/docker-compose.yml -f deploy/docker-compose.dev.yml \
  --profile dev up -d --wait
```

Открыть <http://127.0.0.1:5173/app/src/teacher/live/stand-live.html>

Нужен `.env` в корне с `API_MODE=database` и `JWT_SECRET`, а база — с миграциями
и сидами (`apps/api/README.md`). **`--env-file .env` обязателен**: с `-f deploy/…`
каталогом проекта становится `deploy/`, корневой `.env` не подхватывается, и
поднимется мок вместо рабочего api.

На macOS Vite в контейнере не всегда замечает правки на хосте через bind-mount —
если страница отдаёт старый код, `docker compose … restart web-dev`.
