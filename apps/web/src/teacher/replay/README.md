# Brikkerdev · T-034

Реплей потребляет GET /cards/{id}/events (StoredEvent[]) и GET /cards/{id}/calls.
Сортировка по server_ts, исходный client_ts сохраняется; время для оценки корректирует evalcore.
Оценку не пересчитывать в браузере. Публичный вход index.ts. Рабочий скраббер — T-034.

Целевая эмоция зоны — эталон в `apps/web/src/arm/softphone/README.md`: привлечь внимание и
помочь сделать быстро и правильно, не нагнетать. Сигнал зовёт и гаснет; норматив — «сколько
осталось», а не «сколько потеряно»; красное только там, где нужно действие прямо сейчас.

## Что сделано в T-034

| Файл               | Ответственность                                                                          |
| ------------------ | ---------------------------------------------------------------------------------------- |
| `timeline.ts`      | чистая сборка журнала: подписи шагов, места промахов, состояние карточки на секунду      |
| `timeline.test.ts` | 29 тестов: порядок, промахи по v3 и legacy, ожидание, бригады, состояние, переходы       |
| `useReplay.ts`     | карточка, журнал, снимок методики, итог сервера, доклады бригад, вердикт — одним чтением |
| `Replay.tsx`       | скраббер с засечками ошибок, журнал, карточка на выбранной секунде, вердикт              |

Места промахов выводятся из журнала и нормативов, а не из оценки: у `CriterionResult`
нет отметок времени, а преподавателю нужно попасть в момент, а не в формулировку.
Считаются четыре: реакция позже норматива, обработка дольше норматива (или карточку
не закрыли), звонок не в службу карточки, звонка не было.

Время — общим расчётом C-02 (`shared/timing.ts`) по версии методики занятия; итог
сервера по попытке (`/cards/{id}/analysis`, `timing`) главнее, потому что только он знает
подтверждённое ожидание сведений. В [v3](../../../../../contracts/I-TIME.md#v3) реакция
идёт от направления карточки до первого «Принята» / «Не принята» (нет статуса — промах
на нормативе), а обработка сравнивается с нормативом по активному времени: ожидание
доклада бригады в неё не входит. Ожидание неизвестно — превышение неизвестно, ложной
ошибки нет. Занятия v2/legacy — по своим правилам («открыл через…», «закрыл через…»).

В журнале названы словами и события C-04 и подсказок: выбор бригад, звонок бригаде
(номер и имя адресата), прозвучавший или прочитанный доклад с его текстом, незасчитанный
доклад с причиной, открытая подсказка, уточнённый адрес. В карточке на секунде видно,
какие доклады обучаемый к этому моменту уже услышал — по ним он писал комментарий.
Оценку в браузере не пересчитываем — показываем ту, что пришла; берём последнюю версию,
потому что переопределение преподавателя приходит новой.

Модуль логики называется `timeline.ts`, а не `replay.ts`: на macOS имя различалось бы
с `Replay.tsx` только регистром, и TypeScript отказывался собирать.

## Как посмотреть своими глазами

```sh
pnpm install          # один раз
pnpm dev              # из корня репозитория
```

Открыть <http://127.0.0.1:5173/app/src/teacher/replay/stand.html>

На стенде разобран прогон с тремя промахами. Тяните ползунок или жмите «следующая
ошибка»; красные засечки под шкалой — сами ошибки, по ним тоже можно кликать.

## Что осталось

- прослушивание записи доклада рядом с таймлайном — после T-036a;
- транскрипт доклада с подсветкой сущностей — T-036c;
- монтирование в пульт выполнено капитаном при интеграции 23.09: кнопка
  «Разобрать действия» в вердикте выбранного занятия. Публичный вход остаётся прежним:

```tsx
import { Replay } from "./replay";
<Replay cardId={cardId} />;
```

Реплею нужна выбранная карточка, поэтому одной строкой он не встаёт: разбор начинается
с выбора, чьё занятие смотрим. Как это выглядит минимально — в `stand-live.tsx` рядом
(список закрытых карточек и `select`). Сам выбор — решение в зоне Qwots, не наше.
Скраббер при смене `cardId` встаёт на начало сам — об этом заботиться не нужно.

## Живой стенд — те же компоненты против настоящего api

Фикстурный стенд проверяет поведение, но не доказывает, что реплея говорит с
рабочим backend. Для этого рядом лежит `stand-live.html`: настоящий вход под
`teacher`, настоящие данные, настоящий WebSocket.

```sh
docker compose --env-file .env \
  -f deploy/docker-compose.yml -f deploy/docker-compose.dev.yml \
  --profile dev up -d --wait
```

Открыть <http://127.0.0.1:5173/app/src/teacher/replay/stand-live.html>

Нужен `.env` в корне с `API_MODE=database` и `JWT_SECRET`, а база — с миграциями
и сидами (`apps/api/README.md`). **`--env-file .env` обязателен**: с `-f deploy/…`
каталогом проекта становится `deploy/`, корневой `.env` не подхватывается, и
поднимется мок вместо рабочего api.

На macOS Vite в контейнере не всегда замечает правки на хосте через bind-mount —
если страница отдаёт старый код, `docker compose … restart web-dev`.
