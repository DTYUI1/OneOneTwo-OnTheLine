# Студия сценариев · D-01 (Dwots)

Преподаватель создаёт и правит сценарий формой, без ручного JSON. Открывается из пульта:
«Студия сценариев» в левой колонке. Заменила прежний каталог с JSON-редактором; копия и
архив сохранены.

| Файл                   | Ответственность                                                        |
| ---------------------- | ---------------------------------------------------------------------- |
| `studioModel.ts`       | форма ↔ `Scenario`, проверки у разделов, исходы эталона, шаги словами |
| `studioModel.test.ts`  | 13 тестов, в том числе «туда-обратно» на сценарии из seed              |
| `ScenarioStudio.tsx`   | список: служба, статус, источник; создание, правка, копия, архив       |
| `ScenarioEditor.tsx`   | форма по разделам, сохранение черновика и утверждение, выход из 409    |
| `ScenarioPreview.tsx`  | карточка глазами обучаемого и эталон — ожидаемые действия по порядку   |
| `ConstructorPanel.tsx` | «Собрать по классификатору»: `POST /scenarios/preview` заполняет форму |
| `ScenarioSource.tsx`   | источник задания и эталона по `GET /scenarios/{id}/content`            |

## Путь сценария

черновик → правка → «Утвердить» (сервер проверяет эталон) → выдача на занятии.
Черновик сохраняется неполным; утвердить можно только то, что оценщик сможет проверить.

## Решения

**Тип — из классификатора**, 1281 запись `GET /incident-types`, поиск по названию. Служба
подставляется только по соответствию из `contracts/data_formats.md` (MCHS→101, Police→102,
AMBULANCE→103, MOSGAZ→104, GKH, MOSLIFT). Для прочих кодов службы среди шести учебных нет
— преподаватель выбирает сам, выдуманных ID нет.

**Исход вместо списка состояний.** Эталон задаётся одним из пяти исходов («принять и
довести до конца», «не принимать и перенаправить»…), каждый — допустимая
последовательность по переходам `evalcore/validation.py`; тест это проверяет.

**Ошибки у своих разделов (A2).** Проверка до отправки повторяет правила сервера; ответ
422 сервера раскладывается по разделу по тексту, незнакомый — в общий блок как есть.

**409 предлагает выход.** «Назначенный сценарий нельзя изменить» → «Создать копию»:
новый черновик с новым ID и номером, история назначений исходного не трогается.
«Уже изменён» → «Загрузить актуальную версию». Правка всегда начинается с
`GET /scenarios/{id}`, а не со строки списка.

**Архив вместо удаления** — `POST /scenarios/{id}/retire`, история назначений цела;
архивный сценарий открывается только для чтения, работать дальше — копией.

## Пакеты (D-01, п. 3)

Вкладка «пакеты» студии. Генерация — `POST /packs/generate` (служба, уровень, количество,
seed), затем опрос `GET /jobs/{id}/progress` до done/failed («N из M», предупреждения); при ошибке — «Повторить». Опрос ведёт
TanStack Query (`refetchInterval`), а не таймер в эффекте: часы в шапке перерисовывают
страницу каждую секунду и сбрасывали бы таймер. После «готово» открывается пакет
из `pack_id` прогресса: у каждого сценария готовность по тем же правилам, что «Утвердить» в редакторе.
Отметить можно только пригодные — неполный эталон не выдаётся.

«Утвердить отмеченные» — одна операция `POST /packs/{id}/approve` с версиями и
`request_id`: сервер утверждает все отмеченные или ни одного; повтор после обрыва связи
идёт с тем же `request_id`, другой набор — с новым.

## Конструктор (D-01, п. 1)

«Собрать по классификатору» в разделе «Происшествие»: тип, служба, уровень, вес, адрес,
пострадавшие, осложнения и seed уходят в `POST /scenarios/preview`; сервер детерминированно
собирает карточку и эталон по классификатору 046_24. Ничего не сохраняется — форма
заполняется предложением, номер, версия и статус остаются у редактируемого сценария.
Показаны источник, предложенный сервером вес и ошибки проверки.
