# web — Qwots и Brikkerdev

C-01: передача участникам.
`src/shared/contracts.ts` экспортирует общие типы времени, адресной пачки, бригад,
аналитики и preview из сгенерированного клиента. Реализация таймера — C-02.
Фикстуры `contracts/examples/timing-v2.json` импортируются только тестами; до C-02…C-07
новые HTTP-операции отвечают 501 и не должны отображаться как готовые функции.

23.09: у обучаемого добавлен `/app/results` («Мои результаты» в шапке): итог с учётом
решения преподавателя, критерии/evidence, пояснение partial и комментарий преподавателя.
Данные поступают через существующие приватные API; WS/snapshot обновляют результат,
перезагрузка перечитывает его из БД. Экран отделён от рабочей карточки ДДС.

Node 20, pnpm 9.15.9. Из корня: `pnpm install --frozen-lockfile`, `pnpm dev`.
Перед этим запустить мок из `apps/api/README.md`. Вход: `http://127.0.0.1:5173/app/login`.
Логины admin / teacher / trainee01..05, пароль из `DEMO_PASSWORD` (по умолчанию `demo-local`).

При каждом входе обучаемого `shared/WelcomeGate` показывает выбор обучения **до** рабочего
интерфейса: «112» — оператор 112, «Диспетчер служб» — АРМ ДДС. Выбор сохраняется в
localStorage отдельно для каждого user_id, поэтому reload его не повторяет; вход
(`LoginPage` → `forgetWelcome`) снимает отметку. При запрете storage выбор хранится до reload.
С 28.09 приветствие есть у каждой роли (`shared/welcomeContent.ts`): обучаемому — порядок
работы с карточкой, преподавателю — порядок проведения занятия, администратору — что проверить
перед занятием; у преподавателя и администратора кнопка «Начать работу». После приветствия
`shared/help/HelpTip.tsx` один раз показывает стрелку к кнопке «?» (отметка
`arm112:help-tip:v1:<user_id>`): щелчки проходят сквозь подсказку, в порядок фокуса она не
входит и исчезает после первого щелчка, Esc или F1. Нет «?» на экране (подсказки выключены) —
стрелка ждёт, пока кнопка появится. В e2e вход преподавателя и администратора проходит
приветствие помощником `passWelcome` (`qa/e2e/captain-fixture.ts`).

«Сообщить об ошибке» (`shared/ReportButton.tsx`) — кнопка шапки у всех ролей: тема, описание,
экран подставляется сам; `POST /problem-reports`. Сообщения хранятся в базе тренажёра (без
интернета), читает администратор в разделе «Сообщения об ошибках».

`pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm test`. После изменения OpenAPI: `pnpm gen:api`.
Сгенерированный `src/api-client/schema.d.ts` входит в git, вручную не редактируется.
Все HTTP-вызовы через `shared/api.ts` (openapi-fetch), серверное состояние — TanStack Query.
WS/IndexedDB — `shared/ws/`; `useSession()` отдаёт user и realtime. Для действия:
`realtime.enqueue(cardId, {client_event_id: crypto.randomUUID(), client_ts: new Date().toISOString(), type: 'open', payload: {}})`.
Повторную отправку реализует shared; фичи не создают второй буфер.
Подписка на обновления: `realtime.subscribe(listener)` возвращает unsubscribe.
Входящие WS-сообщения проверяет Ajv по общему контракту; `realtime.pending()` показывает очередь.

на kickoff; сейчас новый UI-kit не навязывается. Токены — из скриншотов, точная сверка T-028.

АРМ (T-013, Qwots): список происшествий с поиском и таймером реакции, карточка «формата 112»
поверх списка, статусы жизненного цикла с комментарием, перенаправление, история действий,
таймер отработки с красной индикацией, разбор очереди `Outbox.list(userId)` — `arm/PendingActions`.
Чистая логика вынесена в `arm/cardModel.ts` (подписи, допустимые переходы, таймеры) и покрыта
vitest; компонентных тестов нет — для них нужны jsdom/@testing-library, а зависимости добавляет
капитан. `deliver` уходит после первого рендера строки, `open` — при открытии карточки.

Prism можно запустить отдельно: `pnpm mock`, порт 4010. Он не хранит cookies/состояние
и не поддерживает WS; для разработки логина/софтфона используйте MockBackend на 8000.
Смена реализации API не требует изменений в фичах: пути и транспорт сохраняются.
Prism слушает `/cards` (без `/api`); для ручного GET передайте Cookie `session=prism-example`.
Его транзитивные prism-http/server/core закреплены в корневых overrides: новые 5.x подняли
требование Node до 24 и несовместимы с выбранным Node 20. Lock проверен реальным запуском.
